# 검증과 완료 판정 지침

현재 `active` PLAN의 완료 조건에 맞춰 검증을 선택하고 실제 결과를 기록한다.
PLAN 상태와 전환은 [작업 절차](workflow.md)를 따른다.

## 변경에 맞는 검증 선택

| 수준 | 주요 대상 | 확인 예 |
| --- | --- | --- |
| 문서·정적 확인 | 지침·계획·참조 및 코드 구조 | 링크·줄 수·PLAN 상태·변경 범위·컴파일 |
| 로직 검증: Edit Mode 중심 | 일반 C# Thing·컴포넌트·공통 시스템 | 규칙 결과, 상태 독립성, 소유·예약, 저장·복원 |
| Unity 통합: Play Mode 중심 | 씬·프리팹·SO 연결·화면 입력 | 누락 참조, 공통 명령 전달, 화면과 논리 상태의 일치 |
| Android 빌드 | 대상 플랫폼 패키징·설정 | 빌드 성공, 실제 산출물, 빌드 오류 |
| Android 실기기 | 실행·표시·터치·방향 전환·성능 | 기기에서 기본 흐름 실행, 가로·세로 조작과 상태 유지 |

- 모든 수정에 모든 수준을 실행하지 않는다. 변경의 영향과 PLAN 완료 조건에 필요한 검증을 고른다.
- 컴파일 성공·테스트 통과·빌드 성공·기기 실행 확인은 각각 구분한다.
- 단순 문서 수정에는 링크·줄 수·상태 일관성 검사를 사용한다. 게임 테스트를 불필요하게 추가하지 않는다.
- 새로운 변경·실패·남은 우려가 없다면 같은 검증을 반복하거나 범위를 계속 늘리지 않는다.
- 테스트 도구·명령은 실제 프로젝트와 패키지에서 확인한다. [Unity 도구 지침](unity-tools.md)의 검증된 절차를 사용한다.

## 로직과 하네스

- [하네스 지침](harness.md)에 따라 UI와 같은 명령·규칙·상태를 검증한다.
- 승인된 기획과 관찰 가능한 결과를 기준으로 테스트한다. 구현을 그대로 복사한 기대값을 사용하지 않는다.
- 변경과 관련된 정상 흐름, 중요한 예외, 저장·복원 후 관계를 확인한다.
- 기능 추가 시 해당 상태의 저장·복원과 초기화도 함께 검토한다.
- 아직 구현하지 않은 기능은 통과로 표시하지 않는다. 현재 PLAN의 범위와 후속 범위를 구분한다.
- 테스트를 완화하거나 비활성화해 통과시켰다면 원인 해결로 보고하지 않는다.

## 결과 확인

1. 실행 환경과 대상 테스트·시나리오를 확인한다.
2. 실제 명령 또는 도구 호출과 실행 대상을 기록한다.
3. 프로세스 종료 결과, 테스트 결과 파일·실행 수·실패·건너뜀, 관련 로그를 함께 확인한다.
4. 실행 대상이 발견되지 않아 테스트가 0개인 경우 검증 통과로 처리하지 않는다.
5. 해당 실행에서 생성된 결과인지 확인한다. 이전 실행의 로그·산출물을 새 증거로 사용하지 않는다.
6. 오류가 있으면 원인과 영향을 정리하고, 수정 후 필요한 범위만 다시 검증한다.

도구 호출 성공이나 종료 코드만으로 모든 테스트가 실행됐다고 판단하지 않는다.
Editor·CLI·MCP 연결 성공도 게임 로직 검증 성공과 구분한다.

## Android와 화면 검증

- 승인된 플랫폼과 검증 범위는 [플레이 환경](../game-design/04-delivery/01-platform/environment.md)을 따른다.
- PC Play Mode나 Android 빌드만으로 실기기 터치·성능이 확인됐다고 기록하지 않는다.
- 가로 기본 사이클을 먼저 구현하고 세로 대응을 추가하는 [구현 순서](../game-design/05-development/02-implementation/roadmap.md)를 유지한다.
- 최종 기기 검증에는 두 방향의 표시·입력·전환을 포함한다. 조작 중 상태 변화도 확인한다.
- 엔진·패키지·그래픽 설정 변경 시 해당 변경의 실제 영향에 맞춰 기기 검증 범위를 정한다.
- 기기 모델·OS·빌드 식별 정보·방향·실행 조건을 기록한다. 성능 수치는 실제 측정값과 조건을 함께 남긴다.
- 검증 기종·반복 횟수·성능 기준 등의 위임 사항은 작업에 필요한 시점에 정한다.

## PLAN 증거와 완료

현재 PLAN의 검증 결과에는 다음을 남긴다.

| 항목 | 내용 |
| --- | --- |
| 환경·대상 | 사용 버전, 플랫폼·기기, 코드·설정 또는 산출물 식별 정보 |
| 방법 | 재실행 가능한 명령·절차와 테스트·시나리오 이름 |
| 결과 | 실제 실행 수·통과·실패·건너뜀과 관찰 내용 |
| 증거 | 해당 실행의 결과 파일·로그·필요한 화면·빌드 산출물 위치 |
| 미검증·문제 | 실행하지 못한 항목, 이유, 영향, 다음 행동 |

- 요구한 검증을 실행할 수 없다면 가능한 확인까지 마치고 제한과 재개 조건을 기록한다.
- 미실행·건너뜀을 통과로 표시하지 않으며, 필수 완료 기준이 남으면 PLAN을 `completed`로 바꾸지 않는다.
- 문서 작성 완료·설계 승인·설치 완료와 실제 구현·검증 완료를 구분한다.
- 로드맵에는 단계 요약과 PLAN 링크를 남기고 상세 실행 기록은 PLAN에서 관리한다.
- 장기 기술 선택은 [기술 결정](../decisions/README.md), 최종 제품 판정은 [프로토타입 완료 기준](../game-design/04-delivery/02-release/scope.md)을 따른다.
