# 데이터·저장·네트워크 준비 지침

장기 플레이를 재개할 때 무엇이 같은 상태로 복원되어야 하는가?

## 시작할 자료

[아키텍처 지침](../../architecture.md)과 기술 결정 이력에 기존 데이터·저장 방식이 있다.

## 준비 방법

1. 정의 데이터와 플레이 중 변하는 상태를 나눈다. 저장 직전에 진행 중인 작업·운반·연구를 예로 들어 복원에 필요한 값을 찾는다.
2. 저장 도중 중단, 이전 버전 저장 불러오기, 복구 가능한 오류 시나리오별로 기대하는 사용자 경험을 적는다.
3. 오프라인·온라인 요구를 확인한 뒤 로컬·클라우드 저장, 서버·멀티플레이의 필요성과 보호할 데이터를 기록한다.

## 산출물과 확인 기준

**데이터 분류표와 저장·복원·호환 시나리오**를 준비한다. 같은 저장 시점의 복원 결과와 실패 시 사용자에게 제공할 복구 경로를 판단할 수 있다.
