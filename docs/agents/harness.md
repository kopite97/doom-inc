# 게임 하네스 지침

명령 실행·상태 관찰·시나리오 재현과 자동 검증을 구현하거나 수정할 때 읽는다.
[작업 절차](workflow.md)의 단일 `active` PLAN에 포함된 기능만 대상으로 한다.

## 공통 실행 경로

- 플레이 화면과 하네스가 같은 명령 처리·규칙 검사·상태 조회를 사용한다.
- 하네스는 실제 Thing·컴포넌트·시스템의 상태를 관찰한다. 별도 정답 시뮬레이션을 만들지 않는다.
- 입력 변환과 결과 표시는 달라도 같은 명령의 허용 여부와 상태 변화는 같아야 한다.
- 검증을 통과시키기 위해 생산·자원·배치·진행 규칙을 하네스에 복제하거나 우회하지 않는다.
- 화면 오브젝트의 존재 여부만으로 논리 객체의 존재·삭제·외부 활동 상태를 판단하지 않는다.
- 공통 책임과 상태 소유는 [Thing 기준 문서](../game-design/05-development/01-architecture/thing-model.md)와 [GameFlow](../game-design/05-development/01-architecture/game-flow.md)를 따른다.

## 시나리오 구성

각 시나리오는 다음 요소를 명시한다.

| 요소 | 기록할 내용 |
| --- | --- |
| 기준 | 관련 기획 문서·규칙과 확인하려는 동작 |
| 초기 상태 | 정의·개체·배치·자원·저장 데이터 등 필요한 시작 조건 |
| 명령 | 공통 경로로 전달할 입력과 실행 순서 |
| 진행 | 완료를 관찰할 조건, 시간 진행 방법과 종료 한계 |
| 기대 상태 | 규칙에 따른 결과와 유지되어야 하는 관계 |
| 증거 | 실제 결과, 실패 시 관련 개체와 상태, 실행 조건 |

- 기능이 추가되는 단계에서 필요한 시나리오를 함께 확장한다.
- 정상 흐름과 해당 변경에서 중요한 예외·경계를 선택한다. 모든 조합을 먼저 구현하지 않는다.
- 기존 구현을 그대로 따라 쓰는 단언 대신 승인 규칙과 관찰 가능한 결과를 기준으로 판정한다.
- 특수 초기 상태를 준비하는 테스트 도우미는 명령 실행·판정과 구분한다. 준비용 상태 주입을 실제 사용자 조작 검증으로 간주하지 않는다.

## 초기화·시간·재현

- 시나리오 간 상태가 새지 않도록 실행 상태와 테스트용 저장 데이터를 초기화한다.
- 테스트용 저장 경로를 사용해 사용자의 플레이 저장을 덮어쓰지 않는다.
- 실제 기다림에만 의존하지 않고 게임 진행 시간을 제어·관찰할 수 있게 설계한다.
- 시간 제어도 같은 게임 갱신과 일시정지 규칙을 거친다. 하네스 전용 생산 계산을 두지 않는다.
- 시간 주입·단계 진행 등 구체적 방식은 개발에서 선택한다. 고정 틱이나 완전한 결정성을 선결 조건으로 요구하지 않는다.
- 무작위 요소를 사용한다면 재현에 필요한 입력·시드 등을 기록한다. 없는 무작위 시스템을 추가하지 않는다.
- 실패 시 초기 조건·명령 순서·진행량·관련 Thing ID·관찰 상태를 남겨 재실행할 수 있게 한다.
- 무한 대기 대신 관찰 한계를 두고, 한계 초과를 성공으로 처리하지 않는다.

## 단계별 적용

- 선행 기반부터 정의 공유와 실행 상태 독립, Map 반영, 공통 조작, 저장·복원을 확인한다.
- 후속 기능의 Job·예약·생산 회차·외부 활동 상태는 해당 기능을 구현할 때 검증에 추가한다.
- 구현하지 않은 후속 기능까지 미리 하네스로 구축하지 않는다.
- 현재 단계와 통과 조건은 [구현 로드맵](../game-design/05-development/02-implementation/roadmap.md), 실제 작업 범위는 현재 PLAN을 따른다.
- 하네스 통과만으로 화면 연결·터치·성능 검증을 대신하지 않는다. [검증 지침](verification.md)에 따라 필요한 통합·기기 검증을 수행한다.

## 기록

- 시나리오와 검증 코드는 관련 구현 가까이 두고 현재 PLAN에서 실행 방법·결과·증거를 연결한다.
- 공통 명령·시간 제어·상태 조회 등 지속적인 구조 선택은 [기술 결정](../decisions/README.md)에 기록한다.
- 실제 확인한 실행 절차는 [Unity 도구 지침](unity-tools.md)에 반영한다.
- 새로운 게임 규칙이 필요하면 기획 절차로 다룬다. 하네스 기대값을 먼저 만들어 확정 규칙으로 취급하지 않는다.
