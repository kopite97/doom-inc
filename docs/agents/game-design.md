# 기획 작성·해석 지침

적용: 기획 조회·작성·변경, 기획을 기준으로 PLAN을 준비할 때.
탐색: [기획 MAP](../game-design/README.md), [작업 절차](workflow.md), [PLAN 관리](../plans/AGETNS.md).

## 작업 초안과 최종 정리

- 새 기획은 문서에 쓰기 전에 실제 플레이 장면으로 먼저 검토해 사용자에게 평가를 제시한다. 플레이어가 무엇을 보고 선택하는지, 선택에 따라 결과가 어떻게 달라지는지, 의도와 달리 진행이 막히는 지점을 짚는다. 논의 후 합의한 규칙을 담당 문서에 기록한다.
- 시작 맵을 검토할 때는 성격이 다른 두 맵에서 같은 초반 목표를 따라가 본다. 첫 건설의 재료 선택, 절약했을 때 첫 연구를 가동할 경로, 첫 증설에서 달라지는 판단을 비교한다. [시작 맵 기준과 비교 사례](../game-design/systems/maps.md#시작-맵의-자원과-첫-증설)를 따른다.
- 현재 `docs/game-design/`의 문서는 기획 중인 임시 작업 초안이다. 논의가 진행되는 동안 기존 카테고리에 계속 작성·갱신한다.
- 문서 전체의 초안 상태와 개별 항목의 확정·제안·미정 상태는 별개다. 초안이라는 이유로 확정된 결정을 무효화하거나 모든 내용을 확정 규칙으로 해석하지 않는다.
- 사용자가 기획 완료를 알리면 전체 기획안을 다시 정리한다. 중복·충돌·남은 미정 사항을 점검하고, 확정 내용을 중심으로 문서 구성과 MAP·참조 링크를 정돈한다. 정리 과정에서 미정 사항을 임의로 확정하지 않는다.
- 2026-11-17 사용자 지정 순서: 기획 마무리 → 기획 재정리와 개발 비용·재미 기여도 검토를 통한 축소·제외 → 기존 지침·구현 검토 → 여러 시스템이 공유하는 경계 결정 → 단계별 개발. 현재는 기획을 이어가며 범위 정리나 공통 경계 설계를 앞당겨 실행하지 않는다.

## 기준과 상태

- 새 기획의 기준은 `docs/game-design/`의 해당 주제 문서다. 최신 사용자 지시를 우선하며 충돌한 문서는 함께 갱신한다.
- `확정`: 사용자가 지정·승인한 방향 또는 규칙. 방향의 승인이 세부 기능 전체의 승인을 뜻하지 않는다.
- `제안`: 검토용 선택지·예시. 문서 작성 요청만으로 예시를 확정 콘텐츠나 구현 범위로 바꾸지 않는다.
- `미정`: 사용자 판단이 필요한 게임 규칙. 관련 작업에 들어가기 전에 결정하며 임의로 기본값을 정하지 않는다.
- `개발 위임`: 확정 규칙 안의 데이터 구조·알고리즘·API·수치 조정. 통상적인 기술 선택은 근거를 남기고 진행한다.
- 플레이어의 선택·승패·손실·콘텐츠 범위를 바꾸는 사항은 구현 디테일로 처리하지 않는다. 의존하지 않는 작업은 계속 진행할 수 있다.

## 작성과 배치

- README에는 짧은 게임 개요와 문서 MAP만 둔다. 작업 진행·검증 결과·작성 지침은 넣지 않는다.
- 주제 문서는 게임의 목적·경험, 확정 규칙·행동 방향, 제안·미정, 갱신일·근거를 필요한 만큼 기록한다.
- 카테고리 하위에 주제별 파일을 둔다. 한 규칙의 원본은 한 문서이며 다른 문서에서는 링크한다.
- `docs/game-design/`에는 게임 기획을 기록한다. 클래스·API·캐시·코드 재사용·기술 검증 절차는 [구현 지침](implementation.md)·PLAN·기술 결정에 둔다.
- 핵심 경험·게임 규칙·상호작용을 먼저 정하고 기술 설계는 개발 중 구체화한다. 사용자가 지정한 JSON 관리 같은 제약은 간단히 기록하되 스키마·연결 절차를 게임 기획에 쌓지 않는다.
- 예시 수치·생명체·시설·전술은 제안으로 표시한다. 기술적 가능성을 게임 규칙의 승인으로 해석하지 않는다.
- 변경 시 담당 문서의 날짜·근거와 관련 링크를 갱신한다. 미정 사항 색인은 질문과 원본 링크만 유지한다.

## 문서의 책임

| 위치 | 책임 |
| --- | --- |
| 주제별 기획 | 플레이 경험·게임 규칙·행동·상호작용 |
| [개발 로드맵](../game-design/development/roadmap.md) | 별도로 합의한 개발 순서·선행 관계·단계별 경험 확인 기준. 기술 설계는 넣지 않음 |
| PLAN | 승인된 작업 범위·상세 구현·진행·검증 결과 |
| 기술 결정 | 중요한 구현 선택·이유·대안·적용 위치 |
| 에이전트 지침 | 기획 해석·작업·검증·기록 방법 |

- 로드맵은 실제 완료·검증을 뜻하지 않으며 다음 PLAN 실행을 자동 승인하지 않는다.
- 기획 작성·정리는 active PLAN이 없어도 가능하다. 구현 실행은 [PLAN 관리](../plans/AGETNS.md)를 따른다.

## 이전 기획과 재사용

- `docs/game-design-deprecated/`는 과거 기록이다. 규칙·완료 기준·숫자 분류·D/Q/S-ID를 자동 승계하거나 다른 의미로 재사용하지 않는다.
- 새 기획의 미정 사항을 이전 기획으로 채우지 않는다. 기존 코드·에셋·기술 결정은 현재 상태를 확인한 뒤 재사용을 판단한다.
- 완료된 PLAN과 증거는 보존한다. 옛 `docs/game-design/` 주제 링크는 deprecated 디렉터리의 같은 하위 경로에서 찾는다.
