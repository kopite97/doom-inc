# 텍스트와 Localization 유지보수

적용: 제품 문구·정의 표시 이름·언어 설정·번역 테이블·문구 표시 경로 변경.
탐색: [작업 절차](workflow.md), [객체 설계](object-design.md), [검증](verification.md), [CSV 사용 설명](../../UnityProject/Assets/CSV/Localization/README.md).

## 원본과 경계

- 편집 원본은 `Assets/CSV/Localization/`의 주제별 CSV다. String Table·내장 오류 JSON은 가져오기 결과이며 직접 수정하지 않는다.
- 밸런스·게임 정의는 JSON + SO → Data → Runtime을 유지한다. JSON의 `displayNameKey`는 Definitions 테이블 키이며 번역과 함께 저장 호환성 해시에서 제외한다.
- 정의 ID·저장 필드·명령 코드·UI 행 식별자는 번역하지 않는다. 번역 키를 행 수명 식별자로 대체하지 않는다.
- 개발자 진단·예외 원문·하네스·Editor 도구와 라이선스 원문은 제품 번역과 구분한다. 제품 오류는 번역하고 원인은 진단으로 보존한다.
- 새 제품 문구를 C#·씬·프리팹에 직접 넣지 않는다. 폰트·아트 변경은 해당 승인 범위를 따른다.

## 키와 인수

- 의미가 드러나는 안정적인 키를 사용한다. 원문을 키로 쓰거나 수정 때 ID를 재생성·재사용하지 않는다.
- 단어가 같아도 문맥이 다르면 분리한다. 공통 버튼처럼 의미가 같은 경우에만 Common을 공유한다.
- 전체 문장을 Smart String과 명명된 인수로 구성한다. 표시용 숫자·복수형은 선택 언어로 처리하되 저장·밸런스 수치는 바꾸지 않는다.
- 시설·자원 이름은 중첩 LocalizedMessage 인수로 전달한다. 번역 완료 string을 장기 알림 상태에 저장하지 않는다.
- 발생한 알림은 키와 당시 값의 스냅샷을 보관한다. 재번역으로 수량·시각·유효 기간·콜백을 바꾸거나 다시 실행하지 않는다.
- 코드 참조는 명시적 테이블/키 리터럴·조건별 키와 제공된 헬퍼를 사용한다. 임의 키 문자열 조립을 피한다.
- 새 동적 키 공급원·패키지 씬/프리팹 바인딩을 추가하면 참조 검사도 확장한다. 현재 검사기가 모든 C# 구문·임의 에셋을 분석한다고 가정하지 않는다.

## 변경 절차

1. active PLAN 범위와 영향 화면을 확인한다.
2. CSV의 키·문맥·Smart·Arguments·한국어/영어를 함께 편집한다. ID는 양의 15자리 이하 정수다.
3. `Preview CSV Changes`로 추가·값·삭제·이름 변경·재검토 대상을 확인한다.
4. 원문·문맥·인수·Smart 또는 번역 변경 후 `Review Translations`에서 실제 내용을 검토하고 개별 키·언어를 확인한다.
5. `Validate CSV` → `Import Reviewed CSV` → `Validate Imported Tables`를 실행하고 콘솔 결과를 확인한다.
6. 이름 변경·삭제는 참조를 먼저 정비한 뒤 `Apply Reviewed Key Changes`로 명시적으로 적용한다. 사용 중 키 삭제 차단을 우회하지 않는다.
7. 영향 화면을 런타임에서 확인하고 PLAN에 증거를 남긴다.

- Import는 검토 완료를 자동 기록하지 않는다. 번역 수정이 불필요해도 실제 검토 후 명시적으로 확인한다.
- 필수 언어 누락·공백·변수 계약 불일치·포맷 오류·미검토는 완료 검사 실패다.
- UTF-8·쉼표·따옴표·개행을 보존하며 단순 Split 파서를 사용하지 않는다. Key 정렬·줄바꿈은 제공된 CSV writer 규칙을 유지한다.
- 생성 테이블만 수정한 불일치는 CSV 원본으로 복구한다. 입력 오류가 정상 테이블 일부를 덮어쓰게 하지 않는다.

## 소유와 언어 전환

- TextManager는 앱 소유 일반 C# 객체다. 별도 싱글톤·서비스 로케이터를 만들지 않는다.
- UnityLocalizationService가 패키지를 격리한다. SelectedLocale·String Table을 원본으로 사용하며 번역 사전을 GameDataStore에 복제하지 않는다.
- 정상 UI는 필수 테이블 준비 후 열고 준비 전 오류는 CSV에서 생성한 BootstrapText로 표시한다.
- 새 언어를 비동기로 준비한 뒤 마지막 요청만 적용한다. 실패 시 기존 언어·게임 상태를 보존한다.
- 화면 조회에 파일 읽기·동기 대기·전체 테이블 비동기 요청을 숨기지 않는다. 준비된 테이블 포맷과 기존 행 재사용을 구분한다.
- 구독은 화면/행 수명과 함께 해제한다. 프레임 갱신과 별도 구독이 같은 Text를 이중으로 소유하지 않게 한다.
- 언어는 앱 범위 Preferences에 저장한다. 슬롯·새 판과 분리하며 저장 실패 시 현재 선택과 영구 보존을 구분해 알리고 재시도를 제공한다.
- 누락 시 메시지 전체를 한국어로 대체하고 그것도 없으면 내장 일반 오류 문구를 사용한다. 키·개발용 포맷 오류를 제품 문구로 노출하지 않는다.

## 확장과 검증

- 추가 언어에는 Locale·모든 주제의 언어/Reviewed 열·String Table·폰트·문법·화면 검증이 필요하다. 제품 기본 언어는 ko/en이다.
- 지원 목록은 등록 Locale에서 읽는다. 언어 enum·고정 개수 버튼을 추가하지 않는다.
- 세 번째 언어의 글리프·줄바꿈·복수형·RTL·숫자 폭은 별도로 검증한다. ko/en 결과를 확대 해석하지 않는다.
- 열린 확인창·알림·상세 이름·보고·결과 재번역, 오래된 클릭 차단, 미리보기/스크롤/선택 보존과 빠른 변경·실패·재시도·종료를 확인한다.
- 초기화·씬 진입·반복 Play·Domain Reload, 언어 저장 손상/쓰기 실패, 기존 저장 호환성은 변경 영향에 따라 함께 검증한다.
- 빌드는 [기본 제외 원칙](verification.md#build-test-authorization)을 따른다. Editor 에셋 직접 사용 검증은 Player/Addressables 콘텐츠 빌드 검증이 아니다.
