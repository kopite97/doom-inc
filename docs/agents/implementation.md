# 새 기획의 구현·재사용 지침

적용: 새 기획을 구현하기 위한 기술 설계·재사용·작업 범위 검토.
탐색: [기획 지침](game-design.md), [아키텍처](architecture.md), [추상화](abstraction.md), [밸런스 편집](balance-editor.md).
이 문서는 개발 방법을 다룬다. 게임 규칙의 원본은 [기획 MAP](../game-design/README.md)의 주제 문서다.

## 책임 구분

- 사용자는 1인 개발과 에이전트 활용을 계획한다. 기획은 핵심 경험·규칙을 정하고 상세 기술 설계는 개발하면서 진행한다.
- 클래스·컴포넌트·API·알고리즘·데이터 구조·수치 조정은 확정 규칙 안에서 결정한다. 중요한 선택은 [기술 결정](../decisions/README.md)에 기록한다.
- 승패·손실·명령 수준·플랫폼·콘텐츠 범위의 미정 사항을 기술 선택으로 확정하지 않는다.
- 범위·진행·검증은 PLAN에서 관리한다. 로드맵 작성이 구현 실행 승인이나 완료 증거는 아니다.
- 기획 완료 후의 검토·설계 착수 순서는 [기획 지침](game-design.md#작업-초안과-최종-정리)을 따른다. 범위를 정리한 뒤 공유 상태의 소유·처리 순서·작업 중단 및 예약·저장 복원 경계를 관련 기능 구현 전에 함께 결정한다. 그 경계 안의 세부 클래스·알고리즘·수치는 개발 중 구체화한다.

## 데이터와 재사용

- [생명체](../game-design/systems/creatures.md)의 코스트는 JSON으로 관리한다. 필드·자료형·초기값·검증·호환 방식은 구현 단계에서 정한다.
- 생명체의 작업 특화는 [기획 원칙](../game-design/systems/creatures.md#작업-특화)에 따라 관련 수행 수치를 조정해 표현한다. 특화 여부·종류를 위한 별도 필드나 특화 판정 분기를 추가하지 않는다. 작업 가능 여부와 수행 성능을 혼동하지 않는다.
- 기존 JSON 로딩·밸런스 편집 기반을 활용하며 [밸런스 편집 지침](balance-editor.md)에 따라 실제 동작까지 연결한다.
- 아트·개체·지도·이동·작업·생산·물류·저장·명령·하네스는 재사용 후보이며, 새 규칙과 실제 구현을 대조한다.
- 이전 보조형·침공형 구분, 배정 제한, 전투로 인한 중단·복구와 충돌하는 부분을 확인한다. 전체 교체 또는 전체 유지를 미리 가정하지 않는다.

## 판단과 명령

- [커맨더](../game-design/systems/commanders.md)의 판단 방식을 교체할 수 있도록 필요한 추상화를 적용한다.
- 커맨더는 상태 조회 후 게임 내부의 공통 명령 API로 작업 우선순위·배정을 조정한다. 외부 AI 서비스 도입을 의미하지 않는다.
- 상태 조회·판단·명령 검사·작업 실행을 구분한다. 공통 유효성 검사와 실행 로직을 커맨더별로 복제하지 않는다.
- 집계 공유·판단 주기·캐시·변경 대상만 갱신하는 방식을 검토한다. 중앙 판단이나 복잡한 알고리즘만으로 성능·효율 개선을 단정하지 않는다.
- 실제 동률 처리·평가식·자료구조는 확정한 게임 규칙 안에서 정한다.

## 연결과 검증

- 생명체의 행동·대기 이유·명령 결과를 화면과 하네스에서 관찰할 수 있게 한다.
- 자동 전투는 작업 중단·운반물·예약·시설 피해·저장·일상 복귀와 함께 검증한다. 플레이어 전투 명령은 만들지 않는다.
- 공수 추정은 확정 일정이 아니다. 구현·검수 결과로 갱신하며 에이전트 사용에 따른 속도를 보장하지 않는다.
- 일반 검증과 별도 승인이 필요한 빌드·고부하는 [검증 지침](verification.md)을 따른다.
