# Unity 에셋 변경 지침

씬·프리팹·ScriptableObject(SO)·이미지·임포트 설정을 변경할 때 읽는다.
[작업 절차](workflow.md)의 단일 `active` PLAN 범위에서만 작업한다.

## 변경 전 확인

- 실제 Unity 프로젝트 경로와 에디터·패키지 버전을 확인한다. 경로나 도구 설치를 추정하지 않는다.
- 승인된 환경은 [플레이 환경](../game-design/04-delivery/01-platform/environment.md)을 따른다.
- 대상 에셋을 참조하는 씬·프리팹·SO와 변경 의도를 먼저 확인한다.
- 기존 변경 사항을 확인하고 사용자나 다른 작업의 변경을 덮어쓰지 않는다.
- 프로젝트 생성·에디터 변경·패키지 추가는 현재 PLAN 범위에 포함된 경우에 진행한다.

## 파일과 참조 보존

- 에셋과 대응하는 `.meta`를 함께 관리한다. 이동·이름 변경 시 기존 GUID를 유지한다.
- 기존 `.meta`를 삭제·재생성하여 참조 오류를 해결하지 않는다. 누락 시 기존 파일과 참조를 먼저 조사한다.
- 새 에셋의 메타데이터는 Unity가 생성하게 하고, 생성된 에셋과 `.meta`를 함께 변경 목록에 포함한다.
- 폴더의 `.meta`도 참조 관리 대상이다. 파일 이동 후 이전 경로의 잔여 파일을 확인한다.
- 삭제 전 참조를 확인하고, 필요한 참조 교체를 같은 작업에서 처리한다.
- `Library/`, `Temp/`, `Obj/` 등 Unity가 재생성하는 캐시·임시 파일을 소스 변경으로 포함하지 않는다.
- 패키지나 프로젝트 설정 변경은 필요한 항목으로 제한한다. 재직렬화로 생긴 무관한 대량 변경을 포함하지 않는다.

## 에셋 편집

- 씬·프리팹·SO 변경은 가능한 경우 Editor와 실제 연결이 확인된 도구를 사용한다.
- 도구 사용법은 [Unity 도구 지침](unity-tools.md)에서 확인한다. 존재하지 않는 명령·API를 가정하지 않는다.
- 직렬화 텍스트를 직접 수정해야 하면 구조를 확인한 좁은 변경만 수행하고 Unity 재임포트로 검증한다.
- 에셋 이름·폴더·클래스를 일괄 변경할 때는 직렬화 참조와 누락 스크립트를 함께 확인한다.
- 자동화가 파일을 저장했다는 사실만으로 Unity에서 에셋을 정상 로드했다고 판단하지 않는다.

## 정의 데이터와 실행 상태

- SO에는 종류별 공통 정의만 둔다. 플레이 중 진행도·재고·배정 등 실행 상태를 기록하지 않는다.
- 같은 정의를 쓰는 Thing의 실행 상태를 독립적으로 유지한다.
- 테스트나 Play Mode 실행이 정의 SO를 변경한 경우 원인을 확인한다. 실행 결과를 정의 변경으로 저장하지 않는다.
- 생산 수치와 기능 설정은 담당 정의를 참조하며, 같은 값을 프리팹·코드·하네스에 독립 복제하지 않는다.
- 세부 구조는 [아키텍처 지침](architecture.md)과 [Thing 기준 문서](../game-design/05-development/01-architecture/thing-model.md)를 따른다.
- 정의 설정을 바꾸는 작업이 승인된 게임 규칙 변경인지, 개발 위임 값 조정인지 구분한다.

## 변경 후 확인과 기록

1. 변경 파일·`.meta`·GUID와 의도하지 않은 직렬화 변경을 검토한다.
2. Unity에서 해당 에셋을 재임포트하고 로드 오류·누락 스크립트·깨진 참조를 확인한다.
3. 영향받는 씬이나 프리팹을 열고 필요한 [통합 검증](verification.md)을 수행한다.
4. 실행한 환경·방법·결과와 검증하지 못한 항목을 현재 PLAN에 기록한다.

Editor를 실행하지 못했다면 텍스트 검토와 링크 확인까지만 수행했다고 기록한다.
장기적으로 영향을 주는 에셋 구조 선택은 [기술 결정](../decisions/README.md)에 남긴다.
현재 승인된 게임 규칙의 원본은 [기획 MAP](../game-design/README.md)에서 찾는다.
