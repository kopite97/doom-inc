# 아트 제공·Sprite 임포트·검수

적용: 아트 요청·수령·등록·교체, Sprite 임포트 설정, 아트 검증 기록.
탐색: [프로젝트 구조](project-structure.md), [Unity 에셋](unity-assets.md), [검증](verification.md).

## 제작과 역할

- 정식 게임 아트는 일관성을 위해 사용자가 Aseprite로 직접 제작해 제공한다.
- 에이전트는 제공받은 아트의 등록·참조 연결·임포트 설정·기술 검증을 담당한다. 정식 아트를 임의 생성·다운로드·교체하거나 원본 픽셀·색·스타일을 수정하지 않는다.
- 개발에 필요한 임시 대체 에셋은 정식 아트와 구분하고 [임의 에셋 표식·교체 규칙](project-structure.md#temporary-assets)을 따른다. 영문 이름에 `Temp_`를 붙인다.
- 최종 외형·색감·스타일 일관성·가독성·애니메이션의 시각 검수는 사용자가 직접 한다. 에이전트의 기술 검증 통과를 사용자 시각 검수 완료로 기록하지 않는다.
- 사용자 확인 전에는 결과를 `기술 검증 완료 / 사용자 시각 확인 대기`처럼 구분한다. 기능 개발의 완료와 정식 아트 교체·검수의 완료도 구분한다.

## 제공 파일과 배치

- 이미지·시트는 `Assets/Sprites/` 아래 해당 기능·주제에 둔다. 에셋명·파일명은 영어로 작성하고 같은 주제의 파일만 함께 둔다.
- Aseprite 원본과 Unity에서 사용할 이미지·시트를 구분해 기록한다. 원본을 전달받아도 임의 리사이즈·재색칠·병합으로 덮어쓰지 않는다.
- 실제 제공 형식이 확인되기 전 `.aseprite` 직접 임포트나 전용 패키지 도입을 확정하지 않는다. PNG가 제공되면 그 파일을 기준으로 설정한다.
- 프레임 크기·순서·피벗·경계 등은 제공 자료와 실제 사용처를 확인해 연결한다. 근거 없이 잘라내기·프레임 재배열·원본 해상도 변경을 하지 않는다.
- 메타데이터·GUID·참조 보존과 교체 후 로드는 Unity 에셋 지침을 따른다.

## Sprite 요청·수령·교체

1. 작업 종료 시 신규 Sprite와 정식 아트로 교체할 임시 Sprite를 확인한다. 요청이 있으면 `UnityProject/Assets/Sprites/Require/PLAN-NNN/README.md`를 생성하거나 갱신한다. 폴더명은 요청 출처 PLAN 번호이며 예시는 `PLAN-007`이다.
2. 같은 PLAN의 요청은 기존 README에 항목별로 추가한다. 이전 요청과 처리 기록을 덮어쓰거나 매 작업마다 별도 폴더를 만들지 않는다. 요청이 없으면 폴더·README를 만들지 않는다.
3. README에 아래 명세를 작성하고 요청 출처 PLAN에는 요청 README 링크와 요약을 남긴다. 이후 수령·적용 진행은 README에서 관리한다. 작업 종료 보고에도 요청 유무와 README 경로를 알린다.
4. 사용자는 Aseprite로 제작한 파일을 해당 PLAN 폴더에 넣는다. 에이전트는 작업 시작·재개 또는 파일 제공 알림을 받았을 때 요청과 수령 파일을 대조한다. 파일이 들어왔다는 이유만으로 적용·시각 검수 완료로 처리하지 않는다.
5. 수령한 파일의 이름·크기·프레임·용도와 제공 형식을 확인한다. 불일치·불명확한 규격은 사유와 필요한 확인을 기록하고, 정상 항목은 아래 독립 작업 범위에서 계속 처리한다. 제공 원본을 임의 수정해 요청 규격에 맞추지 않는다.
6. 사용할 Sprite에 이 문서의 임포트 기본값을 적용하고 정규 주제별 최종 경로로 옮겨 씬·프리팹·SO 참조를 연결한다. `.meta`·GUID와 하위 Sprite 참조를 보존하고, 임시 에셋의 남은 참조·표시·애니메이션 연결을 검사한다. Require를 영구 런타임 참조 경로로 쓰지 않는다.
7. README에 수령 파일·최종 경로·검증 결과를 갱신한다. 사용자의 시각 확인 뒤 해당 요청을 완료 처리한다. 이동 후에도 README와 최종 경로 기록을 남기며, 제공 원본과 다른 미처리 파일을 일괄 삭제하지 않는다.

요청 상태는 `요청 → 수령 → 적용 → 사용자 확인 완료`로 구분하고 항목별로 기록한다. 수정이 필요하면 현재 단계와 사유를 남긴다. 이 상태는 PLAN의 status와 별개다.
폴더의 PLAN 번호는 요청 출처만 나타낸다. 해당 PLAN의 상태·완료 여부나 다른 active PLAN 유무와 관계없이 요청·수령·적용·사용자 확인을 진행한다.
독립 작업 범위는 기존 요청 규격에 맞는 파일 확인·등록·임포트 설정·폴더 배치·참조 교체·검증·README 갱신이다. 이를 위해 새 PLAN을 만들거나 완료된 출처 PLAN을 재활성화하지 않는다.
사용자가 별도 `type: art` PLAN으로 관리하는 작업은 해당 PLAN의 승인·단일 active 규칙을 따른다. 그 범위의 작업을 독립 흐름으로 우회 실행하지 않는다.
새 게임 규칙·코드 기능·패키지 도입은 독립 아트 작업에 포함하지 않고 기존 PLAN 승인 절차를 따른다.
PLAN의 타입별 완료 판정은 [PLAN 관리 지침](../plans/AGETNS.md)을 따른다. 일반 개발 PLAN을 아트 대기 때문에 미완료로 두거나 완료 상태에서 되돌리지 않는다.

### 요청 README에 기록할 내용

README 상단에는 요청 출처 PLAN과 이 아트 지침의 실제 링크를 둔다. PPU·임포트 공통값은 복제하지 않고 이 지침을 참조한다.
한 요청을 아래 형식으로 작성하고 필요만큼 반복한다. 요청 ID는 같은 PLAN 안에서 고유하게 유지한다.

```markdown
# PLAN-NNN Sprite 요청

## PLAN-NNN-SPR-001

- 구분: 신규 / 교체
- 요청 파일명: Storage.png
- 용도·표시 위치:
- 필요한 모습·동작:
- 이미지 크기·Sprite Mode:
- 프레임 수·배열·순서·피벗 등 필요한 규격:
- 교체할 Temp_ 에셋 경로: 신규라면 없음
- 사용처·교체할 참조 위치:
- 최종 배치 예정 경로:
- 상태: 요청
- 수령 파일·적용 경로·기술 검증 결과:
- 사용자 확인 결과·남은 수정 사항:
```

파일명은 영어로 작성한다. 정식 제공본 요청 파일명에는 `Temp_`를 붙이지 않는다.
필요 규격은 현재 구현과 사용처에 맞춰 구체화하고 확인되지 않은 값은 미정으로 표시한다. 미수령 파일의 링크를 미리 만들거나 예시를 실제 요청으로 복사하지 않는다.
부분 수령은 요청별로 처리하고, 여러 PLAN에서 같은 Sprite를 요청할 때는 기존 요청을 연결해 중복 제작을 피한다. 요청·진행·검증의 원본은 해당 README이며 출처 PLAN에는 링크와 출처 요약만 둔다.

## Sprite 기본 Inspector 설정

**모든 Sprite의 Pixels Per Unit은 32다.** 월드·UI·VFX와 임시 Sprite에도 동일하게 적용한다.
PPU 32를 모든 이미지 크기가 32×32여야 한다는 뜻이나 시설 한 칸의 화면 크기 확정으로 해석하지 않는다.

| Inspector 항목 | 기본 설정 | 적용 기준 |
| --- | --- | --- |
| Texture Type | Sprite (2D and UI) | Sprite로 사용하는 이미지 |
| Sprite Mode | Single / Multiple | 단일 그림은 Single, 여러 프레임·타일이 있는 시트는 Multiple |
| Pixels Per Unit | **32** | 모든 Sprite에 적용하는 고정 기준 |
| Filter Mode | Point (no filter) | 픽셀 사이의 보간으로 흐려지지 않게 설정 |
| Wrap Mode | Clamp | 일반 Sprite의 기본값 |
| Generate Mip Maps | Off | 일반적인 정면 2D 도트 표현 기준 |
| Read/Write | Off | 코드에서 원본 픽셀을 읽거나 수정해야 할 때만 활성화 |
| sRGB (Color Texture) | On | 캐릭터·배경·UI 등 일반 컬러 이미지 |
| Alpha Source | Input Texture Alpha | 제공 PNG의 알파 채널 사용 |
| Alpha Is Transparency | On | 투명 영역 가장자리 색 처리 |
| Non Power of 2 | None | 항목이 표시되는 경우 원본 크기 유지 |
| Compression | None으로 시작 | 압축 없이 원본 표현부터 확인 |
| Max Size | 원본 이미지의 긴 변 이상 | 실제 Inspector에서 선택 가능한 값 중 원본이 축소되지 않는 값 |

예: 256×128 이미지는 Max Size 256 이상, 768×256 시트는 선택 가능한 값 중 1024 이상으로 설정한다.
Max Size 판단에는 잘라낸 한 프레임이 아니라 원본 시트 전체의 크기를 사용한다. 한계 때문에 원본을 유지할 수 없으면 자동 축소하지 말고 제약을 기록한다.

## 설정의 실제 적용 확인

- PPU는 자동 최적화나 다른 기기의 표시 크기 조정을 이유로 변경하지 않는다. 기준 변경은 사용자의 새 지시를 따른다.
- 나머지는 기본값이다. Read/Write 등 실제 기능 때문에 예외가 필요하면 대상·이유·변경값을 요청 README에 기록한다. 요청과 무관한 개발 설정은 담당 PLAN에 기록한다. 원본 아트나 표현 의도를 바꾸는 변경은 사용자의 요청을 따른다.
- Default 설정뿐 아니라 Android 등 사용 중인 플랫폼 오버라이드가 실제 크기·압축을 바꾸는지 확인한다. 설정상 원본 크기와 무압축 기준을 유지한다.
- Sprite Atlas를 실제 사용하는 경우에도 최종 크기·필터·압축 설정을 확인한다. 이 지침만으로 아틀라스·자동 임포터·픽셀 퍼펙트 카메라를 도입하지 않는다.
- 피벗·Mesh Type·슬라이싱 격자·애니메이션 속도 등 표에 없는 항목은 필요할 때 정한다. 별도 공통 기본값을 임의 확정하지 않는다.
- 항목 표시와 동작은 [Unity 6.3 Sprite 임포트 문서](https://docs.unity3d.com/6000.3/Documentation/Manual/texture-type-sprite.html)를 참고한다. 프로젝트 설정값의 기준은 위 사용자 지정 표다.

## 검증과 교체 기록

1. 대상 경로·파일명·실제 크기·Sprite Mode·PPU·기본값·플랫폼 오버라이드를 확인한다.
2. 실제 씬/프리팹의 참조, 누락 Sprite, 시트 분할·프레임 연결과 표시 여부를 기술적으로 확인한다.
3. 요청 README에 기술 검증 결과와 사용자 시각 확인 여부를 별도로 남긴다. 별도 art PLAN은 해당 기록을 연결해 자신의 완료 기준 충족 여부를 기록한다. 확인하지 않은 색감·품질을 통과로 표시하지 않는다.
4. 임시 에셋은 `임의(Temp)`로 기록하고 사용처·교체 대상·연결 지점을 남긴다. 정식 제공본 연결 후 잔여 임시 참조를 확인한다.

현재 지침 작성은 실제 아트 수령·임포트·시각 검수 완료를 뜻하지 않는다. 독립 아트 작업을 진행하기 위해 현재 개발 PLAN의 범위·상태를 바꾸지 않는다.
