## 기본 화면과 선택 패널 (D-006·D-067)

제품 진입은 D-091에 따라 Bootstrap의 공용 로딩 화면 이후 Title에서 새 게임·이어하기·기존 표시 설정을 선택한다. 기존 저장을 덮어쓰는 새 게임과 플레이/결과의 메뉴 복귀는 확인을 거친다. 로딩 중 뒤 화면 입력을 차단하며 오류 시 재시도·복구를 제공한다. 별도 Loading 씬은 사용하지 않는다. 저장 보호 정책은 [플레이 환경](../../04-delivery/01-platform/environment.md)을 따른다.

공용 로딩 화면은 물마루로 쓴 `Loading...`을 글자별로 움직인다. 다음 씬을 읽는 동안 실제 진행률을 막대와 백분율로 보여준다. 성공한 전환은 전경에서 기본 1초 이상 표시하며 준비가 더 오래 걸리면 완료 즉시 화면을 연다. 오류는 즉시 표시한다.

연구소 기본 화면을 중심으로 운영하며, 시설·생명체를 선택하면 해당 대상의 설정과 상태를 확인하는 패널을 연다. 연구소 화면은 줌인·줌아웃할 수 있다(S1-B-04). 전과 보고는 필요할 때 펼쳐 본다.

| 구성 | 표시와 조작 범위 |
| --- | --- |
| 연구소 기본 화면 | 연구소, 자원·개체 수, 멸망 게이지를 확인하고 건설·방출을 실행한다. |
| 시설·생명체 선택 패널 | 선택한 대상에 해당하는 시설 이동·회전, 작업 배정, 배양 대상 선택, 저장 허용 자원 설정을 제공한다. 작업 상태와 대기 이유도 보여준다. |
| 펼쳐 보는 전과 보고 | 연구소 화면에서 필요할 때 전과 보고를 펼쳐 확인한다. 표시·열람 여부와 성과 누적은 별개다. |

조작은 해당 시설·생명체에 승인된 기능에만 적용한다. 배정·작업 전환은 [보조형 모델](../../02-systems/05-creatures/support-models.md), 배양 선택은 [생산시설](../../02-systems/01-production/facilities.md), 저장 설정은 [저장과 운반](../../02-systems/02-logistics/storage-and-transport.md)의 규칙을 사용한다.

## 선택 강조와 빈 땅 선택 해제

2026-11-15 사용자 요청으로 다음 동작을 정한다. [PLAN-030](../../../plans/PLAN-030-sprite-selection-outline-and-deselect.md)에서 구현과 일반 Editor 검증을 완료했다.

- 시설·생명체 선택은 기존 노란 사각형 대신 All In 1 Sprite Shader를 사용한 본체 Sprite 외곽선으로 강조한다. 색·두께 등 표현 수치는 개발 위임이다.
- 일반 지도 조작 중 선택 대상이 없는 빈 땅을 클릭·탭하면 선택 상태와 강조를 해제한다. 선택 상세·요약·후보 UI도 함께 정리한다.
- UI 조작·지도 드래그·확대와 시설 배치·이동·회전의 위치 지정은 빈 땅 선택 해제로 처리하지 않는다. 기존 조작 우선권과 배치 미리보기는 유지한다.
- 다른 대상 선택 시 이전 강조는 제거한다. 본체와 별개인 운반물·상태 마커까지 합친 외곽선이나 다른 셰이더 효과는 이번 범위에 포함하지 않는다.

<a id="placement-preview"></a>

## 건설·시설 이동 미리보기

2026-11-15 사용자가 요청한 다음 동작을 [PLAN-031](../../../plans/PLAN-031-placement-preview-drag-and-validation.md)에서 구현하고 일반 Editor 검증·화면 확인을 완료했다.

- 신규 건설 종류를 선택하면 추가 지도 클릭 없이 보이는 지도 중앙에 미리보기를 표시한다. 기존 시설 이동은 원래 위치·방향에서 즉시 미리보기를 표시하고 필요하면 해당 위치가 보이게 한다.
- 두 모드 모두 미리보기 건물을 잡아 드래그하면 격자 단위로 후보 위치가 이동한다. 빈 땅 탭으로 위치 지정, 빈 지도 드래그로 지도 이동, 두 손가락 지도 이동·핀치를 함께 제공한다.
- 드래그 종료는 실제 배치 확정이 아니다. 기존 확정·취소·90도 회전 흐름을 유지하며 이동 대상은 확정 전까지 실제 원래 위치와 상태를 보존한다.
- 점유 칸 중 다른 시설과 겹치거나 건설 영역 밖으로 나간 칸을 구분하고, 배치 불가 이유를 텍스트로 함께 표시한다. 위치·회전에 따라 표시와 확정 가능 상태를 갱신한다. 이동 대상 자신은 충돌에서 제외한다.
- 통로 차단·생명체 겹침·작업 위치 접근 문제를 새로운 배치 금지 조건으로 추가하지 않는다. 판정 기준은 [시설 배치](../../02-systems/03-space/placement.md)와 같다.
- 화면 가장자리 자동 이동·새 입구 표시·연속 건설은 이번 범위에서 제외한다. 구체적인 색·터치 판정 여유·진단 API는 개발 위임이며 세부 조작과 검증은 PLAN을 따른다.

## 작은 시설 진행 바

2026-11-15 사용자 요청에 따라 지도 위 시설 상태 표시를 다음 방향으로 단순화한다. [PLAN-032](../../../plans/PLAN-032-minimal-facility-progress-bars.md)는 completed이며 구현·일반 Editor 검증·실제 화면 확인을 완료했다. PLAN-014의 표식 재탭·문구 확장·상태 표시 ON/OFF 동작은 이번 요구로 대체한다.

- 진행 대상 시설 위에는 얇은 배경 막대와 진행량으로 구성된 작은 바 하나만 표시한다. 아이콘·퍼센트·설명 글자·배경 카드·연결선을 붙이지 않는다.
- 바는 조작 기능 없이 상태만 계속 표시한다. 클릭·탭·호버·설명 펼치기·표시 ON/OFF 조작을 제거한다. 입력은 아래 지도·시설·배치 미리보기의 기존 규칙으로 처리한다.
- 선택·줌·큰 글씨 설정으로 바가 커지거나 글자가 나타나지 않는다. 시설 가까이에 배치하며 화면 밖 바를 가장자리로 모으지 않는다. 작은 크기·얇은 배경의 대비와 선명도는 실제 모바일 비율 화면에서 조정한다.
- 정상 진행과 대기는 같은 막대의 색조로 구분하고 진행량은 기존 상태를 따른다. 0% 대기도 얇은 배경에 남겨 표시하며, 전체 일시정지는 별도 시설 장애로 해석하지 않는다.
- 완공 저장소처럼 진행할 작업이 없는 시설에는 바를 표시하지 않는다. 건설 중인 저장소에는 건설 바를 표시한다.
- 정확한 진행률·대기 이유·설정은 기존 시설 선택 상세 패널에서 확인한다. 시설 본체 선택과 상세 패널의 조작은 유지한다.
- 이전 표시 OFF 설정이 새 바를 숨기지 않게 하되 기존 설정 파일과 다른 설정을 보존한다. 구체적인 막대 치수·색·호환 정리는 PLAN의 구현 위임 범위다.

## 가로·세로 지원 (D-090)

**프로토타입에서도 가로·세로 화면을 모두 지원한다. 가로 화면에서 기본 게임 사이클을 먼저 완성한 뒤 세로 대응을 추가한다.**

- 두 방향에서 같은 기능과 화면 요소를 유지한다. 기존 연구소 기본 화면·시설과 생명체 선택 패널·전과 보고를 함께 사용한다.
- 화면 방향에 따라 기존 요소를 재배치하는 수준으로 대응한다. 방향별 게임 규칙이나 전용 기능을 추가하지 않는다.
- 가로에서 초기 건설부터 생산·침공·한 판 종료와 다시 시작까지 연결한 뒤 세로 대응을 추가한다. 최종 검증에서는 두 방향을 모두 확인한다.

단계별 순서는 [구현 계획](../../05-development/02-implementation/roadmap.md), 실제 Android 기기 검증은 [플레이 환경](../../04-delivery/01-platform/environment.md)을 따른다.

가로·세로 UI와 모바일 입력은 [PLAN-013](../../../plans/PLAN-013-responsive-ui-and-mobile-input.md)·[PLAN-014](../../../plans/PLAN-014-mobile-ui-ux-and-facility-status.md)에서 구현하고 당시 APK의 직접 기기 검증을 완료했다. 이후 추가된 씬 흐름·Localization·Popup·연출을 포함한 최신 Android 통합 검증은 [PLAN-025](../../../plans/PLAN-025-android-integration-and-prototype-completion.md)에서 사용자 승인에 따라 완료했다. 해당 기종·APK의 증거와 남은 표시/측정 한계는 해당 PLAN을 따른다. 과거 검증을 최신 버전의 통과로 간주하지 않는다.

## 시간 흐름과 결과 화면 (D-033·D-064)

시설 배치·이동·회전의 위치와 방향을 고르는 동안 연구소 진행을 일시정지하고, 확정하거나 취소하면 재개한다. 상태·작업·예약 유지와 재개 규칙은 [시설 배치](../../02-systems/03-space/placement.md)를 따른다.

멸망 게이지가 가득 차면 연구소와 외부 활동의 진행을 멈추고, 간단한 멸망 연출 후 결과 화면을 표시한다. 플레이어가 ‘다시 시작’을 선택하면 초기 상태로 돌아간다. 진행 정지 중에도 연출과 화면 표시는 동작한다. 한 판 종료·재시작은 [목표와 반복 흐름](../../01-direction/02-experience/core-loop.md), 단계 전환 책임은 [GameFlow](../../05-development/01-architecture/game-flow.md)를 따른다.

여러 세계 진행·환생·영구 보너스는 현재 결과 화면에 포함하지 않는다. 전체 포함·후속 범위는 [최초 제공 범위](../../04-delivery/02-release/scope.md)에서 관리한다.

## 화면과 로직 연결 및 개발 위임 (D-059·D-079)

화면의 조작과 상태 표시는 플레이 화면·하네스의 공통 명령 처리·규칙 검사·상태 조회를 사용한다. 상태 원본과 구조의 정식 기준은 [Thing과 정의 데이터](../../05-development/01-architecture/thing-model.md)를 따른다.

버튼 위치·크기, 패널 배치, 화면 비율 대응, 카메라 표시 범위, 방향 전환 처리, 연출·결과 화면의 표현과 세부 조작 구현은 개발하면서 정한다. 실행·저장 규칙은 [플레이 환경](../../04-delivery/01-platform/environment.md)을 따른다.
