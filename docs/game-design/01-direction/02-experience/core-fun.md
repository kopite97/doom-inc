## 플레이 재미의 핵심 콘셉트

> 생산시설을 건설하고 자재의 운반과 배치를 개선하면서, 병목을 발견하고 해결하는 방법을 배워가는 모바일 게임.

이는 플레이 재미의 중심을 정의한 승인 문장이다. 게임 전체의 테마와 정체성은 [게임 콘셉트](../01-identity/concept.md)에서 관리한다.

초반에는 시설의 역할을 배우고, 운반량이 늘면 배치의 중요성을 깨닫고, 발생한 병목을 개선하면서 게임을 학습한다. 별도 해금 조건이나 강제 진행 순서를 추가하는 규칙은 아니다.

## 다섯 가지 재미 요소

| 요소 | 플레이어가 느끼는 경험 | 관계 |
| --- | --- | --- |
| 학습과 문제 해결 | 시설 역할을 배우고 운반·배치의 문제를 발견해 개선한다. | 중심 재미 |
| 연구소 관찰 | 생명체가 일하고 연구소가 돌아가는 모습을 지켜본다. | 관찰 |
| 배양과 발견 | 생명체의 외형과 쓰임새를 알아간다. | 발견 |
| 전과 보고의 호기심 | 방출한 생명체가 어떤 황당한 일을 벌였는지 확인한다. | 호기심 |
| 세계 멸망의 성취감 | 연구소 운영의 결과가 멸망 게이지 상승으로 이어짐을 느낀다. | 성취감 |

나머지 네 요소 사이의 순위나 비중은 정하지 않았다. 이 표를 근거로 새로운 콘텐츠 종류를 늘리지 않으며 프로토타입 포함 범위는 [최초 제공 범위](../../04-delivery/02-release/scope.md)를 따른다.

## 개발에서 확인할 경험

작업 상태와 대기 이유를 보고 대표적인 병목을 파악한 뒤 배치·배정·저장 설정 등으로 개선할 수 있어야 한다. 현재 규칙과 검증 기준은 [병목 해결](../../02-systems/04-optimization/bottlenecks.md), 표현은 [이해와 피드백](../../03-player-experience/02-learning/guidance.md)을 따른다. 세부 표현과 조정 수치는 개발하면서 정한다.
