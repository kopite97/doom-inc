# 자율 행동과 작업 운영

- 갱신일: 2026-11-17
- 상태: 작업 긴급도·기본 우선순위·거리 기반 선택·작업 중단·커맨더 배분 방향 확정. 수치와 긴급 구조·자기 보충의 충돌 기준 등 세부 미정
- 근거: 2026-11-17 사용자가 제안한 작업 선택·우선순위 방식을 채택하고 수치 및 긴급 구조·자기 보충 충돌 기준을 미정으로 유지하도록 요청.

## 목적과 확정 방향

- 생명체는 자신이 할 수 있는 일을 기본적으로 자율 수행한다.
- 플레이어는 작업 우선순위나 담당 시설을 정해 운영에 개입할 수 있는 방향으로 설계한다.
- 초반 소수 개체의 관찰·조정과 중후반 다수 개체의 운영을 함께 고려한다.
- 초반에는 단순한 행동 알고리즘을 사용하고, 플레이어가 조정하면 효율이 개선되는 여지를 둔다.
- 이후 [커맨더](commanders.md)가 작업 분배를 대신 판단해 반복 설정 부담을 줄이도록 한다.
- 수행 가능 여부는 [생명체 기능](creatures.md)을 따른다. 이전 보조형의 기능 상속·시설 배정 제한을 그대로 적용하지 않는다.
- [건설](construction.md)은 자재 운반과 현장 작업을 통해 진행한다. 플레이어는 위치와 현장 우선순위를 정하고 실제 작업 배분은 자율 행동·커맨더로 처리한다.
- [생산시설](production.md)에서 시약 제조는 생명체 작업, 배양은 재료 공급 후 자동 진행, 연구는 조수 작업으로 구분한다.
- [물류 정책](logistics.md)은 창고·시설 요청과 자원 배분의 기준이다. 작업 긴급도가 높아도 보호된 최소 유지분을 임의로 소비하지 않는다.

## 작업 선택 순서

수행 가능 여부 → 작업 긴급도 → 설정된 작업 우선순위 → 가까운 작업 순으로 선택한다.

| 단계 | 작업의 목적과 예시 | 기본 처리 |
| --- | --- | --- |
| 긴급 | 전투 후 구조, 회복 중인 개체에게 필요한 원료 공급 | 실행 가능한 일반 작업보다 우선 |
| 운영·생산 | 필요한 자원 수집·시설 공급·시약 제조·건설 | 플레이어 설정과 기본 우선순위 적용 |
| 비축·정리 | 여유 재고 확보·당장 사용하지 않는 물품 정리 | 상위 작업에 필요한 인력을 제외하고 수행 |

- 작업 종류만으로 긴급도를 고정하지 않는다. 같은 운반이라도 회복 재료 공급과 여유 물품 정리를 구분한다.
- 가능한 행동·재료·경로 등 실행 조건을 충족하는 일만 선택한다. 회복 원료가 없으면 불가능한 운반에 매달리지 않고 수집 가능한 개체가 원료를 확보하는 등 다른 가능한 일을 수행한다. 선행 수집에 긴급도를 전달하는 세부 기준은 미정이다.
- 이미 다른 개체가 맡은 일에 필요 인원 이상으로 몰리지 않게 한다. 필요한 인원과 동시 작업 수 등의 수치는 미정이다.
- 같은 긴급도와 작업 우선순위에서는 가까운 일을 선택한다. 거리 산정·동률 처리와 오래 대기한 작업의 처리는 별도로 구체화한다.

## 기본 설정과 플레이어 개입

- 새로 배양한 개체는 가능한 행동에 맞는 기본 작업 우선순위를 가진다. 모든 개체의 작업표를 설정하지 않아도 일상 운영이 가능해야 한다.
- 플레이어는 필요한 개체의 작업 우선순위나 담당 시설을 변경할 수 있다. 담당 시설에 일이 없으면 다른 가능한 작업을 수행한다.
- 2026-11-17 지정한 [주인공 선택](../experience/characters.md)을 행동 방침 설정의 진입점으로 사용한다. 본진 전투 시 참여·작업 유지는 [평시 전투 방침](defense.md#평시-방침과-전투-모드)을 따르며 기존 작업 우선순위와 구분한다.
- 초기 3종의 기본 방향은 아래와 같다. 행동 목록은 [생명체](creatures.md)를 따르며 작업 성능의 특화는 관련 수치로 표현한다. 기본 작업표를 별도 특화 여부·종류 필드로 해석하지 않는다.

| 초기 개체 | 평상시 기본 선택 방향 |
| --- | --- |
| 건설 가능한 민트색 개체 | 건설 우선, 건설할 일이 없으면 수집·운반 |
| 시약 제조 가능한 보라색 개체 | 시약 제조 우선, 재료가 없으면 가능한 공급 운반 |
| 수집·운반 가능한 주머니 개체 | 필요한 자원 수집과 시설 공급 |

- 위 방향은 긴급 작업보다 앞서는 고정 직업이 아니다. 구체적인 우선순위 값과 표 안에 명시하지 않은 작업 간 순서는 미정이다.

## 작업 중단과 자기 보충

- 일반적인 우선순위 변경은 현재 작업의 적절한 구간을 마친 뒤 적용한다. 작은 변화마다 작업을 반복 교체하지 않는다.
- 구조 같은 긴급 작업은 일반 작업을 중단하고 전환할 수 있다. 구조는 [전투 종료 후 자동 수행](maintenance-and-loss.md)하며 전투 중 구조를 추가하지 않는다.
- 운반 중 전환한다면 물건을 안전하게 내려놓는 등 중단 절차를 거친다. 내려놓은 물품은 정책에 따라 다시 배분하며 긴급 원료라는 이유로 보호 비축을 자동 해제하지 않는다.
- 중단한 작업은 진행도를 보존할 수 있는 범위에서 재개한다. 건설 진행도 보존은 [건설](construction.md)의 확정 규칙이며 다른 작업의 보존 범위는 별도로 정한다.
- 자기 유지 보충은 작업 사이에 자동 수행하되 효율 저하가 커지면 먼저 보충한다. 보충 방식은 [물류](logistics.md)를 따른다.
- 긴급 구조와 자기 보충이 겹쳤을 때의 기준은 미정이다. 위 선택 순서만으로 어느 쪽이 항상 우선한다고 확정하지 않는다.
- 2026-11-17 지정한 [작업 유지 개체의 대피](defense.md#평시-방침과-전투-모드)는 위협 시 작업보다 우선하며, 적에게서 최대한 먼 이동 가능한 장소로 피한 뒤 위협이 사라지면 작업에 복귀한다. 운반물·예약·기존 작업 재개와 재선택의 세부 처리는 미정이다.

## 커맨더 배분과의 관계

- 실행 불가능한 일 건너뛰기·중복 배정 방지·기본 선택은 커맨더 없이도 제공한다. 전체 인력을 더 효율적으로 나누는 것이 [커맨더](commanders.md)의 역할이다.
- 주인공은 행동 방침과 개별 설정·자동 배분 위임을 정하고, 커맨더는 그 안에서 인력을 배분하는 보조 역할이다. 주인공이 고정한 설정을 임의로 바꾸지 않는다. 긴급 작업과 고정 설정의 세부 충돌은 공통 규칙으로 추가 기획한다.
- 초기 커맨더는 유휴 개체 분배, 상위 커맨더는 실제 작업 속도·자원 상황을 고려한다. 운반을 다른 개체에게 넘겨 제조 가능한 개체를 제조에 복귀시키는 것은 상위 판단의 예시다.
- 커맨더 명령 Low의 낮은 코스트 우선 배분은 유지한다. 명령 수준·알고리즘 수준·작업 긴급도를 서로 구분한다.

## 행동의 이해

- 기본 행동과 지시 결과를 [UI](../experience/interface.md)에서 관찰할 수 있도록 한다.
- 작업 우선순위와 시설 배정은 연구소 운영을 위한 개입이다. [완전 자동 전투](defense.md)를 수동 제어하는 기능으로 확장하지 않는다.

## 검토 중인 제안

- 시설별 필요 인원 설정과 구역 관리 방식은 검토안이다.
- 일감이 없을 때의 대기는 정상 상태로 허용하는 방향을 검토한다. 유휴 감소를 위한 무의미한 작업을 만들지 않는다.

## 미정

- 우선순위 값·동시 작업 인원·자기 보충 기준 등 구체적인 수치와 긴급 구조·자기 보충 충돌 기준.
- 긴급 작업 안의 순서·필요 인원, 선행 작업의 긴급도, 거리 동률·장기 대기 처리.
- 개체별 우선순위와 담당 시설의 세부 관계, 커맨더 자동 배분의 위임·해제 방식과 수동 설정 보호 범위, 긴급 작업과 보호 설정의 충돌 처리.
- 작업별 중단 가능한 구간·진행도 보존·안전한 물품 내려놓기·예약 유지와 해제, 전투·대피 전환 시 처리. 건설 진행도 보존 외 자재·취소·파괴 처리는 별도 미정이다.
- 자원 예약과 필요 인원 초과 배정 방지의 상세 처리. 기존 코드의 레시피·자원 수·속도를 자동 승계하지 않는다.
