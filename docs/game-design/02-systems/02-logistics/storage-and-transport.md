## 범위와 연결

이 문서는 저장소의 용량·허용 자원, 운반량·목적지 선택, 예약과 운반 예외의 정식 규칙을 관리한다. 자원을 한곳에 모으거나 분산 보관하며 운반 동선을 설계하는 것이 배치의 중요성과 연결된다(D-001·D-012).

보조형이 자원을 운반한다. 모델 기능·자동 작업 자격·작업 종류의 우선순위·시설 배정 전환은 [보조형 모델](../05-creatures/support-models.md#task-selection)을 따른다. 자원 투입·회수·시설 작업은 [고정 상호작용 위치](../03-space/placement.md#interaction-position)에서만 수행한다.

생산시설은 한 회차분 재료 준비와 해당 회차 완료품 대기만 유지하며 여러 회차의 자체 입출력 재고를 쌓지 않는다. 저장소에서 공급하고 자원 결과물을 저장소로 보내는 [생산 회차 규칙](../01-production/facilities.md#production-cycle)을 따른다. 전체 콘텐츠와 시작 상태는 [프로토타입 범위](../../04-delivery/02-release/scope.md)에서 관리한다.

<a id="storage-capacity"></a>

## 저장소와 용량

- 저장소 건물은 범용 저장소 한 종류다. 플레이어가 저장소마다 허용할 자원을 지정한다(D-013).
- 모든 자원을 허용하면 공용, 일부만 허용하면 전용 저장소처럼 사용한다. 별도의 건물 종류를 추가하지 않는다.
- 새 저장소는 기본적으로 모든 자원을 허용한다(D-024).
- 실제 사용 용량은 보관 중인 **모든 자원 수량의 합계**다. 종류별 크기·무게 차이 없이 자원 1개가 용량 1을 차지한다(D-015).
- 입고 예약 수용량은 실제 재고와 구분하되 다른 작업이 사용할 여유 공간에서 제외한다. 실제 입고로 전환한 수량을 예약으로 중복 계산하지 않는다(D-021).

### 보관할 곳이 없을 때

운반 시작 전 해당 자원을 허용하고 접근 가능한 다른 저장소에 여유가 있으면 그곳으로 운반한다. 보관할 곳이 없으면 운반을 시작하지 않으며 자원을 버리거나 바닥에 내려놓지 않는다(D-016).

자원 완료품은 생산시설에서 기다린다. 공간이 생기면 기존 작업 우선순위로 운반을 재개한다. 해당 회차 완료품은 **전량이 저장소에 실제 입고된 뒤** 다음 생산을 시작한다. 운반 중 공간·경로가 바뀌는 경우에는 아래 [운반 예외](#transport-exceptions)를 적용한다.

<a id="transport-selection"></a>

## 운반량과 대상 선택

### 한 번의 운반량 (D-017)

- 한 번에 한 종류의 자원만 운반한다.
- 각 생명체는 최대 운반 수량을 가진다.
- 실제 운반량은 **개체의 최대 운반량, 공급처의 가용 수량, 목적지의 수용 가능 수량 중 최솟값**이다. 공급처·목적지 수량은 다른 개체의 예약분을 제외한다.
- 최대량을 채우지 못해도 운반하며, 가능한 수량이 0이면 시작하지 않는다.
- 목적지가 생산시설인 경우 수용 가능 수량은 준비할 현재 회차의 부족분이다. 자체 비축 재고를 추가하지 않는다.

### 거리·장애물과 동률 (D-018·D-020·D-027)

- 장애물을 피해 실제로 이동할 수 있는 최단 경로의 길이로 거리를 비교한다. 시설 대상으로는 지정된 상호작용 위치까지의 경로를 사용한다.
- 생산시설을 포함한 시설은 이동을 막는다. 생명체끼리는 겹쳐 지나갈 수 있고 서로의 경로를 막지 않는다.
- 접근할 수 없는 시설은 작업 대상에서 제외한다. 개체끼리 겹쳐 이동할 수 있다는 규칙이 동시 작업 인원을 정하지는 않는다.
- 기존 우선순위와 거리가 같으면 **먼저 생성된 대상**을 선택한다. 공급처와 목적지에 각각 적용하며 시설을 이동해도 최초 생성 순서는 유지한다.

### 공급처를 먼저 선택 (D-019)

1. [작업 우선순위](../05-creatures/support-models.md#task-selection)에 따라 작업 종류를 고른다.
2. 운반 가능한 공급처 중 생명체의 **현재 위치에서 가장 가까운 공급처**를 고른다.
3. 해당 자원을 받을 수 있는 목적지 중 **선택한 공급처에서 가장 가까운 목적지**를 고른다.

공급처는 가져올 자원이 있고 접근 가능한 유효 목적지가 있는 곳만 후보로 삼는다. 목적지는 수용 가능량이 있어야 하며 저장소라면 허용 자원 설정도 만족해야 한다. 두 구간 모두 위 최단 경로 기준을 사용하며, 자원·수용량의 가용 여부는 예약분을 제외하고 판단한다.

<a id="reservations"></a>

## 자원·수용량 예약과 실물 소속

D-021의 정상 운반 예약은 다음과 같다.

| 시점 | 공급처 | 목적지 |
| --- | --- | --- |
| 작업을 맡음 | 가져올 자원을 운반량만큼 예약 | 수용량을 운반량만큼 함께 예약 |
| 자원을 집음 | 해당 예약을 실제 반출로 전환 | 입고 예약 유지 |
| 운반 중 | 반출된 자원은 개체가 보유 | 입고 예약 유지 |
| 자원을 내려놓음 | — | 해당 예약을 실제 입고로 전환 |

- 다른 생명체는 예약된 수량을 제외하고 운반 가능량을 계산한다. 남은 자원·수용량이 있으면 같은 공급처·목적지를 이용할 수 있다. 시설 전체를 예약하지 않는다.
- 실물 자원은 한 보관처에만 속하고 출고·입고 예약은 별도 관리한다. 실제 수령·입고 시 소속을 변경한다(D-075).
- 실제 재고와 예약을 중복 계산하지 않는다. 구조의 기준은 [Thing과 정의 데이터](../../05-development/01-architecture/thing-model.md)를 따른다.
- 경로 차단·시설 변경 또는 허용 목록 변경 시 아래 예외 규칙으로 예약을 유지·해제·재예약한다.

<a id="normal-transport"></a>

## 정상 운반 유지와 다음 작업

운반을 맡으면 자원을 집기 전 이동까지 포함해 완료할 때까지 유지한다(D-023·D-053).

- 더 가까운 대상이나 높은 우선순위 작업이 생겨도 정상 운반을 중간에 바꾸지 않는다.
- 시설 배정 변경·해제나 담당 생산 작업이 가능해진 경우에도 정상 운반을 마친 뒤 전환한다.
- 완료 후 그때의 작업 우선순위·거리·동률 기준에 따라 다음 작업을 선택한다.
- 경로 차단·시설 변경·목적지 허용 자원 변경에는 완료를 기다리지 않고 해당 예외를 적용한다.
- 수집·생산 등 운반 외 행동의 전환 시점은 [보조형 모델](../05-creatures/support-models.md)에서 관리한다.

<a id="transport-exceptions"></a>

## 운반 중 경로 차단·시설 변경

먼저 변경된 상호작용 위치까지 장애물을 피하는 최단 이동 경로를 다시 계산한다. 이후 자원을 이미 집었는지에 따라 처리한다(D-022).

| 상황 | 처리 |
| --- | --- |
| 시설이 이동하거나 길이 바뀌었지만 기존 대상을 계속 이용할 수 있음 | 새 경로로 진행하고 작업·유효 예약을 유지한다. |
| 자원을 집기 전에 작업이 불가능해짐 | 공급처·목적지 예약을 모두 해제하고 기존 우선순위·대상 선택 규칙으로 새 작업을 고른다. |
| 자원을 집은 뒤 기존 목적지를 이용할 수 없음 | 기존 목적지 예약을 해제하고 현재 위치에서 가장 가까운 유효 저장소를 찾아 수용량을 예약한다. |
| 보관할 곳이 전혀 없음 | 자원을 든 채 현재 위치에서 대기한다. 경로나 공간이 확보되면 다시 목적지를 찾는다. |

- 대체 저장소는 자원 허용, 접근 가능, 다른 생명체의 예약을 제외한 여유 공간 조건을 모두 만족해야 한다.
- 자원을 든 상태의 대체 저장소는 **개체의 현재 위치부터** 거리를 비교하며, 동률이면 최초 생성 순서를 적용한다.
- 대체 저장소에 공간이 일부만 있으면 가능한 수량만 예약·입고한다. 남은 자원은 다음 유효 저장소로 운반하고, 보관할 곳이 없으면 계속 든 채 대기한다.
- 자원을 버리거나 바닥에 내려놓지 않는다. 들고 있는 자원을 처리하기 전에는 다른 작업을 맡지 않는다.
- 이미 자원을 집었다면 공급처가 이동해도 운반을 계속한다.
- 자원 완료품을 대체 저장소에 나눠 보내더라도 해당 회차 전량이 **실제 입고된 뒤** 다음 생산을 시작한다.

시설 이동 시 재고·허용 설정·시설에 남은 완료품은 [이동 상태 보존](../03-space/placement.md#facility-movement)을 따른다. 이미 운반 중인 자원은 개체가 계속 보유한다. 배치 조작 중에는 작업·예약을 유지한 채 연구소를 일시정지하고, 확정 시 배치 변경과 경로·예외 처리를 반영한 뒤 재개한다. 취소하면 기존 배치에서 재개한다(D-032·D-033).

<a id="allowed-resources"></a>

## 허용 자원 변경

### 이미 보관된 재고 (D-025)

- 새 허용 목록과 대조하여 계속 허용되는 재고는 현재 저장소에 유지한다.
- 제외된 재고는 그 자원을 허용하고 접근 가능하며 여유 공간이 있는 다른 저장소로 자동 재배치한다. 위 거리·동률·운반량·예약 규칙을 적용한다.
- 옮길 곳이 없으면 기존 저장소에 남겨 두고 공간이 생기면 운반한다. 실제 반출 전까지 용량을 차지한다.
- 이미 출고 예약된 수량을 중복 이송 대상으로 잡지 않고 기존 운반을 이어간다.
- 정상 운반을 끊지 않으며, 다음 운반 선택 때 기존 작업 우선순위에 따라 재배치한다. 목적지 허용 변경으로 현재 운반이 무효가 된 경우에는 아래 즉시 처리 규칙을 적용한다.

### 변경 전 입고 예약·운반 중 자원 (D-026)

새 허용 목록을 기존 입고 예약과 운반 중인 자원에도 즉시 적용한다.

| 변경 후 상태 | 처리 |
| --- | --- |
| 계속 허용되는 자원 | 기존 입고 예약과 운반 유지 |
| 제외된 자원이며 아직 집기 전 | 해당 입고 운반의 공급처·목적지 예약을 모두 해제하고 새 작업 선택 |
| 제외된 자원이며 이미 운반 중 | 기존 목적지 예약을 해제하고 현재 위치에서 가장 가까운 유효 저장소의 수용량을 재예약하여 운반 |

부분 입고와 보관할 곳이 없을 때의 대기는 [운반 예외](#transport-exceptions)를 따른다. 허용 목록을 바꾼 저장소에서 **밖으로 나가는 기존 출고 예약은 유지**한다. 위의 공급처 예약 해제는 해당 저장소로 들어오려던 운반을 취소할 때의 처리다.

<a id="development-details"></a>

## 개발 중 결정할 상세와 후속 범위

D-059에 따라 저장 용량·최대 운반량·이동 속도, 경로 탐색 구현, 생성 순서 저장 방식, 자료구조와 자원 묶음의 분할·합치기는 개발하면서 결정한다.

현재 프로토타입에 포함하지 않는 모델의 수치 차이는 후속 개발 범위다. 생산시설의 공급 조건·회차 완료와 생명체 출현의 구분은 [생산시설](../01-production/facilities.md), 초기 건설 자원의 지급·사용은 [프로토타입 범위](../../04-delivery/02-release/scope.md)를 따른다.
