## 목표와 범위

완성한 게임 흐름에 정식 아트를 단계적으로 연결해, 시설·생명체·운영 상태를 그림으로 구분할 수 있는 연구소를 만든다. 가장 오래 보는 연구소 화면부터 완성하고 그 결과를 UI·연출·타이틀에 확장하는 순서를 권장한다.

이 문서는 전체 로드맵의 **후속 5단계**다. 1~4단계와 [PLAN-025의 D-070 완료](../../../plans/PLAN-025-android-integration-and-prototype-completion.md)는 당시 소스·임시 표현 기준의 완료로 유지한다. 아트 적용 완료는 별도로 판정한다.

5-1은 [PLAN-026 스타일·크기 샘플과 연구소 적용](../../../plans/PLAN-026-art-style-scale-and-sample-integration.md) `art` / `completed`로 완료했다. 5개 분류·8개 샘플(PNG 5파일·106 Sprite)의 전체 적용 후 Editor 기술 검증과 사용자의 실제 게임 화면 승인을 마쳤다. 획득시설 r003 36프레임과 보조형 r002 4방향 64프레임·머리 위 운반을 포함한다. 채택 규격·화면·한계는 [통합 완료 증거](../../../plans/evidence/PLAN-026/integration-2026-11-10/README.md)를 따른다.

별도 표현 기반 완료 [PLAN-027 연구소 Tilemap·SpriteRenderer 전환](../../../plans/PLAN-027-laboratory-tilemap-and-sprite-rendering.md)은 `development` / `completed`다. 2026-11-10 사용자 승인 후 바닥 Tilemap·시설/개체 SpriteRenderer·UI uGUI 전환과 Editor 검증을 완료했다. 원본 아트·게임 상태를 보존했다.

[PLAN-028 이동 보간](../../../plans/PLAN-028-creature-movement-interpolation.md)은 기존 아트를 재사용하는 development·completed 작업이다. 이동 보간·표시/입력 구현과 Editor 기능 검증을 마쳤고 빌드·고부하 제외 재개 요청에 따라 현재 소스와 기존 증거를 대조해 완료했다. 추가 계측과 신규 아트 요청은 없으며 기존 성능 한계와 완료된 5-1 판정을 유지한다.

현재 대상은 기존 시설 4종·생명체 4종·자원 2종과 기존 화면이다. 여러 세계·새 생명체·새 시설·전투 장면·해금 시스템은 추가하지 않는다. 외부 침공은 기존 텍스트 보고와 멸망 게이지로 표현한다. PLAN-025의 큰 글씨 안내 잘림과 GC 최적화 후보는 사용자 요청에 따라 잠시 미뤄 두며, 이 문서 작성이나 첫 아트 샘플의 선행 조건으로 삼지 않는다.

정식 아트는 사용자가 Aseprite로 제작하고, 에이전트가 등록·연결·기술 검증을 담당한다. 최종 외형·색감·스타일·가독성·동작의 시각 확인은 사용자가 한다. 제작 방식과 임포트 공통값은 [아트 지침](../../../agents/art-assets.md)을 따른다. 세부 규격과 각 단계의 완료 기준은 아래 제안에서 실제 작업 범위를 정할 때 구체화한다.

### 첫 제작 묶음: 5-1

첫 묶음은 **5개 분류·8개 샘플**이다. 사용자 추가 요청으로 획득시설은 Idle·Working·Complete, 프로토타입은 4방향 Idle·Move·Work와 머리 위 자원 합성 표시를 포함한다. 바닥·유기물·Build는 정적이며 바닥 4개를 혼합한다. 파일명·크기·프레임·시간·받침점·검증 상세는 PLAN-026과 요청 README에서 관리한다. 샘플은 다음 단계와 렌더링 전환에서 재사용하며 같은 외형을 중복 제작하지 않는다.

제작 전에 실제 요청서에서 다음을 구체화한다. 아직 정하지 않은 픽셀 수·프레임 수·방향 수·팔레트를 이 문서의 확정 제작 규격으로 취급하지 않는다.

| 확인할 항목 | 이번 샘플에서 결정할 내용 |
| --- | --- |
| 비율·시점 | 시설과 생명체의 상대 크기, 탑다운에서 보이는 면, 상호작용 위치와 그림의 기준점 |
| 명암·색·실루엣 | 바닥보다 시설/개체가 잘 보이는 대비, 역할 구분, 선택/대기 표식의 가독성. 팔레트·조명 방향은 사용자 확인 |
| 바닥 변형 | 기본·변형의 공통 연결면과 낮은 경계 대비, 혼합 시 반복감·밀집, 화면 갱신·이어하기 후 같은 칸의 무늬 유지. 지형 규칙·게임 난수·저장 형식은 변경하지 않음 |
| 시설 회전 | 그림 회전 재사용과 방향별 원화 중 표현에 맞는 방식 선택. 논리 회전·점유·입구는 기존 규칙 유지 |
| 원본과 출력 | Aseprite 원본과 Unity용 출력, 여백·알파·피벗·캔버스/시트 크기. 기존 건설 아이콘은 PLAN-014 요청 규격 우선 |
| 지도 표시 | 시설을 여러 점유 칸에 같은 그림으로 반복하지 않고 한 시설 외형으로 표시하는 경로, 개체 겹침과 그리기 순서 |

첫 묶음에서는 획득시설·프로토타입의 지정 동작 외에 다른 종류의 전체 애니메이션·시설 장식 변형·새 배경 테마까지 요구하지 않는다. Tilemap·SpriteRenderer 전환은 PLAN-027로 분리했으며 2026-11-10 별도 실행 승인을 받았다. Sprite Atlas·Pixel Perfect Camera·Aseprite 전용 임포트 방식도 자동 도입하지 않는다.

### 상호작용이 많은 생명체의 외형

2026-11-07 사용자가 슬라임 형태의 참고안을 선호하며 상호작용이 많은 대상에 같은 방식을 적용하도록 지정했다. 이후 보조형의 귀여운 인상·두 눈·단색 점눈을 명시했다. 이 기준 안에서 몸체 색·세부 비율·실루엣은 사용자 시각 확인으로 정하며 특정 생성 이미지를 정식 제공본으로 취급하지 않는다.

- 건설·수집·운반 등 상호작용이 많은 보조형은 팔다리별 세부 동작에 의존하지 않는 슬라임·젤리형의 단순한 몸체를 기본으로 한다. 종류 구분은 몸체 윤곽·얼굴·작은 무늬로 확보하며 모두 같은 외형으로 만들 필요는 없다.
- **보조형의 인상과 눈:** 프로토타입·보급형 등 보조형은 귀엽고 친근한 인상을 우선하며 둥글고 부드러운 몸체와 **눈 두 개**를 기본 디자인으로 한다. 각 눈은 **흰색 또는 검은색 한 색으로 채운 작은 점**으로 그린다. 흰자·홍채·동공을 겹쳐 그리는 안구 구조나 눈 안의 다른 색 반사점은 사용하지 않는다. 점은 작은 원·타원 형태로 표현할 수 있으며 반드시 1픽셀일 필요는 없다. 같은 개체의 두 눈은 같은 색을 사용하고 몸체와의 대비로 흰색/검은색을 선택한다.
- **방향별 얼굴과 검수:** Down 정면은 두 점눈을 보이게 한다. Left/Right 측면은 원근·가림에 따라 먼 쪽 눈을 생략할 수 있고 Up 뒷면에는 눈을 그리지 않는다. 눈이 한 개만 보이는 측면을 외눈 캐릭터 설정으로 해석하지 않는다. 각 동작에서 눈의 간격·몸체와의 관계·색을 일관되게 유지하고 실제 표시 크기에서 두 점이 합쳐지거나 무늬에 묻히지 않는지 확인한다. 최종 귀여움·가독성은 사용자가 확인한다.
- 이동·작업은 몸체의 짧은 눌림·팽창 같은 공통 동작을 재사용하는 방향으로 제작한다. 시설별 손 위치·도구 잡기·관절 동작을 기본 요구로 늘리지 않고 시설의 반응과 상태 표시로 작업 종류를 구분한다.
- 지도에서 상하좌우로 움직이는 생명체는 동작별 Down·Left·Right·Up 4방향을 기준으로 제작한다. 정면·뒷면·측면을 구별하며 화면 가로/세로 전환과 캐릭터 방향을 혼동하지 않는다. 이동 시 현재 경로 구간, 작업 시 상호작용 대상, 대기 시 마지막 방향을 따른다. 다른 종류의 실제 제작·프레임 수는 해당 후속 PLAN에서 정한다.
- 운반물은 몸체에 그려 넣지 않고 **머리 위에 올리는 별도 자원 Sprite**로 표현한다(사용자 후속 지정, 2026-11-07). [한 번에 한 종류를 운반하는 규칙](../../02-systems/02-logistics/storage-and-transport.md#transport-selection)에 맞춰 자원 표시 슬롯 하나의 그림을 교체한다. 자원 종류별 운반 몸체 프레임을 추가하지 않는다.
- 머리 위 받침 위치는 방향·프레임별 생명체 표현의 기준점으로 관리하며 몸체·자원 PNG는 별도로 제작한다. 운반물의 표시 크기·하단 정렬을 맞추고 기존 상태 표식과 겹치지 않게 한다. 운반물은 몸체의 눌림/좌우 반전을 그대로 물려받지 않고 필요한 위치 움직임만 따라가게 한다.
- 실제 운반 대상과 실물 소유 상태를 확인해 표시한다. 출고 예약·빈손 이동·운반에 사용하지 않는 시작 지급 재고는 머리 위 자원으로 표시하지 않으며, 운반 중 대기·경로 변경·부분 입고 시 남은 실물이 있으면 유지한다. 이는 시각 표현 원칙이며 소유·전달·작업·저장 규칙을 변경하지 않는다.
- 상호작용이 적은 침공형에는 보조형의 몸체·두 점눈 제약을 강제하지 않는다. 역할과 실루엣에 맞춰 팔다리를 포함한 외형을 사용할 수 있으며, 외부 전투 구현·애니메이션 범위를 늘리는 근거는 아니다.
- 사용자 후속 요청으로 PLAN-026의 프로토타입을 Idle·Move·Work 각각 4방향으로 확대했다. 방향당 프레임은 Idle 4·Move 6·Work 6, 총 64프레임·12태그다. 운반은 해당 방향의 Move/Idle과 별도 자원 표시를 합성하고 집기·내려놓기 전용 프레임은 추가하지 않는다. 문서 작성과 제작·게임 적용·테스트 실행은 구분한다.

### 제작량을 늘리는 기준

- 5-2 시설은 우선 각 종류의 정적 외형과 공용 건설 표시를 적용한다. 시설별 별도 건설/파손 단계·장식 변형은 실제 표시 요구가 확인됐을 때 추가한다. 파손을 새 게임 규칙으로 도입하지 않는다.
- 5-3 자원은 HUD/목록과 운반 상태의 읽힘을 우선한다. 수량마다 그림을 추가하거나 실제 소유와 무관한 재고 더미를 만들지 않는다. 지도상 자원이 표시되는 위치·조건은 현재 컨테이너/운반 상태를 따른다.
- 5-5 동작은 5-1의 프로토타입·획득시설을 기준으로 다른 종류에 확장한다. 공통 동작은 재사용하되 의미가 다른 사건을 같은 완료 효과로 표시하지 않는다. 이동 생명체의 4방향 기준을 유지하고 후속 종류의 동작·프레임·속도는 샘플 확인 후 정한다. 프로토타입의 제작 수치를 모든 종류의 공통값으로 강제하지 않는다.
- 침공형은 연구소 안의 배양·대기·방출 표현을 우선한다. 외부 전투 애니메이션이나 전투 맵은 이 로드맵의 범위가 아니다.
- 정적인 문구는 기존 TMP·Localization을 유지하고 번역이 필요한 글자를 그림에 굽지 않는다. 정식 게임명은 [콘셉트의 확인 필요 항목](../../01-direction/01-identity/concept.md)에 따라 로고 제작 전에 확인한다.
- 전환·게임 사건·글자 연출은 기존 [외부 연출 에셋 기준](../../../agents/presentation-effects.md)을 따른다. 이 로드맵은 새 음원 제작·음악·패키지 교체를 포함하지 않는다.
