## 책임 분리 (D-085)

**GameFlow는 한 판의 진행 단계와 전환을 관리하고, 각 시스템은 담당 규칙과 상태를 관리한다.**

| 담당 | 책임 |
| --- | --- |
| GameFlow | 새 게임·이어하기 준비, 플레이·멸망 연출·결과 단계 전환, 진행 정지와 다시 시작 조정 |
| Thing·컴포넌트·Job | 개별 생산·건설·이동·운반 등의 기능과 실행 상태 |
| 공통 시스템 | Map 공간 정보, 자원 예약, 외부 활동과 성과·멸망 게이지 등 여러 개체에 걸친 처리 |
| 저장 기능 | 각 담당 상태와 연결 관계를 수집해 저장·복원 |
| 화면 | 상태 표시, 공통 명령을 통한 조작 전달, 멸망 연출과 결과 표시 |

생산 진행도·재고·예약·멸망 게이지의 원본은 각각 담당 기능에 둔다. GameFlow나 저장 기능이 실행 상태의 소유를 대신하지 않는다. 개별 기능과 공통 시스템의 구조는 [Thing과 정의 데이터](thing-model.md)를 따른다. 표의 행마다 하나의 Manager를 만들거나 공통 시스템을 하나의 클래스로 합치는 결정은 아니다.

## 시작·이어하기·다시 시작

- 새 게임은 확정된 초기 상태의 준비가 끝난 뒤 플레이를 시작한다.
- 이어하기는 저장된 상태와 연결 관계를 복원한 뒤 해당 진행 단계로 재개한다. 무조건 플레이 단계로 전환하지 않는다.
- 다시 시작은 한 판의 상태와 저장을 초기 상태로 바꾸도록 조정한다.

초기 개체·지급 자원은 [최초 제공 범위](../../04-delivery/02-release/scope.md)의 D-071, 저장·이어하기·게임 종료 중 진행 없음은 [플레이 환경](../../04-delivery/01-platform/environment.md)의 D-069를 따른다.

## 멸망과 결과 전환 (D-064)

1. 외부 활동을 담당하는 시스템이 실제 성과를 반영하고 멸망 목표 도달을 알린다.
2. GameFlow가 연구소와 외부 활동의 진행을 멈추고 멸망 연출 단계로 전환한다.
3. 화면에서 간단한 멸망 연출을 진행한다.
4. 연출이 끝나면 GameFlow가 결과 단계로 전환한다.

게임 진행이 멈춘 동안에도 연출과 화면 표시는 진행할 수 있어야 한다. 성과 계산·보고 표시·게이지 누적의 규칙은 [목표와 반복 흐름](../../01-direction/02-experience/core-loop.md), 화면은 [화면과 조작](../../03-player-experience/03-interface/controls.md)을 따른다.

## 일시정지와 공통 조작 (D-033·D-079)

시설 배치·이동·회전 조작 중 연구소 일시정지는 한 판 종료와 구분한다. 시설 조작의 확정·취소만으로 종료된 한 판의 진행을 재개하지 않는다. 일시정지와 재개의 정식 범위는 [시설 배치](../../02-systems/03-space/placement.md)를 따른다.

화면과 하네스는 이 흐름에도 같은 명령 처리·규칙 검사·상태 조회를 사용한다. 화면은 조작을 전달하고 상태를 표시하며 게임 상태 전환은 공통 게임 로직을 거친다.

## 개발 위임과 검증

실제 Manager 클래스·씬 구성·단계 자료형·클래스명·API·전환 통지·초기화 및 복원 절차·호출과 갱신 순서는 승인된 규칙 안에서 개발하면서 정한다(D-059).

GameFlow·파일 저장·복원·재시작·공통 진행 제어는 [PLAN-007](../../../plans/PLAN-007-gameflow-and-persistence.md)에서 구현·검증했다. 목표 도달·연출 완료는 진단 신호로 확인했으며 실제 생산·침공·멸망 연출은 후속 범위다. 선행 기반 완료 기준은 [구현 계획](../02-implementation/roadmap.md), 작업별 구현 범위와 검증 결과는 해당 [PLAN](../../../plans/README.md)에서 관리한다.
