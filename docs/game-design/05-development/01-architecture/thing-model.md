## 구조 원칙 (D-072·D-073·D-084)

시설·생명체·자원 묶음을 공통 **Thing**으로 관리하고, 종류별 공통 정의와 실행 중 개별 상태를 분리한다. 림월드의 Thing 접근을 참고하되 프로토타입의 현재 규칙을 구현하는 범위로 사용한다.

- **정의:** CSV의 게임 값과 주제별 Registry에 등록한 SO의 Unity 에셋 참조를 ID로 결합한 읽기 전용 Data를 공유한다. 초기 로딩에서 전체 Data를 영속 GameDataStore에 준비한다. 사용자 요청을 반영한 PLAN-012에서 구현·검증을 완료했다.
- **실행:** Thing과 실행 컴포넌트는 일반 C# 객체다. Thing은 필요한 기능을 컴포넌트로 조합하며 개별 상태를 가진다.
- **화면:** 논리 객체와 분리하여 연결한다. Unity의 화면용 컴포넌트와 게임 기능의 실행 컴포넌트를 구분한다.
- **공통 실행 경로:** 플레이 화면과 하네스가 같은 명령 처리·규칙 검사·상태 조회를 사용한다.

Thing·Def는 구조를 설명하는 용어이며 정확한 클래스명·상속 계층·엔진 자료형을 고정하지 않는다. 결합 Data는 일반 C# 객체이며 필요한 Unity 에셋 바인딩을 포함한다. 정식 출시용 전체 프레임워크를 요구하지 않는다.

## CSV·SO와 결합 정의 데이터 (D-082·D-084의 저장 위치 변경)

2026-10-28 사용자 요청으로 정의의 일반 값은 CSV, Unity 에셋 참조는 SO, 결합된 실행 정의는 Data로 분리한다. 주제별 Registry SO를 초기화 클래스에 연결하고 정의 ID를 검사한다. SO·Data에는 진행 상태를 담지 않는다. 아래 표의 논리적 정의 범위는 유지하며 상세 계약은 [TECH-009](../../../decisions/TECH-009-csv-data-catalog.md), 구현 상태는 [PLAN-012](../../../plans/PLAN-012-csv-so-data-and-game-data-store.md)를 따른다.

| 정의 범위 | 최소 데이터 | 프로토타입 적용 |
| --- | --- | --- |
| 공통 기반 | 종류를 식별하는 정의 ID, 표시 이름, 필요한 기능과 설정 | 시설·생명체·자원 공통 |
| 자원 정의 | 자원 종류 정보 | 유기물·배양액 2종 |
| 시설 정의 | 점유 크기, 고정 상호작용 위치의 상대 좌표, 건설 재료·수량·필요 작업량, 적용할 생산 규칙, 저장 기능의 용량 | 시설 4종에 필요한 설정만 적용 |
| 생명체 정의 | 수행 가능한 기능, 이동·운반에 필요한 기본 설정 | 시작용 프로토타입·보급형·침공형 3종 |
| 생산 규칙 | 투입 재료, 결과 종류·수량, 기준 작업시간 | 획득 1개·가공 1개·배양 2개의 규칙 |

생산 규칙은 시설 정의와 연결한다. 같은 규칙의 수치를 여러 곳에서 독립 관리하지 않는다. 표는 논리적인 데이터 범위이며 생산 규칙마다 별도 SO 클래스·파일을 만드는 결정이나 전체 SO 에셋 수의 확정이 아니다.

콘텐츠 목록은 [최초 제공 범위](../../04-delivery/02-release/scope.md), 승인된 레시피·작업시간·20%와 100% 속도 조건·회차 완료 조건은 [생산시설](../../02-systems/01-production/facilities.md)을 따른다. 기초 자원 획득에는 생명체의 수집 작업이 필요하며, 작업자 부재 시 20% 생산은 가공·배양에만 적용한다. 시작용 프로토타입 모델의 추가 배양은 포함하지 않는다.

## Thing과 컴포넌트의 실행 상태 (D-082·D-083)

Thing은 설치된 시설 각각, 생명체 각각, 같은 종류의 자원을 수량과 함께 표현한 묶음을 관리한다. 자원 묶음의 수량 제한·분할·합치기 방식은 개발에서 정한다.

| 담당 | 관리할 상태와 관계 |
| --- | --- |
| Thing 공통 | 개별 고유 ID, 참조 정의, 최초 생성 순서, 존재·배치 상태, 소속 관계, 소유 컴포넌트 |
| 공간 상태 | Map 배치 시 위치·회전. 이를 바탕으로 공통 Map이 점유 칸과 실제 상호작용 위치를 계산한다. |
| 시설의 건설·생산 기능 | 건설 진행과 재료 상태, 현재 생산 회차, 진행도, 재료 소비 여부, 완료품의 실제 입고 대기 |
| 배양시설 선택 | 현재 선택한 배양 대상과 이미 시작된 회차의 대상 |
| 저장 기능 | 저장소의 허용 자원 목록과 보유한 자원 묶음의 연결 |
| 생명체·Job | 배정 시설, 개체별 작업 우선순위, 현재 행동과 대상·진행, 운반 자원 연결, 침공형의 방출 대기·외부 활동 |
| 자원 묶음 | 현재 수량과 정확히 하나의 보관처에 속하는 관계 |

표의 각 행을 별도 컴포넌트 클래스로 만들거나 모든 상태를 Thing 본체에 모으는 결정은 아니다. 출고·입고 예약, Map, 전체 작업 우선순위 설정, 멸망 게이지, 전과 보고와 GameFlow는 각 담당 시스템의 상태로 관리한다. 초기 개체·지급 자원은 별도 시작 설정으로 둔다. 특정 Manager 목록이나 별도 SO 파일을 요구하지 않는다.

### 소유와 연결

1. Thing 생성 시 정의의 기능 설정에 따라 필요한 컴포넌트를 구성한다.
2. 각 컴포넌트는 소유 Thing과 연결되어 정의·위치 등 공통 정보를 확인하고 자기 기능과 상태를 관리한다. 같은 종류의 Thing도 실행 상태는 서로 독립적이다.
3. 필요한 기능은 소유 컴포넌트를 조회해 사용한다. 다른 기능의 상태 변경은 해당 상태를 담당하는 기능에 요청하며 내부 상태를 직접 고쳐 책임을 섞지 않는다.
4. 배정 시설·운반 대상·보관처 등 저장·복원할 연결 대상은 고유 ID로 식별한다. 실행 중 객체 참조와 ID 조회의 사용 방식은 개발에서 정한다.

정의 ID는 같은 종류를 연결하고 개별 ID는 각각의 Thing을 식별한다. 최초 생성 순서는 개별 ID와 별개 의미이며 시설 이동과 저장·복원 후에도 유지한다(D-020·D-078).

Thing의 소속과 자원 묶음의 보관처는 하나의 원본 관계로 관리한다. 재고·운반물은 해당 묶음을 참조하며 총재고와 남은 용량은 수량·예약을 바탕으로 계산한다. 배양 선택과 진행 중인 회차의 대상도 구분하여, 선택 변경이 이미 시작된 회차를 바꾸지 않도록 한다.

## Job과 시설 생산 상태 (D-074)

| 담당 | 책임 |
| --- | --- |
| 생명체의 Job | 현재 개체의 이동·운반·건설·시설 작업 등 행동을 관리한다. 작업별 Job 분할과 단계 구성은 개발에서 정한다. |
| 시설의 생산 컴포넌트 | 생산 회차의 진행도·재료 소비·완료품 입고 대기를 관리한다. 작업자가 바뀌거나 Job이 전환되어도 기존 규칙에 따라 시설 상태를 보존한다. |

배정 관계와 현재 Job을 구분한다. 배정 개체가 이동·운반 중인 상태는 고정 상호작용 위치에서 실제 작업하는 상태가 아니다. 생산 속도·공급·정지 조건은 [생산시설](../../02-systems/01-production/facilities.md), 우선순위·정상 작업 유지·작업 전환은 [보조형 모델](../../02-systems/05-creatures/support-models.md)을 따른다.

운반자가 완료품을 집어 들어 시설에 실물이 남지 않아도 저장소에 전량 실제 입고하기 전에는 다음 생산 회차를 시작하지 않는다. 이 대기 상태는 시설 생산 컴포넌트가 관리하며, 운반·입고 결과를 연결하는 방법은 개발에서 정한다.

## 실물 자원과 예약 (D-075)

**실물 자원은 한 보관처에만 속하고 출고·입고 예약은 별도로 관리한다.** 보관처는 저장소·운반 개체·시설 등 현재 자원이 속한 논리적 위치이며 고정 클래스명이 아니다.

| 구분 | 책임 |
| --- | --- |
| 실물 자원 | 수량과 현재 소속. 수령 전에는 공급처, 수령 후에는 운반 개체, 입고 후에는 목적지에 속한다. |
| 출고 예약 | 해당 운반이 가져갈 수량을 확보하고 실제 수령 시 반출로 전환한다. |
| 입고 예약 | 해당 운반의 수용량을 확보하고 실제 입고 시 입고로 전환한다. |

예약은 다른 작업의 가용 수량·여유 공간 계산에 반영한다. 같은 실물을 여러 보관처에서 중복 계산하거나 입고한 수량을 예약으로도 중복 계산하지 않는다. 예약 유지·해제·재평가와 운반 예외는 [저장과 운반](../../02-systems/02-logistics/storage-and-transport.md)의 D-021·D-022·D-026을 따른다.

시설은 현재 회차의 준비 재료와 미운반 완료품만 보관한다. 소비된 실물과 생산 컴포넌트의 소비 완료 상태를 구분한다. 완료품의 실제 입고 대기는 실물의 현재 소속과 별개인 생산 회차 상태다. 여러 회차 비축·바닥 투하를 추가하지 않는다.

## 공통 Map과 존재 상태 (D-076·D-077)

공통 Map은 연구소 격자의 건설 영역·시설 점유 칸·고정 상호작용 위치를 관리하며, **배치 검사와 경로 탐색이 같은 공간 정보**를 참조한다. 문서 탐색용 README MAP과 구분한다.

- Thing의 위치·회전과 공간 정보를 연결한다. 시설 이동·회전 확정 시 점유 칸과 상호작용 위치를 갱신하고 기존 경로 재계산·운반 예외를 적용한다.
- 시설 겹침·영역 밖 배치는 금지하고 통로 차단은 허용한다. 생명체끼리는 겹쳐 통과하며 시설은 이동을 막는다. 배치 가능과 접근 가능은 구분한다.
- 연구소 Map 배치 여부와 Thing의 존재는 별개다. 보관 자원이나 외부 활동 개체에 연구소 좌표를 강제로 부여하지 않는다.
- 방출 대기 침공형은 Map에 배치된다. 방출하면 Map에서 제외하되 개체 정보를 유지하고 외부 활동 상태로 전환한다.
- 외부 활동은 세계 멸망까지 성과를 쌓으며, 게이지 목표 도달 시 멈춘다. 저장·이어하기에 외부 활동 상태를 포함하고 게임 종료 중에는 진행하지 않는다.

정식 공간 규칙은 [시설 배치](../../02-systems/03-space/placement.md), 경로·운반 예외는 [저장과 운반](../../02-systems/02-logistics/storage-and-transport.md), 외부 활동은 [목표와 반복 흐름](../../01-direction/02-experience/core-loop.md)을 따른다. Map이 생산·Job·예약·저장 등 모든 상태를 직접 관리하지 않는다. 별도 외부 격자 지도·전투 시스템·귀환·수명·전투 손실을 추가하지 않는다.

## 식별자와 저장·복원 (D-078)

각 Thing에 저장 후에도 유지되는 고유 식별자를 두고, 개별 상태와 연결 관계를 함께 저장·복원한다.

- 위치·회전·자원 수량·생산 진행도·재료 소비·입고 대기·외부 활동 상태와 배정·운반 대상·보관처·예약 관계가 기존 규칙대로 이어져야 한다.
- 이미 소비한 재료를 다시 소비하거나 자원을 중복 생성하지 않는다.
- 운반자가 완료품을 들고 있는 상태를 실제 입고 완료로 처리하지 않는다.
- Map 밖 침공형의 개체 정보와 외부 활동 상태, 최초 생성 순서를 보존한다.

기기 내 1슬롯 자동 저장·마지막 상태 이어하기·종료 중 진행 없음·다시 시작 시 초기화는 [플레이 환경](../../04-delivery/01-platform/environment.md)을 따른다. 저장 기능은 담당 상태와 연결을 수집·복원하며 실행 상태의 소유를 대신하지 않는다. 진행 단계 전환은 [GameFlow](game-flow.md)에서 관리한다.

## 화면과 하네스의 공통 사용 (D-079·D-084)

게임 규칙과 실행 상태는 화면과 분리된 게임 로직에서 관리한다. 화면은 논리 상태를 바탕으로 위치·외형·선택 등을 표시한다. 화면 표현의 제거는 Thing의 소멸을 뜻하지 않는다.

플레이 화면과 하네스는 같은 명령 처리·규칙 검사·상태 조회를 사용한다. 배치·작업 배정·침공형 방출 등 같은 조작에는 같은 규칙 검사를 적용하고 하네스도 실제 게임 상태를 관찰한다. 화면 분리를 이유로 조작 중 연구소 일시정지·접근 불가 생산 정지·게임 종료 중 진행 없음 등의 규칙을 바꾸지 않는다.

## 개발에서 구체화할 범위 (D-059)

정확한 클래스명·상속과 컴포넌트 분할, 필드·자료구조·SO 에셋 분할, 생성·조회·갱신 순서, Toil 도입과 작업 단계, 컨테이너·예약 관리 배치, 자원 묶음 분할·합치기와 ID 처리, 경로 탐색 알고리즘, 외부 활동 갱신, 식별자·저장 형식과 복원 절차, 화면용 Unity 구성, API·테스트 도구·검증 구성은 개발하면서 정한다. 비용·크기·용량·이동 속도 등 위임된 초기값도 승인 규칙 안에서 정한다.

이 문서는 현재 구조의 기준이다. 정의·Thing 최소 기반은 [PLAN-003](../../../plans/PLAN-003-thing-foundation.md), 공간·공통 조작·최소 화면은 [PLAN-004](../../../plans/PLAN-004-map-and-commands.md), 기존 상태·관계의 저장·복원은 [PLAN-007](../../../plans/PLAN-007-gameflow-and-persistence.md)에서 검증했다. 위 모든 게임 기능을 구현했다는 뜻은 아니다. 선행 기반 범위·완료 기준은 [구현 계획](../02-implementation/roadmap.md), 작업·검증 결과는 [PLAN](../../../plans/README.md), 주요 구현 선택은 [기술 결정](../../../decisions/README.md)에서 관리한다.
