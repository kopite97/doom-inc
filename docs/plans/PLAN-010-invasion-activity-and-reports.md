# PLAN-010 침공형 방출·외부 활동·성과 누적·전과 보고

## 목표

PLAN-009에서 배양해 연구소에 대기 중인 침공형을 플레이어가 방출하고, Map 밖에서도 같은 개체가 활동하며 실제 성과로 멸망 게이지를 채우는 흐름을 구현한다.
전과 보고의 표시·생략·열람과 성과 누적을 분리하고, 외부 활동·보고·연구소의 동시 진행 및 중간 저장·이어하기를 PC 가로 화면과 공통 하네스로 확인한다.
로드맵 3단계의 첫 작업 단위다. 목표 도달에 따른 공통 진행 정지와 기존 GameFlow 전환 연결까지 검증하며, 멸망 연출·결과 화면을 포함한 3단계 전체 완료는 후속 PLAN에서 판정한다.

## 범위

- 포함: 방출 명령 시점에 연구소에서 대기 중인 침공형 전원의 일괄 방출, Map 배치 해제와 개체 ID·정의·생성 순서 보존.
- 포함: 침공형의 대기/외부 활동 상태, 외부 활동 갱신, 실제 성과와 멸망 게이지, 목표 도달 통지. 개체·공통 상태와 Manager 책임 분리.
- 포함: 초반 상세 보고와 후반 큰 공적 중심의 보고, 보고 표시와 독립적인 성과 반영, PC 가로 화면의 방출·게이지·개체 수·펼쳐 보는 보고.
- 포함: 연구소 편집 정지와 외부 진행의 구분, 앱 정지·종료·이어하기, 목표 도달 시 연구소/외부 활동 정지와 기존 `Destruction` 단계 연결.
- 포함: 새 상태의 저장·복원·초기화, 기존 저장 호환, 잘못된 관계 거부와 정상 파일 보존, 생산·배양·물류·배정·GameFlow 회귀.
- 제외: 멸망 시각 연출·연출 완료에 따른 실제 결과 화면·결과 화면에서 다시 시작까지의 완결. 기존 재시작 명령에 새 상태가 초기화되는 검증은 포함한다.
- 제외: 여러 세계·귀환·수명·전투 손실·전투 지도·개체 레벨/경험치·환생·영구 보너스, 신규 자원·시설·모델·해금·방출 비용/쿨다운/선별 방출 규칙.
- 제외: 세로 화면·Android 빌드/실기기·최종 성능 판정·정식 아트 제작. 기존 콘텐츠 2자원·4시설 종류·3생명체 모델을 유지한다.

2026-10-28 후보 작성 후 사용자가 검토의 두 보완 사항 반영과 PLAN 실행을 명시적으로 승인했다. 보완 사항을 포함한 범위로 `active` 전환한다.
수치·구체적인 클래스 분할·보고 문구와 주기는 D-059의 개발 위임 안에서 실행 시 정한다. 새로운 핵심 게임 규칙을 PLAN이나 테스트 기대값으로 추가하지 않는다.

## 구현 순서와 주요 경계

### 1. 책임·상태·정의

침공형의 대기/외부 활동과 활동 회차의 상태는 해당 Thing의 컴포넌트에, 한 세계의 성과·게이지와 보고 기록은 세션에 속한 담당 상태에 둔다. SO에는 공통 설정만 둔다.
외부 활동 조율은 `InvasionManager` 같은 기능별 일반 C# Manager로, 보고는 성과의 소비자/표현 자료로 구성하는 방향을 검토한다. 정확한 타입·필드·분할은 실행 시 기술 결정에 기록한다.
GameFlow는 진행 허용·목표 도달 전환·세션 교체, Persistence는 수집·검사·복원을 맡는다. 화면·저장 객체에 성과 원본이나 별도 게임 시계를 만들지 않는다.
새 C#은 `Assets/Scripts/`의 역할 → 기능 구조를 따르며 필요할 때만 기능 폴더를 추가한다. 기존 Manager 명명·어셈블리 경계·GUID·정의 ID를 유지한다.

### 2. 방출 명령

명령 실행 시점의 Map 내 대기 침공형을 확정하고 그 전원을 한 번에 외부 활동으로 전환한다. 보조형·시설·자원·진행 중 배양 회차·이미 외부에 있는 개체는 대상이 아니다.
Map에서 제외해도 Registry의 동일 Thing과 ID·정의·최초 생성 순서를 유지한다. 방출 클릭 자체를 활동 성과로 계산하거나 방출할 때 게이지를 즉시 지급하지 않는다.
대기 0개·반복 클릭·진행 단계 부적합·유효하지 않은 상태를 명령 경계에서 처리하며, 거부된 명령은 개체 일부만 바꾸거나 성과를 만들지 않는다. 0개 처리의 반환값·버튼 상태는 개발에서 정하되 효과는 없어야 한다.
시설 편집 중 방출 허용 여부와 `Unplace`의 편집 제한을 공통 명령에서 일치시킨다. UI와 하네스가 달라지거나 편집 중인 배치를 임의 확정하지 않게 하며, 선택한 처리 방식을 기록·검증한다.
방출 이후 배양된 침공형은 다음 방출 전까지 대기한다. 출입구까지 이동·통로 접근·외부 지도 같은 새 방출 조건을 추가하지 않는다.

### 3. 외부 활동·성과·목표 도달

방출 개체는 플레이 중 공통 시간 입력에 따라 계속 활동한다. 활동 결과를 정확히 한 번 반영하고, 같은 결과에서 보고 후보를 생성해도 성과를 다시 반영하지 않는다.
활동 간격·성과 산식·목표량은 D-059 범위에서 정하고 한 곳에서 설정한다. 난수는 필수가 아니며 사용한다면 재현·저장 상태를 함께 설계한다. 방출 수에 단순 비례하는 공식을 사전 확정 규칙으로 취급하지 않는다.
시설 건설 후보·이동·회전 편집은 연구소만 멈추고 기존 GameFlow의 외부 진행 허용을 유지한다. 앱 정지·종료에서는 양쪽을 멈추며, 재개/복원 때 벽시계 경과분을 보충하지 않는다.
현재 GameFlow는 연구소에 전체 delta를 넘긴 뒤 외부 알림을 보낸다. 목표를 넘는 큰 delta에서도 목표 도달 후 남은 시간으로 연구소나 외부를 추가 진행하지 않도록 공통 갱신 순서·시간 분할을 점검하고 회귀 검증한다.
게이지 목표에 도달하면 담당 로직이 알리고 GameFlow가 기존 `ReachGoal` 경계로 `Destruction` 단계에 한 번 전환한다. 이후 진행·방출은 멈추고 편집 취소·보고 열람·저장 재시도가 진행을 되살리지 않아야 한다.
`ReachGoal()`은 단계 전환과 동시에 저장하므로 마지막 활동의 진행·회차·성과·보고와 처리 표식을 모두 확정한 뒤 호출한다. 그 자동 저장 파일을 추가 수동 저장이나 시간 진행 없이 새 객체로 복원해 마지막 성과/보고의 누락·중복이 없는지 검사한다.

### 4. 전과 보고와 최소 화면

초반에는 활동을 상세히, 후반에는 큰 공적을 중심으로 보여준다. 단계 전환 기준·공적 분류·보고 주기·문구·보관 수는 D-059 범위에서 정하고 검증 가능한 설정으로 기록한다.
성과 반영은 보고 필터·표시 여부·읽음 여부보다 독립된 실행 경로를 가진다. 후반에 작은 활동을 생략하거나 오래된 보고를 정리해도 해당 성과는 유지한다.
보고는 필요한 때 펼쳐 확인하며 반복 열람이 성과 재계산을 호출하지 않는다. 조회를 위한 기록과 이미 처리한 활동을 구별해 이어하기 뒤 중복 보고/중복 성과를 막는다.
기존 PC 가로 화면에 대기/외부 침공형 수, 방출 버튼, 현재 게이지, 접기/펼치기 보고와 목표 도달 정지 상태를 표시한다. 선택한 개체가 방출될 때 연구소 좌표나 낡은 선택 표시가 남지 않게 한다.
멸망 시각 연출과 실제 결과 화면은 후속 범위다. 이번에는 목표 도달 상태와 정지를 확인할 수 있게 표시하며, 결과 연출 미구현을 이유로 목표 도달 후 계속 생산하는 임시 규칙을 두지 않는다.

### 5. 저장·복원·초기화

외부 개체 ID·상태·활동 진행, 성과·목표량·목표 도달 상태, 보고의 재개에 필요한 이력/순번/누적 시간을 기존 연구소 상태와 함께 저장한다. 화면의 열림/선택 같은 일시 상태와 영속 상태는 구분해 기록한다.
새 저장 버전과 이관은 구현 시 확정한다. 정상 버전 3 저장은 기존 배양 침공형을 연구소 대기로 보존하고 외부 활동/성과가 없는 초기 상태로 이관한다. 버전 2 호환·진단용 버전 1 분리와 저장된 단계 보존을 유지한다.
복원은 새 객체 그래프를 검증한 뒤 공개한다. Map 안/밖 상태 불일치, 외부 목록의 중복/없는 ID, 보조형의 외부 상태, 잘못된 활동 진행/성과/보고 관계, 미지원 버전은 거부하고 정상 파일·현재 세션을 보존한다.
보고가 생략될 수 있으므로 누적 성과를 현재 보관 중인 보고의 합으로 재구성하지 않는다. 구버전의 단계·새 상태 기본값 간 호환 방침도 명시해 기존 저장을 임의 Playing으로 바꾸지 않는다.
새 저장 형식은 단계·게이지·목표 도달 상태를 함께 검증한다. `Playing`인데 목표 도달 상태이거나 정당한 이관 근거 없이 `Destruction`/`Results`인데 목표 미달인 조합을 거부한다. 성과 데이터가 없는 정상 구버전의 종료 단계는 별도 이관 규칙으로 보존하며 성과·보고를 임의 생성하지 않는다. 이관 후 재저장·재복원도 같은 규칙을 만족해야 한다.
기존 재시작 명령은 새 개체 그래프·외부 상태·성과·보고·시간 누적과 슬롯을 초기화한다. 파일 교체 실패 시 기존 세션을 유지하는 계약을 지키며, 목표 도달 직후 저장 실패가 진행을 재개시키지 않게 한다.
