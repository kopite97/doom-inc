# PLAN-013 가로·세로 UI와 모바일 입력 대응

## 목표

같은 게임 세션을 가로·세로에서 조작할 수 있도록 화면을 재배치하고, PC 마우스와 모바일 터치를 기존 공통 명령에 연결한다. 화면 방향을 바꿔도 한 판·배치 초안·생산/물류 상태가 보존되며, 연구소부터 로딩 오류·멸망 연출·결과·재시작까지 필요한 조작에 접근할 수 있어야 한다.

로드맵 4단계의 첫 작업이다. 이 PLAN은 화면·입력 구현과 그 직접 검증을 완료하며, 병목 개선·장시간 반복·종합 성능을 포함한 프로토타입 최종 판정은 후속 작업으로 남긴다.

## 범위

- 포함: 실제 플레이 씬의 가로·세로 레이아웃, 안전 영역, UI 배율·스크롤·긴 문구, 연구소 확대/축소·화면 이동, 선택·배치·회전·확정·취소와 모든 기존 운영 조작의 터치 연결.
- 포함: 로딩/오류/재시도, 멸망 연출·결과·저장 실패·재시작 화면, 방향 전환·포커스/백그라운드 복귀 중 입력 정리와 기존 상태 보존.
- 포함: 화면·입력 책임 분리, 실제 씬·Editor 생성 도구·입력 에셋/어셈블리 연결, 입력 경유 자동 검사, 기존 Edit/Play 회귀, Android 검증용 APK와 실제 기기 1종의 화면·입력 확인.
- 제외: 신규 콘텐츠·게임 규칙·재밸런싱·저장 형식 변경, 정식 아트/연출 고도화·전체 현지화, 진단 씬 전체 UI 교체, 범용 UI 프레임워크·외부 플러그인 도입, 엔진/패키지 업그레이드.
- 제외: 대표 병목 개선의 종합 판정, 장시간/다기종 성능 검증, D-070 전체 완료 선언, Google Sheets/API 연결, 스토어 배포·서명 운영. 단, 이번 화면·입력 변경의 크래시·중복 명령·입력 불능은 이 PLAN 안에서 해결한다.
- 작업 요청·위임 근거: 2026-10-28 사용자가 가로·세로 UI와 모바일 입력 대응을 위한 PLAN-013 작성을 요청했다. 두 검토 보완 사항의 반영과 PLAN-013 실행을 명시적으로 승인했다.

## 화면과 입력 설계 계약

### 구현 경계와 기술 선택

- 기본 검토안은 설치된 uGUI와 Input System으로 실제 플레이 UI/입력을 구성하고 기존 일반 C# 게임 로직을 유지하는 것이다. 실행 첫 단계에서 선택·배치 프리뷰·스크롤을 포함한 작은 가로/세로 경로로 확인하고, IMGUI 유지/부분 교체 대안과 비교해 하나의 방식을 기술 결정에 기록한 뒤 전체 화면에 적용한다.
- 방식 선택의 기준은 안전 영역·UI 배율·터치 스크롤·다중 포인터 식별·UI/Map 입력 차단·실제 입력 자동 검사 가능 여부다. 같은 조작을 처리하는 활성 입력 경로를 둘 이상 남기지 않는다. 기존 패키지 안에서 해결하며 새 프레임워크 도입으로 확대하지 않는다.
- 화면 배치, 화면좌표→Map 변환, 제스처 판정은 Presentation 책임이다. 게임 명령은 기존 LaboratoryView의 조작 경계와 LaboratoryCommands/GameFlow/Map 명령을 거친다. 입력 코드에서 건설 비용·배정 조건·저장/재시작 규칙을 복제하지 않는다.
- 새 표현 코드·프리팹은 기존 Laboratory 기능 및 프로젝트의 역할별 분류에 배치한다. 실제 경로·기존 partial의 이동/교체·어셈블리 참조·GUID 보존 목록을 실행 시 기록한다. 재배치만으로 View·Controller·GameDataStore를 새로 만들지 않는다.
- UI 배율·제스처 임계치는 표현 설정으로 관리하며 게임 밸런스 CSV/호환성 해시를 바꾸지 않는다. 선택·패널 상태·줌·미확정 터치는 새 저장 스키마로 추가하지 않는다.

### 동일 기능의 가로·세로 배치

- 가로는 연구소와 측면 패널, 세로는 연구소와 하단/접을 수 있는 패널을 기본안으로 둔다. 실제 분기는 화면 크기와 안전 영역을 사용하고, 세로 화면을 단순 축소하여 작은 가로 UI로 만들지 않는다.
- 같은 칸에 겹친 생명체도 각각 선택할 수 있도록 기존 전체 개체 목록 또는 동등한 후보 선택 경로를 유지한다. 두 방향에서 서로 다른 개체의 배정·우선순위를 조작할 수 있어야 한다.
- 자원·개체 수·멸망 게이지와 건설·방출, 선택 패널의 작업 상태·대기 이유, 이동·회전·작업 배정/해제·작업 우선순위·배양 대상·저장 허용 자원, 전과 보고를 두 방향에서 모두 사용할 수 있게 한다.
- 배치 중 회전·확정·취소와 유효/불가 피드백은 긴 목록을 끝까지 스크롤해야만 보이는 위치에 두지 않는다. 보조 정보·긴 목록은 스크롤/접기로 처리하고 글자·버튼·프리뷰의 겹침을 방지한다.
- 확대·축소와 화면 이동 후에도 Map 전체 칸에 접근할 수 있어야 한다. 줌 한계·화면 경계 제한·초기 맞춤을 정하고, 작은 칸을 탭하기 어려우면 확대하여 선택할 수 있게 한다. PC에서는 마우스로 같은 기능을 사용할 수 있어야 한다.
- 안전 영역·기준 UI 배율·최소 조작 크기·줄바꿈 규칙을 한곳에서 관리한다. 실행 시 논리 단위와 검증 해상도를 기록하고, 긴 이름·보고·오류에서도 필수 조작을 가리지 않도록 한다.
- 로딩·취득 실패·저장 복원 실패는 각각의 원인을 유지하고, 재시도/명시적 새 게임 경로를 양방향으로 제공한다. Ready 전에는 연구소 조작을 노출하지 않는다. 종료 화면에서는 종료 단계에 허용된 조작만 제공한다.

### 모바일 제스처와 명령 전달

| 상황 | 의도한 처리 | 막아야 할 부작용 |
| --- | --- | --- |
| Map 한 손가락 탭 | 개체/시설 선택 또는 배치 후보 위치 지정 | 누른 순간 건설 확정, UI 버튼과 중복 실행 |
| Map 한 손가락 드래그 | 화면 이동, 이동 임계치 이후 탭 후보 취소 | 손을 뗄 때 선택/배치 명령 실행 |
| Map 두 손가락 조작 | 핀치 확대/축소, 시작 시 단일 탭 후보 취소 | 남은 한 손가락이 새 탭으로 해석됨 |
| 패널 탭·스크롤 | 버튼 또는 목록 조작만 처리 | 뒤쪽 Map 선택·이동·확대/배치로 전달됨 |
| 배치 도구 | 화면 버튼으로 90도 회전·명시적 확정·취소 | 키보드 없이는 조작 불가, 같은 입력의 두 번 확정 |
| 방향 전환·앱 정지·터치 취소 | 진행 중 포인터/제스처를 해제, 새 화면에서 새 입력 대기 | 이전 좌표의 release/클릭이 뒤늦게 명령 실행 |

- UI/Map 중 포인터가 시작한 영역이 해당 제스처를 소유한다. 영역을 가로질러도 다른 영역의 탭으로 바꾸지 않는다. UI와 Map에 걸친 다중 터치는 Map 제스처에서 제외하고, 손가락이 모두 해제된 뒤 다시 판정한다.
- 터치 ID를 추적하고 마우스 에뮬레이션과 원래 터치가 같은 명령을 중복 실행하지 않게 한다. 패널 닫기·확정 버튼을 누른 뒤 같은 입력이 새로 드러난 Map에 전달되지 않도록 한다.
- 화면의 미리보기와 hit test는 같은 좌표 변환을 사용한다. 안전 영역·스크롤·줌·화면 이동·회전 후 좌표가 바뀌어도 같은 Map 칸을 가리켜야 한다.
- GameFlow 단계 변경·세션 교체 시 오래된 입력과 선택 ID를 무효화한다. 결과 재시작은 기존 종료 요청 검사를 유지하고, 연속 탭·이전 화면 콜백으로 새 판을 다시 초기화하지 않는다.

### 방향 전환과 게임 상태

- 방향 전환은 표현 재배치다. GameDataStore·카탈로그·Controller·현재 세션의 동일성을 유지하며 자동 신규 시작/복원·저장 파일 교체를 유발하지 않는다.
- 유효한 선택 ID, 패널/전과 보고 열림, 건설/이동 초안의 종류·위치·회전·검사 결과를 유지한다. 패널 스크롤·Map 중심/줌은 가능한 범위에서 유지하고 바뀐 화면 경계로 제한한다. 진행 중 포인터만 취소하며 편집 자체를 자동 확정/취소하지 않는다.
- 연구소 편집 중 정지·확정/취소 후 재개, 외부 활동의 기존 진행, 앱 pause/focus 정책을 그대로 사용한다. 방향 전환만으로 새 게임 정지 규칙을 추가하거나 elapsed time을 보상하지 않는다.
- 회전 직전/직후 상태 비교에서는 정상 시간 진행을 분리한다. 제어한 시간에서 회전만 적용한 검사는 상태가 같아야 하고, 실제 진행 검사는 공통 시간 경로에 따른 변화만 허용한다.
- 멸망 연출 중 회전해도 기존 표현 진행량과 종료 요청을 유지하며 연출을 처음부터 다시 만들지 않는다. 결과에서도 통계·단계·실패 메시지를 유지한다. 목표 도달/실제 세션 교체로 인한 기존 초안 취소·선택 정리는 방향 전환 보존보다 우선한다.
