# PLAN-026 아트 5-1 스타일·크기 샘플과 연구소 적용

## 목표

[아트 로드맵 5-1](../game-design/05-development/02-implementation/art-roadmap.md)의 바닥·획득시설·프로토타입 보조형·유기물·건설 아이콘 **5개 분류, 총 8개 샘플**을 실제 연구소 화면에 연결하고, 다음 제작에 사용할 스타일·상대 크기·표시 규격을 사용자와 확인한다. 바닥은 기본 1개와 변형 3개, 나머지 4개 분류는 각 1종이다. 사용자 추가 요청으로 획득시설 r003의 상태별 12프레임·총 36프레임과 프로토타입 보조형의 대기·이동·공통 작업 애니메이션을 포함한다. 보조형은 방향당 16프레임 × 상하좌우 4방향, 총 64프레임으로 명세하며 샘플 종류와 프레임 수를 구분한다.

주목적은 샘플 아트의 적용·검수이므로 `type: art`다. 샘플을 표시하는 데 필요한 최소 표현 코드 보완을 포함하되, 정식 샘플 미수령·미적용·사용자 시각 확인 대기가 남으면 이 PLAN과 5-1을 완료로 표시하지 않는다. 임의(Temp) 그림은 연결 준비용이며 전체 정식 리소스의 작업 완료나 테스트 시작 조건을 대신하지 않는다.

## 범위

- 포함: 5개 분류·8개 샘플의 명세·수령·임포트·참조 연결, 획득시설과 프로토타입 보조형의 상태별 재생·머리 위 운반 표시, 나머지 정적 샘플, 화면 비교·기술 검증·사용자 시각 확인, 후속 제작 기준·요청 기록 정리. 애니메이션 명세·제작·수령과 Unity 재생 구현의 실행 상태는 구분한다.
- 포함할 코드: 기존 uGUI 지도에서 바닥 변형 선택·획득시설·프로토타입을 표시하는 최소 연결, 실제 유기물 상태의 시각 표시, 샘플 참조 및 생성 도구의 참조 보존, 표시 객체의 생성·갱신·정리. 기존 입력·좌표·게임 명령 경로를 사용한다.
- 기존 UI 요청 중 `PLAN-014-SPR-006` 건설 아이콘 1종을 이 art PLAN의 적용 대상으로 삼는다. 나머지 15종은 기존 요청 상태를 유지한다. 새 요청으로 건설 아이콘을 중복 등록하지 않는다.
- 제외: 로드맵 5-2~7 전체 실행, 나머지 시설/생명체/자원, 전체 UI 스킨, 획득시설 r003·프로토타입 보조형 외의 애니메이션 및 새 VFX·음원, 타이틀·로고·세계 그림, 새 게임 규칙·밸런스·저장 형식, 엔진/패키지 변경, 범용 렌더링 체계 구축. 보급형·침공형 애니메이션은 이번 추가 대상이 아니다.
- PLAN-025의 큰 글씨 안내 잘림·GC 최적화 후보는 보류한 후속 범위로 유지한다. 샘플 적용 때문에 새로 생긴 가독성·입력·수명 문제는 이 PLAN에서 처리한다.
- Android APK/콘텐츠·Player 스크립트 컴파일·IL2CPP 빌드·기기 설치는 기본 검증과 완료 조건에서 제외한다. 이 샘플 적용본의 빌드 승인은 아직 없으며, PLAN-025의 승인이나 과거 기기 결과를 새 적용본에 전용하지 않는다.
- 최초 요청 근거: 2026-11-07 사용자가 아트 로드맵 5-1을 진행할 수 있도록 PLAN-026 작성을 요청하고 당시에는 실행하지 않은 `proposed` 상태 유지를 명시했다.
- 보완 근거: 같은 날 사용자가 바닥 1장의 반복감을 줄이도록 디테일이 다른 여러 장을 원했다. 바닥 4장 구성·혼합 비율은 이 요청에 따른 설계 제안이며 PLAN 활성화나 제작 착수 승인이 아니다.
- 활성화 근거: 2026-11-07 사용자가 “일단 PLAN을 활성화해줘. 아트 작업을 하면서 궁금한게 있으면 다시 물어볼게.”라고 명시했다. 이번 작업은 상태 전환·문서 동기화이며, 사용자 아트 제작 준비·제공본 대기 단계로 둔다. 구현·임포트·테스트·빌드를 함께 시작하지 않는다.
- 바닥 제작 위임: 2026-11-07 사용자가 참고 이미지를 제공하고 활성 PLAN을 바탕으로 바닥을 생성하되 Art PLAN을 먼저 작성하도록 명시했다. [Art PLAN-001](../../../Art/docs/plans/PLAN-001-laboratory-floor.md)에서 바닥 4장만 제작·검수 제출한다. 다른 샘플과 Unity 구현·게임 적용의 실행 범위는 확대하지 않는다.
- 시설 제작 위임: 같은 날 사용자가 [Art PLAN-002](../../../Art/docs/plans/PLAN-002-gathering-facility.md)의 활성화와 참고 이미지에 따른 기초 획득시설 제작을 명시적으로 요청했다. `PLAN-026-SPR-002`로 128×128 정적 r001을 제작·수령했으며, 상세 파일·사용자 확인·미적용 상태는 [요청 README](../../UnityProject/Assets/Sprites/Require/PLAN-026/README.md)에 기록한다. 이번 위임에 Unity 게임 적용·테스트를 포함하지 않는다.
- 시설 애니메이션 수정 위임: 2026-11-07 사용자가 상태별 아이콘·Working/Complete 점멸 제작을 요청했다. r002는 에이전트가 합계 12프레임으로 잘못 해석해 제출했다. 이후 사용자가 상태마다 12프레임으로 정정하여 r003의 36프레임·768×768 시트를 제작·수령했다. 이번 제작에 Unity 슬라이싱·재생 구현·게임 테스트는 포함하지 않는다. 이전 제출본은 보존한다.
- 바닥 적용 승인: 2026-11-07 사용자가 r003 바닥 시트를 64×64로 슬라이싱하고 네 타일을 섞어 연구소 바닥에 적용하도록 명시했다. 이 요청의 바닥 연결·Editor 검증을 수행하며 다른 샘플·빌드 범위는 확대하지 않는다.
- 테스트 순서 변경: 같은 날 사용자가 앞으로 PLAN의 모든 리소스 작업이 끝나기 전에는 아트 테스트를 진행하지 않도록 지시했다. 이미 수행한 바닥 검증은 이력으로 보존하고, 이후 테스트는 아래 전체 리소스 준비 조건을 충족할 때까지 대기한다.
- 보조형 애니메이션 추가: 2026-11-07 사용자가 이번 PLAN에 보조형 생명체 애니메이션과 필요한 동작을 작성하도록 요청했다. 현재 샘플인 프로토타입의 정적 1프레임 명세를 대기·이동·공통 작업 세트로 확대한다. 이번 요청은 문서 보완이며 이미지 제작·Unity 구현·게임 테스트는 실행하지 않는다.
- 4방향 보완: 같은 날 사용자가 상하좌우 이동을 반영한 4방향 애니메이션과 동작별 프레임 수 명시를 요청했다. 종전 단일 방향 16프레임안을 각 방향 Idle 4·Move 6·Work 6의 64프레임 명세로 대체한다. 기존 제작 기록은 보존하고 문서만 갱신한다.

## 실행 설계와 적용 명세

### 1. 샘플 명세와 요청

#### 제작 방식과 종류별 규격

제작 역할은 [아트 지침의 제작과 역할](../agents/art-assets.md#제작과-역할)을 따른다. 사용자가 Aseprite에서 직접 제작할 수 있도록 각 에셋에 **종류·캔버스 크기·애니메이션 여부·프레임/방향·필요한 모습·사용처·출력 파일**을 적는다. 발행된 요청은 요청 README를 명세·수령·변경 기록의 원본으로 사용하고, 아직 발행하지 않은 항목은 아래 제작안을 구체화한다.

- 같은 종류는 채택한 캔버스 규격을 일관되게 사용한다. 캐릭터·바닥 타일·시설·자원·UI가 모두 같은 크기일 필요는 없다. 시설은 점유 칸에 맞춘 배수 규격을 사용하고, 큰 배경 그림은 바닥 타일과 별도 종류로 정한다.
- 사용자의 캐릭터 **64×64는 설명 예시**이며 확정 지시가 아니다. 아래는 이를 바탕으로 정리한 **새 시작 제안**으로, 신규 4개 분류의 종전 32/64/32/16픽셀 제안을 대체한다. 채택 크기는 실제 표시 영역·가독성과 사용자 제작 의도를 대조해 확정한다. 기존 Build 요청의 64×64는 유지한다.
- 아래 크기는 **투명 여백을 포함한 한 프레임의 원본 캔버스**다. 그림의 불투명 영역, 게임 점유 칸, 화면 표시 크기, 터치 영역과 구분한다. 한 칸에 64픽셀을 대응시키는 시작안도 점유 규칙이나 PPU를 변경하는 근거가 아니다. PPU·필터·압축 등 공통 임포트값은 아트 지침을 참조한다.
- Aseprite 작업 원본은 각 PNG와 같은 기본 이름의 `.aseprite`로 구분해 보관하고, Unity 적용용은 **원본 캔버스를 유지한 100% 크기의 PNG**로 내보내는 안을 사용한다. 자동 잘라내기·확대/축소·여백 제거를 하지 않는다. 원본을 함께 제공하는 경우 원본과 출력의 파일명·버전을 각각 기록하며 직접 임포터 도입을 전제하지 않는다.
- 애니메이션 대상은 획득시설 r003과 프로토타입 보조형이다. 시설은 Idle·Working·Complete 각각 12프레임(총 36프레임), 보조형은 각 방향에 Idle 4·Move 6·Work 6프레임을 사용한다. 4방향 합계는 64프레임·12태그다. 나머지는 정적이며 동작·프레임·시간·반복·재생 조건의 명세 원본은 [요청 README](../../UnityProject/Assets/Sprites/Require/PLAN-026/README.md)다.

#### 1-1. 연구소 바닥 — 기본과 변형 4장

같은 Base를 공유하는 **기본 1개 + 변형 3개**를 한 Aseprite 원본에서 제작한다. 출력은 `LaboratoryFloorSet.png` 256×64 시트 한 장이고 각 셀은 64×64·불투명·정적이다. r003을 Multiple·64×64 격자·간격/Offset 0으로 나눠 `Assets/Sprites/World/Laboratory/`에 적용했다. 수령·최종 참조·기술 검증·시각 확인 상태는 [요청 README](../../UnityProject/Assets/Sprites/Require/PLAN-026/README.md)를 따른다.

| 구분 | 왼쪽부터 시트 셀의 Sprite 이름 | 원하는 디테일 | 혼합 가중치 시작안 |
| --- | --- | --- | --- |
| 기본 | `LaboratoryFloor` | 장식이 거의 없는 평평한 바닥. 낮은 대비의 재질과 최소한의 이음선 | 70% |
| 질감 변형 | `LaboratoryFloorVariant` | 기본과 같은 밝기·재질에 작은 표면 질감만 다르게 배치 | 10% |
| 긁힘 변형 | `LaboratoryFloorScuffed` | 내부에 짧고 옅은 긁힘·마모 자국을 소량 배치 | 10% |
| 얼룩 변형 | `LaboratoryFloorStained` | 내부 일부에 작은 옅은 얼룩. 위험·오염 상태 표식으로 오인할 강한 색은 피함 | 10% |

- **원하는 에셋:** 시설·개체보다 시각적 대비가 낮은 탑다운 연구소 바닥. 전체 색·밝기·조명 방향을 맞추고 세부 무늬만 달리해 반복감을 줄인다. 진한 사각 테두리를 타일마다 두르거나 타일 전체의 밝기를 번갈아 바꿔 바둑판 패턴을 만들지 않는다. 최종 색·재질은 사용자가 정한다.
- **그림 영역·연결:** 각 캔버스를 불투명하게 채운다. 네 가장자리의 색·이음선 위치·두께를 모든 변형에서 동일하게 유지하고 디테일은 내부에 둔다. 어떤 두 파일을 상하좌우로 이어도 빈 틈·끊긴 무늬·두꺼워진 경계가 없어야 한다. 차이를 만들기 위해 원본을 임의 회전·반전·재색칠하지 않는다.
- **사용처·기준점:** 각 그림은 지도 한 칸을 채우고 중심을 칸 중심에 맞춘다. 기본 타일을 대부분 사용하고 변형을 드물게 섞는다. 위 비율은 작은 지도에서 정확한 수량을 강제하는 값이 아니라 표시 선택의 시작 가중치이며 실제 혼합 화면을 보고 조정한다.
- **포함하지 않을 그림:** 시설·벽·캐릭터·문자·방향 화살표·선택 테두리. 큰 배경 일러스트·외곽/모서리 타일·다른 바닥 테마·별도 장식 오브젝트는 추가하지 않는다.
- **동작·검수:** 애니메이션 없음, 파일별 1프레임. 동일 타일을 포함한 4×4 인접 조합을 가로·세로로 확인하고 대표적인 네 타일 접점도 확인한다. 기본만 반복한 화면과 혼합 화면을 비교해 반복감 감소, 얼룩/긁힘의 과도한 밀집, 확대/축소 및 선택·배치 표식과의 대비를 검수한다.

#### 1-2. 획득시설 — `Gathering`

- **원하는 에셋:** 유기물을 얻는 연구소 장치의 전체 외형 1종. 유기물이 모이는 수집부와 작업면을 읽을 수 있는 실루엣을 제안한다. 장치의 세부 구조·색은 사용자 디자인으로 정하며 새 생산 기능을 뜻하지 않는다.
- **그림 영역:** 128×128 투명 캔버스 안에 2×2칸 시설 전체를 그린다. 그림을 네 칸으로 잘라 같은 완성 외형을 반복하지 않는다. 부속물·그림자도 캔버스 안에 두는 시작안으로, 잘리거나 인접 칸을 가리지 않게 한다.
- **사용처·기준점:** 지도상의 획득시설과 기존 배치 미리보기. 시설 외형 중심을 2×2 점유 영역 중심에 맞추고, 기본 방향의 상호작용 칸 `(0, -1)`에 대응하는 작업면을 구분한다.
- **포함하지 않을 그림:** 개체·숫자·진행 막대·선택/배치 가능 색·시설 바깥의 상태 아이콘. 내부 디스플레이 상태 아이콘은 사용자 r002 요청으로 포함한다.
- **동작·검수:** 기본 방향 Idle·Working·Complete 각 12프레임. 실제 수집 중 Working, 산출 사건에 Complete 한 번 후 Idle, 연구소 일시정지 시 현재 프레임 유지. 유기물 생성은 애니메이션 루프로 결정하지 않는다. 기존 네 방향 회전에 같은 시트를 재사용해도 시점·조명·작업면이 맞는지 전체 리소스 준비 후 확인한다. 방향별 원화가 필요하면 명세·제작량부터 수정한다.

#### 1-3. 프로토타입 보조형 — `PrototypeSupport`

- **원하는 에셋:** 건설·수집·운반을 맡는 시작 개체 1종의 대기·이동·공통 작업을 각각 상·하·좌·우로 제작한 12개 동작 세트. 사용자 지정 [상호작용이 많은 생명체의 외형](../game-design/05-development/02-implementation/art-roadmap.md#interaction-friendly-creatures)에 따라 팔다리별 동작이 필요 없는 단순한 슬라임·젤리형 몸체를 사용한다. 보조형은 귀엽고 친근한 인상과 작은 화면에서 읽히는 실루엣을 우선한다. 외형 승인·수정 이력은 연결된 Art 제작 PLAN에서 보존하고 최신 사용자 디자인 요청을 현재 명세에 반영한다.
- **얼굴 디자인:** 눈은 두 개이며 각 눈을 흰색 또는 검은색의 단색 점으로 표현한다. 흰자·홍채·동공·눈 안 반사점은 나누어 그리지 않는다. 두 눈은 같은 색을 쓰고 몸체와의 대비로 색을 정한다. 정면은 두 눈, 측면은 가려지는 눈 생략 가능, 뒷면은 눈 없음으로 제작한다. 기존 Art 외눈·동공 초안은 과거 기록이며 이번 두 점눈 명세로 대체한다. 눈 간격·크기·동작 중 정렬·작은 화면 가독성은 전체 리소스 준비 후 사용자와 확인한다.
- **그림 영역:** 64×64 투명 캔버스, 본체는 중앙 약 48×48 안에 놓고 사방 약 8픽셀 여백을 두는 시작안이다. 캔버스 크기와 실제 몸집을 구분해 시설보다 작게 읽히는지 확인한다.
- **사용처·기준점:** 기존 지도 위치·이동·Job의 실제 진행에 연결할 개체. 전 방향·프레임에 공통 중심 피벗을 유지하고 바닥 접지 위치·시점·방향별 머리 위 자원 받침점과 프레임별 위치 변화를 기록한다. 받침점은 표현용 좌표이며 PNG에 표식으로 그리지 않는다.
- **포함하지 않을 그림:** 들고 있는 유기물·선택 원·이름·상태 아이콘. 실제 운반물은 머리 위의 별도 자원 표시 슬롯에 연결하며 기본 몸체에 굽지 않는다. 자원별 캐릭터 시트를 만들거나 64×64 몸체 캔버스에 운반물 공간을 합치지 않는다.
- **출력·요청:** `PLAN-026-SPR-003`. 같은 몸체의 `PrototypeSupport.aseprite` 1개와 `PrototypeSupport.png` 1개로 제작한다. 셀 64×64·8열×8행·512×512 RGBA 시트로 구성하며, 태그·프레임 시간·머리 받침 좌표는 [요청 명세](../../UnityProject/Assets/Sprites/Require/PLAN-026/README.md#plan-026-spr-003--프로토타입-보조형-애니메이션)에 따로 기록한다.

| 필요한 동작 | 각 방향의 태그·프레임 | 원하는 모습 | 실제 재생 조건 |
| --- | --- | --- | --- |
| 대기 | `Idle_<방향>` / **방향당 4**, 합계 16프레임·각 250ms·1초 반복 | 중심/접지를 유지하는 작은 호흡·눌림과 복원. 기본 형태를 유지 | 이동·작업 진행이 없는 정상 대기. 경로/자원 대기에서도 사용 |
| 이동 | `Move_<방향>` / **방향당 6**, 합계 24프레임·각 100ms·0.6초 반복 | 몸체가 짧게 눌렸다 늘어나는 이동 리듬. 실제 이동은 게임 위치가 담당 | 기존 경로 이동이 실제 진행할 때. 빈손·운반 모두 같은 몸체 동작 |
| 공통 작업 | `Work_<방향>` / **방향당 6**, 합계 24프레임·각 120ms·0.72초 반복 | 이동보다 분명한 제자리 눌림·팽창. 얼굴 특징·접지·체적 유지 | 현재 프로토타입이 실제 건설하거나 획득시설에서 수집 작업을 진행할 때 |

`<방향>`은 `Down`, `Left`, `Right`, `Up` 중 하나다. 아래는 원본 타임라인의 1부터 시작하는 프레임 번호이며 각 행의 세 동작은 모두 별도 태그다.

| 방향·보이는 면 | Idle | Move | Work | 방향별 합계 |
| --- | --- | --- | --- | --- |
| 아래 `Down` · 정면 | 1~4 (4) | 5~10 (6) | 11~16 (6) | 16 |
| 왼쪽 `Left` · 왼쪽 측면 | 17~20 (4) | 21~26 (6) | 27~32 (6) | 16 |
| 오른쪽 `Right` · 오른쪽 측면 | 33~36 (4) | 37~42 (6) | 43~48 (6) | 16 |
| 위 `Up` · 뒷면 | 49~52 (4) | 53~58 (6) | 59~64 (6) | 16 |

- **운반은 합성 상태:** 별도 `Carry` 몸체 프레임을 만들지 않는다. 이동 중 해당 방향의 `Move`, 대기 시 마지막 방향의 `Idle`에 머리 위 자원 Sprite를 결합한다. 자원 종류별·수량별·운반 전용 방향 프레임도 추가하지 않는다.
- **집기·내려놓기:** 전용 `PickUp`/`Drop` 동작은 이번 제작에서 제외한다. 실제 집기/전달·소비 결과로 자원 표시만 켜거나 끈다. 애니메이션 종료를 기다려 게임 진행을 지연시키지 않는다.
- **방향별 외형:** 정면·뒷면·두 측면을 구별한다. Up에 정면 얼굴을 그대로 붙이거나 몸체를 90도 돌려 다른 방향을 대신하지 않는다. 좌우도 각각의 태그·출력 프레임을 제공하며 자동 반전만으로 완료 처리하지 않는다. 제작 중 대칭 부분은 재사용할 수 있지만 눈·무늬·광원·받침점의 방향 일관성을 검수한다. 대각선·공격·피격·죽음·작업별 도구 동작은 제외한다.
- **방향 선택:** 지도 논리 축의 +Y=Up, -Y=Down, -X=Left, +X=Right다. 이동은 현재 실제 경로 구간의 진행 방향을 읽으며 먼 최종 목적지나 화면 회전에서 방향을 추측하지 않는다. 실제 건설/수집은 상호작용 칸에서 인접한 시설 점유 칸을 향하는 방향으로 Work를 선택한다. 대기·운반 대기는 마지막 유효 방향을 유지한다.
- **상태 전환:** 실제 이동이면 Move, 이동하지 않고 실제 작업 진행 중이면 Work, 나머지는 Idle로 선택한다. 예약·작업 배정·접근 불가만으로 Work를 재생하지 않는다. 동작이 같고 방향만 바뀌면 반복 진행률을 유지하고 방향별 대응 프레임으로 바꾼다. 동작이 바뀔 때만 해당 태그의 첫 자세로 전환한다.
- **일시정지·복원:** 연구소 진행이 정지하면 현재 동작·방향·프레임·재생 시간을 유지한다. 새 판·이어하기는 실제 이동 구간 또는 작업 대상으로 방향을 재구성하고 해당 동작의 첫 프레임에서 시작한다. 이를 알 수 없는 최초 대기는 Down을 기본으로 한다. 표현용 방향·프레임을 저장 필드로 추가하지 않으며 개체별 상태를 독립 관리한다.
- **동작과 게임 결과:** Work 루프나 재생 완료는 자원 생성·건설 진행·전달을 발생시키지 않는다. 프로토타입의 기존 기능만 표시하고 생산시설 작업 배정 능력 등 새 기능을 추가하지 않는다.
- **머리 받침·그리기 순서:** 방향별 기본 받침점과 프레임별 위치 변화만 자원 표시로 전달하고 자원 Sprite의 크기·회전·좌우 반전은 유지한다. 같은 자원 그림을 네 방향에서 사용하며 자기 몸체 위에 보이게 하고, 다른 개체/시설과의 전체 순서는 몸체의 지도 위치를 따른다. Up에서도 머리에 올려진 모습과 자원 식별성을 확인하고 상태 UI를 가리지 않게 한다.
- **검수:** 전체 리소스 작업 완료 후 12개 태그·64개 프레임의 반복 경계, 네 방향 이동과 급회전·정지, 회전한 시설에서의 Work 방향, 운반 대기·받침점·겹침·시설 옆 가독성 및 각 방향/동작의 사용자 시각 확인을 수행한다. 일부 방향만 준비됐을 때 게임 테스트를 시작하지 않는다.

#### 1-4. 유기물 — `OrganicMatter`

- **원하는 에셋:** 생체 재료임을 알아볼 수 있는 유기물 덩어리 1종. 부드럽고 불규칙한 덩어리 또는 세포가 모인 형태를 제안한다. 후속 배양액의 액체/용기 표현과 색상 외 형태로도 구분할 수 있게 한다.
- **그림 영역:** 32×32 투명 캔버스, 주요 형태는 중앙 약 24×24와 사방 약 4픽셀 여백을 시작안으로 한다. 축소 시 사라지는 세부 묘사보다 윤곽을 우선한다.
- **사용처·기준점:** 유기물 수량 옆 아이콘과 실제 운반 중 머리 위 표시에 같은 그림을 재사용한다. 중심 피벗을 시작안으로 유지하고 표시용 위치 보정으로 그림 하단을 개체의 받침점에 맞춘다. 두 사용처의 표시 크기를 각각 검수한다.
- **포함하지 않을 그림:** 수량 숫자·개체·저장소·재고 더미·선택/상태 프레임. 그림만으로 새 자원이나 보관 상태를 만들지 않는다.
- **동작·검수:** 애니메이션 없음, 1프레임. 운반 표식 크기에서 자원 종류가 읽히고 개체 본체나 입력을 가리지 않는지 확인한다.

#### 1-5. 건설 메뉴 아이콘 — `Build`

- **원하는 에셋:** 건설 가능한 시설 목록으로 들어간다는 의미의 단순한 건물 외형 1종. 개별 획득시설 그림의 축소본보다 메뉴 의미가 먼저 읽히는 실루엣을 원한다.
- **그림 영역:** 기존 요청대로 64×64 투명 캔버스, 중심 피벗 `(0.5, 0.5)`·Full Rect. 가장자리 잘림을 피하고 다른 메뉴 아이콘과 시각적 무게를 맞추며, 내부 여백은 실제 버튼에서 확인한다.
- **사용처·교체 대상:** 하단 건설 메뉴의 `LaboratoryIcon.Build` / `icons[6]`, 기존 `Temp_Build.png`를 교체한다. 버튼 문구·터치 영역은 유지한다.
- **포함하지 않을 그림:** 글자·버튼 배경·눌림/비활성 색·건설 확정 체크 표시. 메뉴 진입과 즉시 건설 명령을 혼동하지 않게 한다.
- **동작·검수:** 애니메이션 없음, 1프레임. 기존 `PLAN-014-SPR-006`을 사용하고 파일명·수령 위치를 중복 요청하지 않는다. ko/en·큰 글씨·가로/세로에서 메뉴 의미와 여백을 확인한다.
- **제작 결과:** [Art PLAN-005](../../../Art/docs/plans/PLAN-005-build-icon.md) completed·r001 제작/파일 검사/수령/Art 사용자 승인 완료·approved_revision 1이다. Unity 적용·게임 화면 승인까지 완료했으며 기록은 [기존 PLAN-014 요청](../../UnityProject/Assets/Sprites/Require/PLAN-014/README.md#plan-014-spr-006--건설-메뉴-아이콘-제작-연결)에 연결한다.

### 2. 실제 연구소에 최소 표시 연결

기존 `LaboratoryMapView`·uGUI와 같은 지도 변환을 유지하는 방식을 우선한다. 추가 이미지가 지도 입력을 가로채지 않고, 기존 셀 선택·겹친 대상 목록·핀치·드래그·시설 미리보기와 함께 동작해야 한다.

- 바닥은 기존 지도 경계 안에 표시하고, 고정된 표현용 선택 규칙과 칸 좌표로 4장 중 하나를 고른다. 화면 갱신·줌·선택·회전·이어하기 때 같은 칸의 무늬가 바뀌지 않게 한다. 게임 진행용 난수 상태를 소비하거나 저장 필드·DataHash·JSON을 바꾸지 않는다. 기본 타일만 있는 동안의 대체 표시도 유지한다. 방·벽·별도 장식·새 지형/게임 규칙은 만들지 않는다.
- 획득시설은 Thing 하나당 시설 외형 하나로 표시한다. 2×2 각 칸에 같은 완성 그림을 반복하지 않는다. 회전·이동·미리보기·건설 중 상태는 기존 점유/상호작용/진행 상태를 따른다.
- 프로토타입은 기존 위치·이동·작업 진행을 읽어 Idle/Move/Work Sprite를 재생하고 실제 운반 자원은 머리 위 별도 표시로 연결한다. 재생용 시간과 앵커 보정은 표현 객체가 소유하며 이동·Job 계산이나 보간용 별도 게임 상태를 만들지 않는다. 겹친 개체는 기존 후보 선택과 개체 수 표시를 유지한다.
- 유기물 수량 옆 아이콘과 운반 표식은 같은 제공본을 재사용한다. 운반 표식은 실제 유기물을 운반하는 상태가 확인될 때만 표시하고, 단순 작업 예약·초기 소지품·빈손 이동을 운반으로 오인하지 않는다. 장식 이미지가 자원 Thing 생성이나 수량 반영을 유발하지 않는다.
- 운반 표식은 머리 위 받침점에 연결한 별도 uGUI Image로 구성하는 안을 사용한다. 자원 정의의 기존 Sprite 참조를 읽고 터치 판정을 가로채지 않게 한다. PLAN-027에서는 같은 표시 계약을 SpriteRenderer로 이관하며, 이 art PLAN에서 월드 렌더러 전환을 선행하지 않는다. 운반 중 대기·부분 입고·복원 시 실제 운반 자원의 잔량에 맞춰 유지/해제하고 상태 표식과의 겹침을 확인한다.
- 건설 아이콘은 기존 `LaboratoryIcon.Build` 슬롯을 교체한다. 메뉴 위치·문구·터치 영역·기능을 바꾸지 않는다.
- 새 바닥 위에서도 선택·배치 유효/무효·접근 칸·건설/생산 상태 표식이 읽혀야 한다. 기존 색상 틴트가 제공 아트의 색을 왜곡하지 않도록 선택/상태 표현을 구분하고 실제 결과를 확인한다.
- 미제공 종류는 기존 표시로 남긴다. Sprite 참조 누락 시에도 대상 선택과 상태 확인이 가능한 대체 표현을 유지한다. 샘플 외 시설·생명체를 정식 적용 완료로 표시하지 않는다.
- 참조 교체는 씬·프리팹·SO와 생성 도구를 함께 확인한다. Require를 영구 런타임 참조로 사용하지 않으며 `.meta`·GUID와 사용자 원본을 보존한다.

표현 객체는 연구소 화면이 소유하고 Thing ID로 연결한다. 같은 종류의 서로 다른 개체가 표시 상태를 공유하지 않아야 하며, 새 판·이어하기·씬 이탈·Play 재진입 때 이전 객체·참조·이벤트를 정리한다. 새 전역 싱글톤·변경 가능한 static 캐시·게임 진행 저장 필드는 추가하지 않는다.

참조 구성과 표시 갱신 책임만 작게 분리한다. 이후 아트 교체 시 게임 규칙 코드 대신 참조를 바꾸는 것이 재사용의 근거다. 클래스/프리팹 이름과 바인딩 방식은 실제 변경 지점에 맞춰 정하고, 범용 렌더러 인터페이스·새 프레임워크·Tilemap/Pixel Perfect/Atlas/임포터 패키지는 선행 도입하지 않는다. 광범위한 렌더링 교체가 필요하면 이 PLAN에 조용히 포함하지 않고 별도 development 범위로 분리한다.

후속 후보 [PLAN-027 연구소 Tilemap·SpriteRenderer 전환](PLAN-027-laboratory-tilemap-and-sprite-rendering.md)을 `development` / `proposed`로 분리했다. 기본 순서는 이 PLAN의 전체 리소스 적용·검증·사용자 시각 확인 완료 후 별도 활성화 승인을 받는 것이다. PLAN-026 완료 후에도 이 후보는 `proposed`로 유지하며, 별도 활성화 승인 없이 렌더링 전환을 시작하지 않는다.

### 3. 비교 상태와 사용자 시각 확인

이 단계의 게임 실행·화면 캡처·테스트는 아래 전체 리소스 준비 조건을 충족한 뒤 진행한다.

기존 플레이 화면에서 5개 분류·8개 샘플이 함께 보이는 초기 운영 상태를 만든다. 시설의 36프레임과 프로토타입의 64프레임 제작안을 동작·방향별로 확인한다. 시설 건설·자원 운반 등 준비는 기존 공통 명령으로 수행하고, 특별한 상태 준비는 검증 슬롯/테스트 쪽에 둔다. 제품 시작 상태·JSON·사용자 저장을 샘플 전시장으로 바꾸지 않는다.

- 같은 준비 상태에서 가로·세로 각각 전체 보기/중간 확대/최대 확대를 비교한다. 실제 해상도·배율·준비 상태·샘플 버전을 기록하고 최소 6개 기본 화면을 남긴다. 화면 크기만 바꾼 Editor 확인을 실제 휴대폰 터치 검증으로 표현하지 않는다.
- 별도 화면으로 시설 회전/접근 칸·건설 미리보기·개체 겹침/후보 선택·실제 유기물 운반 표식을 확인한다. 가독성을 위해 디버그 문자를 숨겼다면 선택/상태 정보의 대체 경로도 확인한다.
- 기본 바닥만 반복한 상태와 4장 혼합 상태를 같은 화면 조건으로 추가 비교한다. 실제 선택 분포를 기록하고 변형 3장이 모두 포함됐는지 확인한다. 바닥 4장 각각과 혼합 결과의 반복감·연결·명암·밀집을 사용자에게 확인받는다.
- 사용자에게 바닥 대비, 시설/개체/자원 비율, 외곽선·시점·색감 일관성, 확대/축소 식별성, 시설/보조형 동작·머리 위 운반·아이콘 의미를 확인받는다. 미확인·수정 요청·확인 완료를 8개 샘플과 각 동작·바닥 세트에 대해 구분한다.
- 수정은 요청 README에 남기고 사용자가 제공한 수정본으로 연결한다. 바뀐 샘플과 영향받는 비교 화면만 재검수하며, 승인되지 않은 원본 수정으로 맞추지 않는다.
- 결과는 `docs/plans/evidence/PLAN-026/` 아래 버전별 화면·설정·참조·검증 기록으로 보존한다. 실제 경로는 실행 후 생성하며 기존 PLAN-025 증거를 덮어쓰지 않는다.

테스트는 실제 변화의 위험을 확인하는 범위로 선택한다. 기존 검사와 실제 표시/입력 경계를 재사용하며, 클래스 구조나 파일명을 기대값으로 복사한 검사를 늘리지 않는다. 같은 변경에 전체 회귀를 근거 없이 반복하지 않는다.
