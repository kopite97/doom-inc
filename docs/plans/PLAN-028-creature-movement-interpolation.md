# PLAN-028 연구소 생명체 이동 보간과 표시 동기화

## 목표

연구소 생명체가 칸 사이를 순간적으로 옮겨 보이는 현상을 줄이고, 상하좌우 경로를 따라 부드럽게 이동하도록 표시 위치를 보간한다. 몸체·머리 위 자원·선택 표시가 같은 위치를 따르고, 이동 중에도 보이는 개체를 선택할 수 있어야 한다. 논리 칸 점유·이동 속도·작업·자원 처리 시점은 기존 게임 규칙을 유지한다.

새 아트 제작이 아닌 표현 기능 개선이므로 `type: development`다. **현재는 proposed이며 구현·Unity 실행·테스트를 시작하지 않는다.**

## 범위

- 포함: 연구소 Map에 배치된 생명체의 작업 접근·운반 이동과 유휴 배회. 정식 Sprite가 있는 프로토타입과 기존 임시 표현을 사용하는 이동 생명체에 같은 위치 계약을 적용한다.
- 포함: 경로 구간의 표시 위치, 4방향 Move/Idle/Work 선택, 운반 자원·선택 테두리·관련 표식의 위치, 이동 개체 클릭과 겹침 후보, 그리기 순서·줌/팬/화면 방향 대응.
- 포함: 이동 시작·도착·방향 변경·경로 재계산·차단·일시정지·이어하기·세션 교체의 보간 수명과 영향받는 Editor 검증.
- 제외: 경로 탐색 알고리즘·격자 점유·이동 시간·작업 우선순위·예약·생산/입고 타이밍·밸런스·저장 형식 변경. 물리 충돌·NavMesh·대각선 이동·가속/감속·새 배회 규칙을 추가하지 않는다.
- 제외: 시설 배치 미리보기와 확정 시 즉시 재배치 규칙, 지도 카메라 자동 이동, Map 밖 침공 활동의 새 이동 표현. PLAN-027의 Tilemap/SpriteRenderer·카메라 전환과 Pixel Perfect Camera 도입은 이 PLAN에서 실행하지 않는다.
- 제외: Sprite 신규 제작·프레임 추가·픽셀/피벗/PPU/필터/압축 수정, PLAN-025의 전역 GC 개선, 무관한 UI 개편.
- 제외: Android/PC Player·Addressables 콘텐츠·Player 스크립트 컴파일·IL2CPP 빌드와 기기 설치/검증. 이 보간 변경에 대한 빌드 승인은 없으며 이전 PLAN의 승인을 재사용하지 않는다.
- 요청 근거: 2026-11-10 사용자가 “한 칸 단위로 한번에 이동”하는 현재 표현에 부드러운 보간이 필요하다며 PLAN 작성을 요청했다. 작성 승인과 실행 승인을 구분한다.

## 설계와 동작 계약

### 1. 논리 칸과 표시 위치

- `Placement.Origin`과 Map이 논리 위치의 원본이다. 표시 위치는 칸 단위의 소수 좌표이며 게임 명령·거리 계산·경로·작업 가능 여부·저장으로 역전파하지 않는다.
- 정상 작업 이동은 유효한 현재 칸 A·다음 칸 B와 `t = Clamp01(MoveProgress / MoveSecondsPerCell)`을 사용해 `A + (B - A) * t`를 표시 위치로 계산하는 안을 우선한다. 각 렌더러의 칸 중심·접지 보정은 그 뒤 한 번 적용한다. MoveProgress를 이미 0~1인 비율로 취급하지 않는다.
- 유효 구간은 현재 세션·Thing ID·논리 원점, 이동 단계/대기 이유, 목표의 현재 상호작용 칸, 경로 버전·인덱스·다음 칸의 인접/통행 가능 여부를 함께 확인한다. LayoutVersion이 같은데 목표가 바뀐 경우도 구별한다. 시간값은 유한·0 이상, 한 칸 시간은 유한·양수여야 하며 Clamp로 잘못된 구간이나 비정상 누적값을 숨기지 않는다. 조회용 읽기 전용 상태를 최소 보완할 수 있으나 표현을 위해 게임 진행률을 수정하지 않는다.
- 같은 종류·출발/목표·경로의 재평가는 새 이동으로 보지 않는다. Job 객체가 다시 생성되거나 진행률이 정확히 0이 되는 정상 칸 경계에서 보간·방향·프레임을 초기화하지 않는다. 반대로 경로 캐시가 남아 있어도 Job 단계/목적지가 바뀌면 이전 구간을 그대로 쓰지 않는다.
- 선형·등속 보간을 기본으로 한다. 매 칸 easing이나 매 프레임 현재 위치에서 목표까지 Lerp하는 방식으로 속도·도착 시점을 바꾸지 않는다. 표시가 다음 칸에 먼저 들어가 보여도 논리 점유 확정과 실제 작업/수령은 기존 로직만 결정한다.
- 직선의 연속 구간과 90도 모서리에서 다음 구간으로 이어진다. 건너뛴 여러 칸의 시작·끝만 연결해 시설을 대각선으로 가로지르지 않는다. 낮은 프레임률·긴 Advance에서는 현재 유효 구간/진행률을 표시하며 지나간 모든 구간을 대기열로 재생해 지연을 누적하지 않는다.

### 2. 배회·재계산·불연속 처리

- 유휴 배회는 실제 이동 확정의 이전 칸·새 칸·시뮬레이션 시각을 읽을 최소 관찰 정보를 추가하는 안을 검토한다. 배회 선택 주기·논리 Place 시점은 그대로 두고, 한 칸의 시각 전환 시간은 기존 MoveSecondsPerCell을 기준으로 한다. 이 경로의 최대 한 칸 전환 지연을 작업 이동과 구분해 기록한다.
- 배회 도중 실제 Job이 생기면 마지막 표시 위치에서 연결한다. 배회 기록은 렌더 프레임의 이전/현재 칸 차이로 추측하지 않고 실제 확정 이동에서 관찰하며, 한 프레임에 여러 이동이 생겨도 시설 재배치·복원과 혼동하지 않는다. 표시 도착 전에는 제자리 Work를 보류하되 논리 작업 시작·생산량은 화면 도착까지 늦추지 않는다.
- 경로 차단·대상 이동/제거·우선순위/Job 변경·배치 확정 후 재개에서 오래된 도착점과 방향을 폐기한다. 정상 재계산은 마지막 표시 위치와 새 유효 구간을 연결한다. 필요하면 진행 중 구간을 논리 칸까지 되짚은 뒤 새 방향으로 이어가며 모서리 절단·막힌 칸 관통을 금지한다.
- 배회→작업과 유효 경로 재지정의 시각 보정은 정상 등속 구간과 구분한다. 첫 보정 시작부터 해당 개체의 한 칸 이동 시간 이내에 최신 유효 표시 위치로 합류하는 것을 목표로 하고, 매 프레임 새 목표를 받는다고 종료 시각을 계속 미루지 않는다. 보정 중에는 허용된 구간을 따르는 일시적인 표시 속도 차이를 허용하되 논리 속도·도착 시점을 바꾸지 않는다. 중간점/기록은 유한한 최근 구간만 보관하고 이벤트 큐를 무한히 쌓지 않는다. 이 조건을 대표 배회→직진/직각/역방향 fixture로 먼저 입증하며, 실패하면 조용히 지연을 허용하지 말고 설계·한계를 재기록한다.
- 지도 변경으로 기존 표시 구간 자체가 무효인 경우에는 유효한 현재 논리 위치로 즉시 재정렬할 수 있다. 이 예외와 생성·새 판·불연속 재배치·복원을 정상 이동의 순간 이동과 구분해 검증한다. 임의의 먼 거리 임계값만으로 실제 경로 이동을 순간 이동 처리하지 않는다.
- 표시용 경로 탐색을 매 프레임 추가하지 않는다. 현재 캐시·이동 관찰을 재사용한다. 복원 직후 표시 전용 경로 조회가 꼭 필요하면 세션/개체/원점/목표/지도 버전 조합당 최대 한 번 수행하고 실패도 기억해 같은 조건으로 재시도하지 않는다. 이후 게임 로직이 경로를 준비하면 그것을 재사용한다. 정상 지속 이동·배회에서 표시 때문에 추가되는 PathQueries/VisitedCells는 0이어야 하며 표시 조회가 Job·예약·경로 진행 상태를 변경하지 않아야 한다.

### 3. 애니메이션·자원·선택·겹침

- 몸체·머리 위 자원·선택 표시와 개체에 붙는 기존 UI는 동일한 표시 위치를 사용한다. PLAN-026의 프레임별 머리 받침점은 이 위치에 상대 좌표로 더하며 자원 크기·회전·반전 규칙을 유지한다.
- Move 방향은 현재 표시하는 유효 경로 구간을 따른다. 모서리에서 방향만 바뀌면 반복 진행률을 유지하고, 도착 시에는 마지막 유효 방향의 Idle 또는 실제 작업 대상 방향의 Work로 전환한다. 위치 갱신마다 애니메이션 시간을 초기화하지 않는다.
- 실제 집기·부분/전량 입고·대기·소비에 따른 자원 표시 조건을 보존한다. 화면 위치가 도착했다는 이유로 집기·전달·산출 사건을 발생시키지 않는다.
- 일반 선택은 표시된 생명체의 화면 영역으로 후보를 찾고 동일 Thing ID를 기존 선택 경로로 전달한다. 시설 등 논리 칸 후보와 합칠 때 중복 ID를 제거하고 기존 시설 우선·생성 순서·후보 순환 정책을 보존한다. 이동 생명체의 과거 논리 칸에 보이지 않는 클릭 영역을 남기지 않으며 배치/건설 클릭은 계속 논리 칸을 사용한다.
- 겹친 생명체·시설·운반 자원에서 후보와 테두리·개수 표시가 어긋나지 않게 한다. 개체의 그리기 순서는 표시 접지 위치와 안정적인 동률 기준을 사용하고 몸체 프레임의 상하 흔들림으로 순서가 뒤집히지 않게 한다.
- 미제공 종류는 기존 색/문자 대체 표현을 필요한 만큼 개체별로 연결한다. 같은 개체가 과거 칸 라벨과 이동 표시 양쪽에 중복되지 않아야 한다. 새 정식 아트를 요구하지 않는다.
- 화면 투영·선택 범위·몸체/자원 위치는 같은 게시된 표시 상태를 읽는다. 시뮬레이션 진행과 UI 레이아웃을 확정한 뒤 위치 평가→몸체/자원→겹침/상태 UI→클릭 범위 게시의 소유와 순서를 명시한다. 서로 다른 MonoBehaviour의 LateUpdate 호출 순서에 우연히 의존하지 않는다. 입력은 사용자가 마지막으로 본 표시 범위를 기준으로 판정하고, 제거/방출된 ID는 명령 전달 전에 다시 확인한다. viewport 변화·UI 차단 중에는 오래된 범위를 사용하지 않는다.
- 움직이는 몸체를 피하는 시설 상태 표식은 기존 위치가 유효하면 유지하고 실제 충돌/viewport 변화가 있을 때 재배치한다. 정지 시설의 표식이 매 프레임 다른 후보 위치로 튀거나 선택 클릭 영역이 한 프레임 뒤처지지 않도록 동영상과 입력 회귀에 포함한다.

### 4. 시간·복원·소유·렌더링 경계

- 연구소 진행 정지 시 보간 위치·배회 전환·방향·동작 시간을 함께 고정한다. 배치 편집·종료·앱 비활성/복귀에서 벽시계로 앞서 움직이거나 복귀 시 누적 시간을 한꺼번에 재생하지 않는다. 정지 중 줌/팬/방향 변경은 같은 지도 위치의 화면 투영만 바꾼다.
- 이동 중 저장과 복원에서는 기존 논리 칸·MoveProgress·Job을 유지한다. 유효한 다음 칸이 재구성되면 그 진행률로 초기 표시를 정하고, 아직 없으면 안전한 논리 위치에서 초기화한다. 이전 세션 화면 좌표에서 새 위치까지 날아가는 보간을 하지 않는다. 표시 캐시·Tween·방향/프레임을 저장 필드로 추가하지 않는다.
- 표시 상태는 연구소 화면/세션이 Thing ID별로 소유한다. 방출·제거·멸망·Title 왕복·새 판에서 상태·표시·구독을 정리하고 다른 개체나 다음 세션에 재사용하지 않는다.
- 공통 책임은 유효 이동 구간에서 지도 표시 위치를 계산하는 부분이다. 달라지는 부분은 uGUI 또는 SpriteRenderer의 위치 적용·화면 선택이다. 작은 값/함수 또는 구체 클래스부터 시작하고, 범용 보간 관리자·싱글톤·가상 렌더러 계층을 만들지 않는다. 근거는 몸체/자원/선택의 공통 좌표와 PLAN-027의 명시적인 전환 경계다.
- 진행률의 직접 표시는 [현재 상태값 표시 예외](../agents/presentation-effects.md)를 적용한다. 독립된 시간 기반 전환이 추가로 필요하면 기존 DOTween 사용 기준과 중단/수명 규칙을 따르되 같은 위치를 두 갱신 경로가 동시에 제어하지 않도록 한다. 구체적인 채택 이유는 실행 PLAN에 기록한다.
- 소수 표시 좌표를 논리 칸이나 정수 픽셀로 먼저 반올림하지 않는다. 기존 Point·PPU 32를 유지하고 전체/중간/최대 및 비정수 배율의 선명도·떨림을 확인한다. Pixel Perfect 설정이 선행 PLAN에서 도입됐다면 최종 렌더링 단계의 스냅과 연속 보간을 함께 검증한다.

### 5. 최적화 범위와 비용 계약

- 이번 범위는 **새 보간 경로와 그 연결 때문에 늘어나는 표시 비용**이다. 위 기존 할당/검색을 그대로 복제하지 않고 접점의 중복 조회는 줄이되, 무관한 HUD/Localization·시뮬레이션 전체 최적화까지 확대하지 않는다. PLAN-027을 먼저 실행했다면 uGUI 시절 병목을 그대로 전제하지 않고 전환 직후 코드를 재측정한다.
- 프레임마다 개체의 구간/표시 위치는 한 번만 평가해 몸체·자원·선택·상태 회피에서 공유한다. 정지 개체도 Job/자원/세션 변경은 확인하되 위치가 같으면 불필요한 Transform/RectTransform 쓰기를 생략한다. 화면 밖에서는 비싼 그림/화면 경계 갱신을 줄일 수 있지만 시간·구간은 뒤처지지 않게 하며 다시 보일 때 현재 상태를 즉시 평가한다.
- 정상 구간의 위치 평가·캐시 갱신은 개체당 O(1), 전체 O(N), 보유 상태는 O(N)으로 제한한다. 매 개체마다 전체 Registry·Placement·Reservation을 다시 순회하지 않는다. 표시 대상·운반 상태·겹침 그룹은 필요한 범위에서 한 번 집계하고 재사용하며, 기존 GetPlacements의 추가 호출을 위치/자원/입력마다 늘리지 않는다.
- List/Dictionary와 임시 ID·정렬 버퍼는 재사용하고, 신규 지속 보간 경로에는 LINQ/ToArray·프레임별 클로저·문자열 생성·새 Tween/객체 생성을 넣지 않는다. 워밍업·구성원 수가 안정된 뒤 **추가한 위치 계산/표시 캐시 경로의 managed 할당은 0 B/프레임**을 목표/완료 기준으로 삼는다. 생성·제거·초기 capacity 확장과 기존 화면 전체 GC를 따로 측정해 전체 게임 무할당으로 주장하지 않는다.
- 수직 순서가 바뀔 가능성이 있는 이동·구성원/시설 변경 때만 정렬을 재평가한다. 필요한 전체 정렬은 재사용 버퍼로 O(N log N)까지 허용하며 상대 순서가 같으면 SetAsLastSibling/정렬 값 쓰기를 반복하지 않는다. 모든 개체 쌍을 비교하는 신규 O(N²) 정렬/겹침 루프는 만들지 않는다. 선택 후보 검색은 입력 시 수행하고 단일 탭 O(N) 순회부터 시작한다. 쿼드트리·전역 객체 풀·Jobs/Burst 도입은 실제 측정 근거 없이 추가하지 않는다.
- 캐시 갱신은 종류별로 나눈다. 구성원은 생성/제거/배치/방출/세션 세대, 위치는 실제 구간과 시각, 경로는 목표/원점/레이아웃, 자원은 소유·종류·잔량·예약 단계, 화면 범위는 위치·프레임/앵커·카메라/viewport/배율을 따른다. LayoutVersion 또는 AvailabilityVersion만으로 모든 표시를 캐시하지 않는다. 기존 관찰 지점이 부족하면 필요한 읽기 전용 조회/알림만 보완한다.
- uGUI 실행 경로에서는 계층 재배열·Canvas 재빌드·상태 표식 레이아웃 비용을 위치 수학과 분리한다. SpriteRenderer 실행 경로에서는 Transform·sorting·관련 uGUI 투영을 분리한다. 화면 갱신 빈도를 낮춰 칸 단위 움직임으로 되돌아가는 것을 최적화 성공으로 처리하지 않는다.

### 6. 측정 조건과 판정

- 활성화 시 **PLAN-028 적용 직전 동일 렌더러/아트/설정**을 비교 기준으로 고정한다. PLAN-025/026의 과거 성능 수치를 새 기준값으로 재사용하지 않는다. 소스/fixture·카메라·해상도·배율·상태 UI·프레임 제한·Profiler 연결 조건을 기록한다.
- 기존 검증 슬롯의 기본 1명·중간 4명·고부하 24명 작업자 구성을 현재 코드로 복원하고 실제 이동/대기/운반 개체 수를 기록한다. 밀집 운반·상태 UI ON과 최대 줌에서 대부분 화면 밖인 경우를 대표 추가 조건으로 둔다. 개체 수가 다르거나 대부분 멈춰 있는 비교를 같은 이동 부하로 취급하지 않는다.
- 화면은 매 렌더 프레임 갱신하면서 논리에는 동일한 고정 delta/명령 목록을 주는 통제 비교와, 실제 Editor Update의 화면 체감을 구분한다. 각 통제 회차는 같은 격리 저장으로 초기화하고 30초 워밍업·60초 수집을 전후 각 3회 수행한다. 예비 측정에서 조건 변경이 필요하면 본 측정 전에 길이·허용 범위를 고정한다. 비교 중 결과에 맞춰 기준을 완화하지 않는다.
- 활성화 시 확인한 유효한 Profiler 카운터/구간으로 위치 계산·전체 표시/정렬·Canvas/렌더 CPU, Main Thread의 실제 작업과 프레임 대기, GC B/프레임·GC 발생·메모리/표시 객체 수를 분리한다. median·p95·max와 반복 범위를 보고하고 Profiler 기록/파일 출력/테스트 단언의 할당을 제품 비용과 분리한다. 측정 버퍼는 사전 할당하고 저장은 측정 구간 밖에서 한다.
- 직접 판정 항목은 신규 정상 보간의 0 B/프레임, 표시로 인한 정상 이동/배회 경로 조회 증가 0, 세션 해제 후 남은 개체별 캐시/구독/표시 0이다. CPU는 개선을 선결 조건으로 약속하지 않고, 사전 기준 반복 편차를 넘는 지속적인 p95 증가가 있으면 원인·허용 비용을 설명하고 해결 전에는 단순 통과로 기록하지 않는다. 전체 화면 비용과 보간 자체의 추가 비용을 함께 보고한다.
- 제한된 보간/집계 구간에는 12/24/48개 표시 대상의 보조 표본으로 증가 양상을 확인한다. 전체 게임 로직의 복잡도와 혼동하지 않고, 프로파일의 호출 횟수·할당 근거와 함께 신규 개체별 전체 검색이 없는지 판정한다. 성능 기준/계측이 준비되지 않았거나 유효 카운터가 없으면 미측정으로 남긴다.

## 완료 기준과 검증 방법

활성화 후 수행할 계획이다. 제품 저장과 분리한 fixture를 사용하고 구현 내부보다 표시 위치·선택 결과·논리 상태를 검증한다. 전체 게임 테스트를 무조건 반복하지 않고 변경된 이동·표현·입력·복원 경계와 기존 회귀를 선택한다.
