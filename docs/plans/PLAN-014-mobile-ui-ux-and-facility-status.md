# PLAN-014 모바일 UI·UX와 시설 상태 표시 정비

## 목표

사용자가 선택한 가로·세로 시안을 기준으로 연구소 관찰 → 대상 선택 → 조작 → 결과 확인을 짧게 연결한다. 아이콘으로 맵을 조작하고, 시설 위 진행바·상태 아이콘으로 생산 흐름과 대기 원인을 파악하며, 표시 ON/OFF를 선택할 수 있어야 한다. 기존 건설·물류·생산·배양·침공·저장·한 판 종료 규칙은 유지한다.

임시(Temp) 에셋으로 기능과 실제 모바일 사용성을 검증하는 development PLAN이다. 정식 아트는 사용자가 직접 제작하며, 그 교체·시각 검수는 사용자가 요청한 별도 `type: art` PLAN에서 진행한다.

## 범위

- 포함: 가로 우측 패널·세로 요약 카드/상세 패널, 상단 현황·하단 목적별 메뉴, 대상 선택·겹친 개체 후보·생명체 목록, 배치 모드와 뒤로 가기.
- 포함: 축소·확대·전체 보기 아이콘, 시설 위 회차 진행바·대표 상태 아이콘·상세 문구, 시설 상태 표시 ON/OFF와 독립적인 로컬 사용자 설정 보존.
- 포함: 아래 유스케이스의 정보·조작 경로 정비, 한국어 표시 문구와 필요한 글리프, 안전 영역·터치 크기·줌/팬·스크롤·방향 전환·입력 수명 검증.
- 포함: 교체 가능한 Temp_ 참조와 아트 인계 명세, 기존 자동 회귀·새 UI 경유 검사·Android APK·실기기 1종의 직접 UX 검증 및 이번 UI 변경의 비용 비교.
- 제외: 정식 아트 제작·다운로드·교체·최종 시각 검수, 정식 아트용 PLAN의 자동 생성/활성화, 새로운 콘텐츠·게임 규칙·레시피·밸런스·저장 스키마 변경.
- 제외: UI 프레임워크 전환·엔진/패키지 업그레이드·진단 씬 전면 개편·전체 현지화 시스템·온라인 설정·Google Sheets 연결·스토어 배포.
- 제외: 병목 개선 효과의 종합 판정, 장시간 반복·다기종/발열/배터리 종합 최적화, D-070 전체 완료 선언. 다만 이번 표시·입력 변경의 오류·조작 불능·명백한 성능 회귀는 범위 안에서 해결한다.
- 작업 요청·위임 근거: 2026-10-29 사용자가 최종 시안 기반 작성을 요청한 뒤, 추가 검토의 세 보완 사항 반영과 PLAN-014 실행을 명시적으로 승인했다. 가로·세로·아이콘·시설 상태 표시·운영 유스케이스를 임시 에셋으로 구현·검증하며 정식 아트 교체는 별도 PLAN으로 진행한다.

## 시안과 구현 기준

[선택된 최종 시안](references/PLAN-014/mobile-ui-ux-wireframe.png)은 2026-10-29 대화의 가로·세로 ON 화면, OFF 비교, 상태 아이콘 예시를 보존한 설계 참고다. `docs/plans/references/PLAN-014/`는 실행 증거와 구분한 참고 이미지 위치이며 Unity 에셋으로 임포트하지 않는다. 그림의 자원 수·진행률·시설 배치·아이콘 외형·여백은 예시다. 구현에서는 아래 상태 의미·조작 계약·검증 기준을 우선한다.

### 화면과 이동 경로

1. 상단에는 자원·개체 수·멸망 진행을 표시한다. 전체 보유량과 시설 도착량·운반 중 수량은 구분하고, 상세 내역은 필요할 때 연다.
2. 하단 진입점은 `건설 / 생명체 / 침공·보고`로 구성한다. 메뉴를 여는 것만으로 건설·배정·방출 명령을 실행하지 않는다. 일반 패널 열람은 게임 진행을 일시정지하지 않는다.
3. 가로는 맵과 우측 선택/관리 패널, 세로는 맵과 작은 선택 요약 카드로 구성한다. 상세 설정·목록은 펼치고 접는다. 두 방향의 기능과 명령은 같으며 요약에는 대상 이름·현재 작업/대기 이유·상세 진입을 우선한다.
4. 드래그 손잡이뿐 아니라 `상세 보기 / 접기 / 닫기`를 제공한다. 한 번에 열린 주 패널을 관리하고, 메뉴와 선택 전환에서 맥락·스크롤을 구분한다. 선택 대상이 가려질 때만 시야를 보정하며 사용자의 수동 팬을 반복해서 되돌리지 않는다.
5. 축소·확대는 돋보기 −/＋, 전체 보기는 맵과 네 모서리 프레임, 상태 표시는 눈/숨김 표식으로 구별한다. 2026-10-29 실기기 검토 요청에 따라 네 버튼은 작은 아이콘 표현을 사용하고 기능 이름은 게임 메뉴의 지도 조작 안내에서 확인할 수 있게 한다. 상태 켜짐/꺼짐은 눈/숨김 모양과 변경 피드백·설정 메뉴의 ON/OFF로 알려 색이나 길게 누르기만으로 의미를 전달하지 않는다. 가로에서는 도구막대를 상단 현황 옆에 두어 맵 아래 공간을 차지하지 않게 하며, 작은 시각 표현과 충분한 터치 영역을 분리한다.
6. 전체 보기는 **현재 가용 맵 영역**에 건설 영역을 맞춘다. 전체 화면 전환·게임 초기화가 아니며 선택·배치 초안·시설 상태를 바꾸지 않는다. 패널·안전 영역 변경 후에도 같은 좌표 변환을 사용한다.
7. 시설 이동은 명시적으로 배치 모드에 진입한다. 위치 탭은 미리보기만 바꾸고, 하단은 `취소 / 90° 회전 / 배치 확정`으로 바뀐다. 연구소 일시정지와 정면 작업 위치·유효/불가 이유를 표시한다. 외부 활동의 기존 시간 규칙은 유지한다.
8. 뒤로 가기는 가장 안쪽 후보/상세 → 열린 패널 → 선택 해제 순으로 처리한다. 배치 중에는 초안을 취소하고 기존 상태로 돌아간다. 기본 화면의 Back과 일반 패널 닫기가 새 판 시작으로 연결되지 않게 한다.
9. 상단의 게임 메뉴에서 `지금 저장 / 최근 저장 불러오기 / 새 판 시작`에 접근한다. 저장 성공·실패를 구분하고, 불러오기·새 판 시작은 현재 진행 교체와 저장 초기화 의미를 안내한 뒤 확인/취소한다. 취소는 현재 세션·선택·초안을 유지하며 실제 실행만 공통 명령으로 전달한다. 기본 화면 Back은 게임 메뉴를 열고, 이미 열린 메뉴에서 Back은 닫는다.

### 시설 위 상태 표시

시설 위 표시는 런타임의 실제 상태에서 파생한다. 오버레이와 선택 패널이 같은 조회 결과·Thing ID를 사용하며, UI 전용 생산 타이머나 자원·작업 규칙을 만들지 않는다.

| 상태 | 표시 계약 |
| --- | --- |
| 건설 중 | 건설 표식·건설 진행을 생산 회차와 구분한다. 자재 준비와 실제 시공을 읽을 수 있게 한다. |
| 채집 작업 중/대기 | 현재 채집 회차의 진행바. 실제 채집자가 없으면 보존된 진행률과 작업 대기를 표시하며 무인 자동 생산으로 표현하지 않는다. |
| 가공·배양 작업자 생산 | 현재 회차 진행바. 실제 생산 Job 수행 여부를 사용하며 배정 존재만으로 100% 작업 중이라 표시하지 않는다. |
| 가공·배양 저속 자동 생산 | 같은 회차 진행바 + 자동 표식. 바의 완료율과 20% 속도를 분리한다. 문구는 `자동 · 진행 60%`처럼 의미를 명시한다. |
| 재료 대기 | 재료 아이콘. 상세에 필요량·도착량·유효 공급 예정량을 구분하여 표시하며 정상 운반 대기를 모두 심각한 경고로 만들지 않는다. |
| 완료품 입고 대기 | 완료된 바 + 입고 대기 표식. 운반자가 집어 든 뒤에도 전량 실제 입고 전까지 유지하고 다음 회차 0%로 먼저 돌리지 않는다. |
| 작업 위치 접근 불가 | 막힌 경로 표식과 정지 이유. 진행도·완료품 상태를 보존하며, 겹친 원인이 있으면 대표 차단 이유와 상세 근거를 일치시킨다. |
| 배양 대상 미선택 | 선택 필요 표식. 이미 선택한 대상을 해제하거나 생산을 중지하는 새 기능은 추가하지 않는다. |
| 연구소 전체 일시정지 | 상단 공통 안내와 정지된 진행을 유지한다. 모든 시설에 개별 오류 경고를 반복하지 않는다. |
| 저장소 | 생산 회차가 없으므로 생산 진행바를 붙이지 않는다. 용량·허용 자원은 선택 패널에서 확인한다. |

- 바는 실제 현재 회차 완료율만 나타낸다. 같은 정의의 시설이라도 개별 진행을 독립적으로 표시하며 생산 대상 변경 후에도 현재/다음 회차를 혼합하지 않는다.
- 멀리서는 짧은 바·대표 아이콘, 가까이/선택 시에는 짧은 문구·정확한 수치를 제공한다. 맵 축소에 따라 판독 불가능하게 작아지지 않도록 최소 표시 크기를 정한다.
- 시설의 화면 점유 영역 위에 앵커를 잡고 회전·이동·줌·팬·가용 영역 변화와 함께 갱신한다. 밀집 시 문구부터 생략하고 표식 간 충돌을 처리한다. 다른 시설의 상태로 오인되거나 맵 밖으로 떠다니는 표시를 허용하지 않는다.
- 최저 줌·밀집 배치에서 대표 상태를 구분할 수 있어야 한다. 세부 수치가 생략된 경우 확대/시설 선택으로 확인할 수 있게 한다. 화면 밖 표시는 가리고 선택 표식·주요 조작을 덮지 않는다.
- 일반 관찰 모드에서 표시 위 탭은 해당 시설 선택으로 통일한다. 신규 건설·시설 이동의 배치 모드에서는 표식 위 탭도 터치한 Map 좌표의 미리보기 이동으로 전달하며 시설을 선택하지 않는다. 드래그·핀치는 같은 Map 제스처를 사용한다. 작은 아이콘마다 별도 명령 버튼을 만들거나 한 입력이 UI와 Map에 중복 전달되게 하지 않는다. 배치 조작은 표시 ON/OFF에 따라 달라지지 않는다.
- 2026-10-29 실기기 검토 보완: 첫 표식 탭은 시설 선택과 설명 펼치기, 같은 시설 표식의 재탭은 설명 접기/펼치기로 처리한다. 접으면 아이콘·진행바로 돌아가며 선택·상세 패널·스크롤은 유지한다. 확대 상태에서도 명시적으로 접은 설명을 자동으로 다시 열지 않는다. 이 선택은 현재 화면의 일시적 상태이며 세션 교체 후 초기화하고 게임 저장·전역 표시 설정에는 추가하지 않는다. 배치 모드는 이 전환을 실행하지 않는다.

### 표시 ON/OFF와 수명

- 카메라 아이콘 옆 전역 토글 하나로 시설 상태 표시를 켜고 끈다. 기본은 ON이며 아이콘·ON/OFF 상태·짧은 피드백으로 결과를 알린다. 문제 시설만 표시하는 추가 필터는 이번 범위에서 제외한다.
- OFF는 **시설 위 진행바·상태 아이콘·상태 문구**를 모두 숨긴다. 선택 패널, 선택 테두리, 필요한 배치 미리보기·작업 위치, 전역 일시정지 안내는 유지한다. 경고가 생겼다고 자동으로 다시 켜지 않는다.
- 선택한 설정은 회전·Home 복귀·앱 재실행·새 판 시작 뒤에도 유지한다. 기기 내 UI 환경설정으로 보존하고 게임의 1슬롯 진행 저장·CSV·DataHash·GameDataStore 정의와 분리한다. 설정 누락/잘못된 값은 기본 ON으로 복구하되 게임 저장을 건드리지 않는다.
- 방향 전환과 메모리가 유지된 복귀에는 선택·열린 패널·스크롤 문맥·초안·맵 초점을 보존하고 진행 중 포인터만 무효화한다. 프로세스가 종료된 재실행은 마지막 게임 저장을 복원하며 미확정 UI 초안의 영속 복원을 약속하지 않는다.
- 세션 교체·멸망 전환에는 이전 개체/목록/오버레이·누르던 명령을 해제한다. 새 판에서 이전 상태 표식이 남지 않으며 사용자 표시 설정만 유지한다.

## 임시 에셋과 별도 아트 PLAN

- 정식 아트는 사용자가 제작한다. 시안 이미지를 잘라 런타임 Sprite로 쓰거나 이를 정식 아트 제공본으로 취급하지 않는다.
- 신규 임시 아이콘은 축소·확대·맵 맞춤·표시 ON/OFF, 메뉴, 작업/자동/재료/입고/접근/선택/건설 상태의 실제 필요 목록을 실행 시 확정한다. 바·패널은 단순 도형으로 검증할 수 있게 하되 정식 외형의 참조 교체 지점을 남긴다.
- `Temp_` 에셋은 `Assets/Sprites/UI/` 등의 기능별 정규 경로에 배치한다. PPU 32와 임포트 기본값은 [아트 지침](../agents/art-assets.md)을 따르며 화면상 터치 크기와 Sprite 픽셀 크기를 분리한다.
- Sprite·폰트·프리팹/SO 등 에셋 바인딩으로 표현을 교체할 수 있게 한다. 임시 파일명·아이콘 모양·픽셀 크기로 명령이나 상태를 판정하지 않는다. 시설/생명체 아트와 상태 UI는 별도 참조로 유지한다.
- 실행 중 사용처·필요 규격이 정해지면 `UnityProject/Assets/Sprites/Require/PLAN-014/README.md`에 요청 ID·최종 파일명·크기/분할·Temp_ 경로·교체 참조를 기록하고 이 PLAN에서 연결한다. 아직 생성되지 않은 경로를 실제 요청/수령 완료로 기록하지 않는다.
- **이번 사용자의 명시적 지시에 따라 정식 교체는 별도 `type: art` PLAN 작성·실행 승인 후 수행한다.** 일반 독립 Sprite 절차로 이 경계를 우회하거나 제공 파일 도착만으로 PLAN-014에서 교체하지 않는다. 후속 PLAN 번호를 선점·자동 활성화하지 않는다.
- PLAN-014는 임시 에셋으로 필수 기능·UX 검증을 충족하면 completed로 판정할 수 있다. 정식 아트 수령/최종 시각 확인은 그 판정을 막지 않지만, 임시 아이콘 식별 불가·한글 누락·터치 실패는 미완료다.

- 최소 하나의 새 판을 초기 건설부터 생산·배양·방출·멸망·결과·다시 시작까지 새 UI로 직접 연결하고, 기존 두 판 자동 회귀를 유지한다. 상태별 재현 준비와 실제 사용자 입력의 증거를 구분한다.
- Android에서 드문 오류를 강제로 재현할 수 없으면 PC 실패 주입 증거와 기기의 확인 범위를 분리한다. 정상 UI 흐름·터치·회전·ON/OFF·재실행 설정 보존은 실제 기기에서 확인한다.
- UI 직접 성능 회귀의 재현 조건·허용 기준은 실행 초기 측정 전에 정해 기록한다. UI 때문에 조작이 끊기는 문제를 후속 종합 최적화로 넘기지 않는다.
- 실행 전 비교 조건: 같은 세션의 시설 20개(표시 대상 19개), 가로·세로, 최소/최대 줌과 표시 ON/OFF를 비교한다. 비용 측정은 1280×720·Fit·시뮬레이션 정지에서 오버레이 갱신 루틴을 OFF/ON 각각 60회 준비 후 120회 측정하며 ON−OFF 중앙값 증가 2ms 이내를 PC 참고 기준으로 삼는다. 이 값은 전체 프레임 시간이나 Android 성능 보증이 아니다. 반복 패널·토글·회전 10회와 새 판 3회에서 표시 객체 수가 증가하지 않아야 한다. 관리 힙 차이는 할당량으로 오인하지 않고 별도 관찰값으로 기록하며, 실제 기기에서 입력 지연·프레임 끊김을 추가 확인한다.

## 관련 결정과 상태 전환

- 2026-10-29: 미등록 → `proposed`. 사용자의 시안 기반 PLAN 작성 요청으로 등록했다. 실행 승인 없이 active로 전환하지 않는다.
- 2026-10-29: `proposed` → `active`. 사용자가 검토의 세 보완 사항 반영과 PLAN-014 실행을 명시적으로 승인했다. UC-05·17·23과 화면/입력/검증 계약에 반영하고 PLAN 목록·로드맵·기획 MAP을 동기화한다.
- 2026-10-29: `active` → `completed`. 임시 에셋의 기능·양방향 UI/입력·상태 조회/설정·새 APK·실기기 한 판/재시작·원상 복원과 UC-12 보완 검증을 마쳤다. 사용자 직접 확인·자동 검사·기기 관찰의 범위와 제한은 증거에서 구분한다. 다음 PLAN의 실행 승인은 없어 추가 PLAN을 활성화하지 않는다.
- 기존 TECH-010의 공통 명령·입력 수명·런타임 UI 구성은 유지한다. 표시 상태 공유·UI 설정·에셋 바인딩은 [TECH-011](../decisions/TECH-011-mobile-ui-state-and-assets.md)에 기록했다.
- 사용자가 정식 아트 교체를 별도 PLAN으로 지정했으므로 PLAN-014의 기능 완료와 분리하며 별도 art PLAN의 승인 절차를 따른다.
