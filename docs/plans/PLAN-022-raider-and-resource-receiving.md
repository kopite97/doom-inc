# PLAN-022 약탈형 배양·침공과 연구소 자원 수신

## 목표와 범위

플레이어가 공용 배양시설에서 **약탈형**을 선택해 배양하고 기존 침공형과 함께 방출할 수 있다. 같은 시간 동안 약탈형이 얻는 멸망 점수는 더 낮고, 약탈형은 외부 활동으로 얻은 자원을 연구소에 보낸다. 연구소는 기존 물류 예약을 보존하면서 자원을 실제 재고로 입고한다.

사용자가 확정한 내용은 새 모델의 이름·역할과 낮은 침공 위력이다. 다음은 실행 승인 시 적용할 프로토타입 제안값이다. 기존 배양 비용·시간을 약탈형에도 적용하고, 외부 활동 주기는 두 모델이 공유한다. 기존 소규모/주요 활동의 2/10점에 대응해 약탈형은 1/5점, 활동 3회마다 유기물 1개로 시작한다. 값은 JSON에서 조정한다. 신규 자원·맵별 스폰 테이블·고갈·귀환·최종 밸런싱은 별도 범위다. 임시 에셋과 텍스트로 구분하며 정식 아트 교체는 별도 PLAN에서 진행한다.

## 확장 구조 판단

| 경계 | 현재 제약과 선택 |
| --- | --- |
| 모델 정의·배양 | 현재 배양 대상은 None/Support/Invader 열거형이고 시설은 침공형 산출물 한 개를 가리킨다. 약탈형 SO를 생명체 Registry에 등록하고 같은 ID의 JSON과 결합한다. 역할은 기존 Invader를 공유한다. 배양 가능한 모델 ID 목록을 시설 정의에서 읽고 UI·명령·생산이 같은 목록을 사용한다. 진행 중 회차의 산출 모델과 다음 선택을 구분해 기존 변경·취소 규칙을 보존한다. |
| 외부 활동 | `InvasionManager`가 방출·활동 시계·완료 회차·성과 정산을 맡고, 모델의 행동을 직접 호출한다. 진행도와 회차는 개체별 `InvaderComponent`에 둔다. 이벤트를 사용한다면 정산 후 UI 알림에 사용한다. 보고 생략이나 구독자 수가 점수·지급 건수에 영향을 주지 않아야 한다. |
| 침공 행동 인터페이스 | 이번 구현에 `IInvaderActivityBehavior`를 도입한다. 단일 메서드 `InvaderActivityOutcome ResolveActivity(InvaderActivityContext context)`는 완료 회차·주요 활동 여부·모델 설정을 받아 점수와 선택적 보급품 요청(자원 ID·수량)을 반환한다. 같은 입력은 같은 결과를 내며 행동 자체는 점수·재고·저장을 변경하지 않는다. |
| 모델 확장 | 일반형은 `StandardInvaderBehavior`, 약탈형은 `RaiderInvaderBehavior`를 사용한다. 모델 ID와 행동 종류를 구분하고 초기 로딩에서 정의에 지정된 행동을 연결한다. 상태 없는 C# 구현체를 공유하며 수치만 다른 모델은 JSON 설정으로 같은 행동을 재사용한다. 새로운 효과는 행동 구현과 등록 지점에서 확장한다. |
| 연구소 수신 | 세션 소유 순수 C# 수신 객체가 전송 요청·대기·입고를 담당한다. 입력은 출처 ID·활동 회차·자원 ID·수량, 결과는 입고 완료·대기 등록·기존 대기로 미적립·이미 처리 중 하나다. 수신부는 침공 모델이나 보고 UI를 조회하지 않는다. 단일 로컬 수신 구현은 구체 클래스로 주입하고, 실제 대체 수신 방식이 생길 때 같은 계약의 인터페이스를 도입한다. 침공형의 인벤토리나 운반 Job을 경유하지 않는다. |

## 작업 목록

- [x] **정의와 배양.** 정의 ID 중복·누락, 미등록 자원·모델, 잘못된 점수·수량·주기와 SO 연결을 초기 로딩에서 검증한다. 약탈형을 배양 선택·출현·대기 수·일괄 방출에 연결하고 기존 침공형·보급형·선택 없음 경로를 보존한다.
- [x] **행동 연결과 활동 정산.** 초기 로딩에서 미등록 행동 종류를 거부한다. 일반형은 점수만, 약탈형은 낮은 점수와 지정 회차의 보급품 요청을 반환한다. 관리자가 개체별 완료 회차마다 연결된 행동을 한 번 호출해 점수를 반영하고, 요청에는 출처 개체 ID와 회차를 붙여 수신부에 전달한다. 긴 프레임에 여러 회차가 지나거나 여러 개체가 동시에 목표에 도달하면 동일 시각의 모든 결과를 기존 생성 순서대로 확정한 뒤 멸망으로 전환한다.
- [x] **입고와 대기.** 완공·품목 허용·실재고·기존 입고 예약을 반영한 가용량 판정을 물류와 공유한다. 실제로 한 회분 전체를 받을 수 있는 저장소를 안정된 순서로 골라 그곳에 재고를 생성하고 작업자에게 재고 변화를 알린다. 저장소 부재·포화·필터 차단 때는 개체당 최대 한 회분을 보류한다. 대기 중 새 전송 회차는 적립하지 않고 점수는 계속 얻는다. 공간·필터·시설 완공 등 수신 조건이 바뀌면 기존 대기부터 재시도한다. 같은 요청의 재처리로 중복 지급되지 않게 한다.
- [x] **시간·종료 경계.** 배치 편집 중에는 현행 규칙대로 외부 활동과 전송 발생만 진행하고 실제 입고는 편집 종료 후 처리한다. 평상시 목표 도달 회차에는 가능한 입고까지 확정하고 멸망 후에는 미입고분을 동결한다. 앱 정지·종료 시간에는 추가 정산하지 않고 새 판에는 이전 재고·대기 요청을 넘기지 않는다.
- [x] **저장 호환.** 현행 세션 v5와 데이터 해시 검사, 이전 버전 복원 분기를 먼저 확인한다. 알려진 기존 정의 해시와 버전에 한정해 배양 대상 값을 모델 ID로 이행하고 기존 침공 점수·보고·진행과 종료 상태를 보존한다. 임의 해시 불일치 허용은 금지한다. 새 저장에는 모델별 정산 기준, 회차와 대기 요청을 재고와 같은 스냅샷 경계에 보존한다. 지난 회차를 소급 지급하지 않으며 손상된 출처·중복 요청·수량은 거부한다.
- [x] **표시.** 배양 선택 시 두 모델의 점수와 전송 차이를 설명한다. 전과 보고가 생략되는 후반에도 실제 입고와 수신 대기를 구분해 확인할 수 있도록 기존 UI에 한국어·영어 키를 추가한다. 대기분을 보유 자원에 합산하지 않는다.
- [x] **점수 복원.** 활동 결과 계산·보고 검사·누적 점수 검증에 모델 설정을 받는 공통 점수 규칙을 적용한다. 복원은 저장된 회차로 점수를 검산하고 대기 요청을 복원한다. 과거 회차의 전송을 재실행하지 않는다.

## 검토 반영 사항
- 출처별 마지막 처리 회차는 미적립 회차까지 전진시킨다. 3회차 대기 → 6회차 미적립 → 3회차분 입고 → 저장·복원 후 6회차 재요청은 추가 지급이 없어야 한다.
- 편집 중 목표 도달 시 점수와 요청을 확정해 대기로 동결하고, 평상시에는 가능한 입고까지 처리한 뒤 종료 저장한다. 양쪽의 이어하기를 검사한다.
- 복원 계층이 출처·외부 상태·완료 회차·행동 결과를 대조해 일반형 출처, 미래 회차, 자원·수량 불일치를 거부한다. 수신부는 침공 모델을 조회하지 않는다.

## 완료 기준과 검증 방법

| 기준 | 실행할 검증과 증거 |
| --- | --- |
| 행동 계약과 연결 | 같은 입력을 반복해 결과가 같고 재고·점수가 바뀌지 않는지 검사한다. 제안값 기준 12회차는 주요 활동과 전송이 겹치므로 일반형은 10점만, 약탈형은 5점과 유기물 1개 요청을 반환해야 한다. 서로 다른 모델 ID가 설정값만 달리해 같은 행동을 재사용하는 경우와 미등록 행동의 로딩 실패도 검사한다. |
| 모델 조합과 기존 기능 | Edit Mode에서 일반형·약탈형 단독/혼합의 동일 회차 점수, 전송 주기 경계, 후반 보고 생략, 긴 시간 한 번/분할 진행, 목표 동시 도달의 합계·전송 건수를 대조한다. 기존 배양·운반·침공·종료 회귀를 포함한다. |
| 수신 책임의 독립성 | 침공 없이 요청을 넣는 테스트로 저장소 없음·미완공·필터·포화·기존 예약·복수 저장소·동시 요청을 검증한다. 공간이 생기면 대기분만 정확히 한 번 입고되고 기존 운반자가 예약량을 배달할 수 있어야 한다. |
| 저장·진행 경계 | 기존 버전 실제 형식의 고정 저장 사례와 새 저장을 복원한다. 배양 중, 전송 직전, 대기 중, 입고 직후, 결과 화면에서 반복 저장·복원해 재고·점수·모델·회차가 일치하고 새 판에 잔존하지 않는지 확인한다. |
| 실제 플레이 | Editor Play Mode와 실제 Editor 플레이에서 배양 대상 전환 → 두 모델 배양·혼합 방출 → 보고·재고 확인 → 입고 차단과 해소 → 이어하기 → 결과·새 판을 검증한다. 배치 편집·앱 일시정지 경계, 두 언어와 양방향 화면의 선택·대기 표시도 확인한다. |

검증 결과에는 실행한 Edit/Play 테스트 수, 실제 조작 순서, 회차별 예상/실제 점수·예약·재고·대기 수량, 저장 전후 결과를 연결한다. 사용자 요청에 따라 Editor 런타임 검증을 필수로 하고 플레이어 빌드·APK·실기기 검증은 제외한다.

## 현재 상황과 다음 행동

약탈형 배양·혼합 방출·수신 및 기존 저장 호환을 구현하고 Editor 검증을 마쳤다. 기존 임시 표현과 다국어 모델명을 사용했다. 신규 Sprite 요청은 없다.

## 검증 결과

최종 Edit Mode 358/358, Play Mode 66/66 통과. 별도 Editor 직접 실행에서 멸망 회차 입고와 편집 중 대기 동결, 결과 복원·새 판 초기화를 확인했다. 실행 환경·수량·초기 실패와 수정·원상 복원은 [검증 기록](evidence/PLAN-022/README.md), 구조 결정은 [TECH-007](../decisions/TECH-007-invasion-time-and-save-boundaries.md)을 따른다. 빌드 제외.
