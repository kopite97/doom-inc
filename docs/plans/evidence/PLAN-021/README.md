# PLAN-021 Editor 검증

[최종 대조](verification.json). Edit 351/351, Play 65/65 통과. 작업 완료와 재검색 기한의 직전·동시·직후, 사방 차단 및 가져오기 실패 시 기존 빌더 선택 복원을 [최종 Edit 실행](edit-complete.json)에 포함했다. 해당 테스트 어셈블리에 설치된 Addressables Editor 참조를 추가하고 재컴파일했다.

원래 CSV 복원 후 같은 내용으로 두 번 연속 가져온 [두 번째 결과](noop-2.json)까지 추적 에셋 diff가 비어 있었다. [원본 파일 7개](files-restored.json)의 SHA-256과 [Editor 종료 상태](environment-after.json)가 시작 상태와 일치했다. 현재 Editor 콘솔 오류·경고는 0개다. [누적 콘솔](console-final.json)에는 오류 복구를 검증하는 Play 회귀의 경고와 수정 전 테스트 어셈블리 참조 오류가 포함된다. 검증 범위는 Editor이며 빌드·실기기는 제외했다.

Unity 6000.3.27f1, Pipeline 0.9.1-exp.1, Unity CLI 1.0.0-beta.15에서 검증한다. 기준은 [PLAN-020 원본](../PLAN-020/analysis/README.md)과 그 실행에서 보존한 초기·중간·고부하 저장 파일이다. Editor 상태와 사용자 파일을 백업한 뒤 대체 테스트 슬롯을 사용했다.

## 수정과 비교 기준

- 셀 통행 조회에는 작은 맵의 시설 점유 인덱스를 사용한다. 시설 배치가 바뀌면 거리 트리를 비우고, 작업자의 이동은 거리 트리를 유지한다. 맵당 출발 칸을 최대 32개까지 보관한다. 4096칸보다 큰 맵에서는 기존 희소 탐색을 사용한다.
- 작업 가능한 후보를 추린 뒤 도달 거리와 생성 순서로 선택한다. 작업자는 목적지·현재 칸·맵 버전이 일치하는 동안 남은 경로를 사용한다. 작업 선택과 운반 목적지 재선택은 작업자별 판정 시점을 공유한다. 완료·명령·자원과 배치 변화에 반응하며, 같은 시뮬레이션 단계에서는 한 번 판정한다.
- 일반 탐색의 기본 간격은 게임 시간 0.2초, 실패 재시도는 0.5초다. 생성 순서에 따라 최대 15% 분산한다. 장시간 프레임 처리에서 지난 자동 탐색 주기를 몰아서 수행하지 않는다. 신규 세션과 복원 시 일시적인 탐색 상태를 재구성한다.
- 빈손이고 작업이 허용된 NoWork 개체는 대기 시작 칸과 인접 칸 안에서 이동한다. 배회는 이동 속도와 휴식 시간을 고려하고 인접 칸만 검사한다. 별도의 작업이나 예약을 생성하지 않는다.
- CSV 가져오기는 이미 선택된 Addressables Play Mode 빌더를 다시 설정하거나 Addressables 설정을 무조건 저장 대상으로 표시하던 처리를 제거했다. 기존 키·테이블 검증과 실패 롤백 검사를 유지한다.

## 증거와 재현

- [수정 전 기준](criteria.json)은 명령 응답 p95 100ms·최대 250ms, 프레임당 BFS 최대 256회와 부하별 비교 기준을 담는다. 측정값은 Editor에만 적용한다.
- [수정 전](bench-before.json)·[수정 후](bench-after.json) 같은 저장 상태를 독립 복원해 게임 시간 16ms 갱신 120회를 수행했다. 고부하 BFS 42,909→23회, 방문 칸 1,922,365→2,297개. 이 구간은 렌더링을 포함하는 실제 프레임 벤치마크와 별도다. [계측 입력](benchmark.cs.txt).
- [CSV 실패 재현](import-before.json). 첫 [Edit 회귀](edit-run.json)에서 배정 해제와 작업자 제거 직후 인계 지연 2개가 발견돼 작업 가용 상태 무효화를 보완했다. [후속 Edit 검사](edit-final.json) 346/346, [Play 회귀](play-regression.json) 65/65.
- [실제 Play 계측 입력](runtime.cs.txt)은 세 가지 저장 상태를 각각 30초 예열하고 60초 수집하며 3회 반복한다. 이어 20분 정상 배율에서 시설 건설과 작업 우선순위 명령을 처리한다. 건설은 작업자가 해당 건설 현장 Job을 획득한 시점, 우선순위는 대상 작업자가 변경된 우선순위로 판단한 시점을 관찰한다. 시각은 게임 시간이 아닌 실시간이며 합성 명령을 게임의 뷰 명령 경로에 전달한다.
- 실행 시 저장한 JSON과 같은 이름의 CSV를 함께 읽는다. [일반 간격 비교](control.cs.txt)는 실패 재시도는 유지하고 일반 간격만 해제한 Editor 진단 조건이다. [할당 샘플 입력](allocation.cs.txt)은 별도 Profiler 구간에서 호출별 관리 할당량을 확인한다. 추가 실험은 [동일 상태 비교](comparison.cs.txt)를 사용한다.

## 실제 Editor Play 반복 표본

PLAN-020의 동일 저장 파일과 같은 가로 해상도·정상 배율에서 상태당 3회 측정했다. 메인 스레드 p95에는 Editor 비용이 포함된다. 할당량은 GC Allocated In Frame의 중앙값이며 KiB 단위다.

| 부하 | 기존 p95 (ms) | 수정 후 p95 (ms) | 기존 할당 (KiB/프레임) | 수정 후 할당 (KiB/프레임) |
| --- | ---: | ---: | ---: | ---: |
| 초기 | 2.61~2.70 | 3.02~3.39 | 121.3 | 117.4 |
| 중간 | 6.84~7.23 | 3.80~4.71 | 697.8 | 146.1 |
| 고부하 | 489.67~536.78 | 4.55~4.84 | 18920.0~19484.0 | 202.7~202.8 |

초기 p95 증가는 사전 기준의 절대 편차 2ms 이내다. 고부하 3회 모두 워밍업 포함 약 90초 진행, 종료 점수 1088, 보고 20개였다. 이 비교는 후보 축소·거리 공유·탐색 간격 등 전체 수정의 결과다.

첫 장시간 관찰에서는 두 번째 검증용 저장소가 배양시설 상호작용 칸을 가렸다. [접근 불가 확인](interrupted-layout.json)과 [중단 구간](interrupted-progress.json)을 보존했다. [수정된 20분 관찰 입력](soak.cs.txt)은 동일 고부하 저장에서 시작하고, 건설 위치를 변경하여 각 건설 후 배양시설 접근 가능 여부를 확인한다. 이 재시작은 앞선 9개 성능 표본 이후에 이루어졌다.

## 장시간 운영과 간격 비교

- [20분 관찰](soak-complete.json)에서 실제 1200.002초에 게임 시간 1199.927초가 진행됐다. 내부 작업자는 정상 배양으로 24→34명, 외부 침공형 16명, 시설은 건설 명령으로 8→10개가 됐다. 건설 2건과 우선순위 변경 24건 모두 작업자 반응을 관찰했다. 명령 시작부터 반영까지 p95 8.41ms/최대 10.11ms, 예정된 입력 시각부터는 p95 10.49ms/최대 20.13ms였다. 프레임당 경로 탐색 최대 20회, 종료 시 조작 가능·저장 오류 없음. [실제 화면](laboratory.png).
- [실패 간격만 둔 90초 표본](failed-only.json)은 p95 4.50ms, 판단 7275회였다. 일반 간격을 함께 둔 3회는 4191~4294회였다. 경로 캐시가 이미 훨씬 큰 비용을 제거한 조건에서 일반 간격의 독립적인 프레임 시간 이득은 구분되지 않았다. 같은 고정 스텝 1200회에서도 1523→1003회로 판단이 줄었고 자원 총량은 모두 42였다. 시설 수를 고정한 5만 회 통행 비교에서 선형 순회는 작업자 4/24명일 때 10.53/22.34ms, 점유 인덱스는 1.30/1.29ms였다. [비교 기록](comparison.json).
- [호출별 Profiler 샘플](allocation-samples.json)에서 1MiB 배열 교정은 1048608바이트, 캐시가 있는 거리 조회는 6회 모두 0바이트였다. 첫 작업 선택 29140바이트, 물류 검사 10448바이트, 게임 갱신은 37948~793204바이트였다. 독립 복원 상태의 명시적 호출 샘플이며 전체 프레임 할당의 원인별 백분율로 사용하지 않는다.
- [실제 배회](live-wander.json)에서 초기 자원을 비워 준비한 단일 작업자가 세 번 걸었고 최대 반경은 한 칸, 경로 검색 호출은 0회였다. 모든 우선순위를 끈 뒤 4초 동안 제자리에 머물렀다.
- [원본에서 단독 CSV 재검사](import-after.json)는 1/1 통과했다. 실제 CSV의 연구소 제목을 두 언어에서 변경·가져온 뒤 [화면에 표시된 제목](translated-labels.json)을 확인하고 원래 CSV를 복원해 재임포트했다. 별도로 사용자 Play Mode 빌더를 다른 항목으로 선택한 상태에서는 [실패 롤백이 이전 선택을 잃는 현상](builder-rollback-before.json)도 발견했다. 빌더 선택은 패키지가 에셋 외부에 보관하므로 스냅샷에 명시적으로 담아 복원하고 전용 Edit 회귀에 추가했다.
