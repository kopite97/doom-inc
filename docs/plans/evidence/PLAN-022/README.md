# PLAN-022 검증 기록

Unity 6000.3.27f1 Editor와 Unity CLI 1.0.0-beta.15에서 실행했다. 플레이어 빌드와 실기기 검증은 제외했다.

| 검사 | 결과 |
| --- | --- |
| 컴파일·Edit Mode | [오류·경고 0](compile.json). [최종 358/358 통과](edit-final.json). [첫 실행](edit.json)에서는 예전 테스트가 직접 만든 생명체에 새 행동 설정이 없어 79개가 실패했다. 테스트 초기화와 침공형 픽스처를 수정한 뒤 모델 재사용과 기존 저장 복원까지 확인했다. |
| Play Mode | [첫 전체 검사](play.json)와 [최종 전체 검사](play-final.json) 모두 66/66 통과. 실제 Laboratory 씬의 격리 슬롯에 완공 시설과 배양 재료를 준비했다. 약탈형 배양 중 다음 대상을 일반형으로 변경하고 저장·복원한 뒤 두 모델을 배양·방출했다. 첫 세 회차의 총점은 9, 필터 차단 시 대기는 1건이었다. 두 언어·두 화면 방향에서 배양 버튼과 수신 대기를 확인하고 필터 허용 후 입고, Update 시간 진행, 결과·새 판까지 검사했다. |
| 수신·물류 | Edit에서 기존 운반 예약 5개를 보존해 첫 저장소에 모두 입고하고, 두 번째 저장소의 필터가 열린 뒤 보급품 1개를 입고했다. 별도 검사에서 3회차 대기 → 6회차 미적립 → 대기 해소·복원 → 6회차 재전달 순으로 검사해 재고가 1개임을 확인했다. |
| 저장 | 변경 전 코드로 생성한 [실제 v5 새 판](legacy-v5.json)과 [외부 침공형 16마리가 있는 v5 저장](../PLAN-020/fixture-2.json)을 새 코드에서 복원했다. 잘못된 출처, 미래·비전송 회차, 보상 종류·수량 변조를 거부했다. |
| 별도 Editor 직접 실행 | 일반형과 약탈형 각 1마리, 빈 저장소, 목표 9점인 [격리용 세션](live-start.json)을 준비했다. 방출 후 세 회차가 끝날 때 [평상시에는 대기 0·입고 1](live-final-admitted.json), [배치 편집 중에는 대기 1·입고 0](live-final-pending.json)이었다. 양쪽 모두 저장 오류 없이 멸망으로 전환했다. [평상시 결과 복원](live-continue-admitted.json)과 [편집 중 결과 복원](live-continue-pending.json)에서 점수와 수신 상태가 같았고 새 판에서는 두 경우 모두 수신 기록이 비었다. |

직접 실행은 Editor의 별도 SlotB에서 수행했다. 종료 후 SlotB 저장을 복원하고 원본 SHA-256과 대조했다. 실제 Gameplay 슬롯도 검증 전과 같은 해시였다. [실행 전](environment-before.json)·[종료 후](environment-after.json) 장면, dirty 여부, 시작 슬롯·이어하기·백그라운드 설정을 대조했다.
