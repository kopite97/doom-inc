# PLAN-008 초기 건설·수집·저장

## 목표

프로토타입 모델 1개체와 초기 유기물로 획득시설·저장소를 건설하고, 유기물 수집 → 운반 → 실제 입고를 반복하는 첫 플레이 흐름을 구현한다.
새 게임부터 공통 명령·실제 작업 진행으로 이 흐름을 실행하고, 중간 자동 저장·이어하기·다시 시작까지 화면과 하네스에서 확인한다. 로드맵 1단계이며 전체 게임 사이클 완성과 구분한다.

## 범위

- 포함: 선배치 시설 없는 실제 시작 구성, 프로토타입 모델 1개체와 두 시설을 건설할 초기 유기물. 저장소 건설 전에도 초기 자원을 사용할 수 있는 전달·소유 경로.
- 포함: 유기물·프로토타입·획득시설·범용 저장소의 필요한 정의·실행 상태, 시설 지정·배치·건설 자원 처리·자동 건설·사용 가능 전환.
- 포함: 현재 작업에 필요한 Job·이동·경로 탐색·작업 선택, 기본 프리셋과 개체별 우선순위 설정, 실제 수집과 시설의 회차·완료품 입고 대기.
- 포함: 저장 용량·허용 자원 설정, 운반량·대상 선택·출고/입고 예약·부분 운반·정상 작업 유지·경로/시설/허용 설정 변경 예외와 제외 재고 재배치.
- 포함: 기존 시설 이동·회전·연구소 일시정지와 새 작업의 연결, 새 상태·관계의 저장·복원·초기화, PC 가로 화면에서 조작할 최소 플레이 화면과 상태 표시.
- 제외: 배양액·가공시설·공용 배양시설의 실제 운용, 보급형 배양·배정·20%/100% 생산 전환, 침공·전과 보고·멸망 사이클. 이들은 로드맵 2~3단계다.
- 제외: 추가 콘텐츠·해금·철거/환불·복잡한 건설 편집 기능, 범용 작업 프레임워크, 정식 아트 제작·최종 UI·세로 대응·Android 빌드/실기기·성능 최적화.

2026-10-26 사용자가 “PLAN승인할게. 작업 시작해줘.”라고 실행을 승인하여 유일한 `active` PLAN으로 전환했다. 완료된 PLAN은 재활성화하지 않는다.
시설 4종 전체의 기획은 유지하되 이 단계의 플레이 대상은 획득시설·저장소다. 콘텐츠 수 제한·강제 건설 순서·해금 조건을 새 게임 규칙으로 추가하지 않는다.
비용·용량 등 개발 위임 상세는 승인 후 구현하면서 정한다. 먼저 새 기획 항목이나 전체 클래스 목록을 확정하는 작업으로 확대하지 않는다.

## 구현 순서와 경계

1. **초기 상태와 정의:** 초기 유기물의 실제 보관처·건설 사용 경로와 두 시설 비용을 정하고 신규 시작에 연결한다. 지급량은 두 시설 건설을 충족해야 하며 선배치·무료 생성·숨은 추가 지급으로 시작 흐름을 우회하지 않는다.
2. **행동과 공간:** 현재 작업에 필요한 Job·경로·이동·선택을 구성한다. Map의 시설 점유와 고정 상호작용 위치를 공유하고, 접근 불가·생명체 중첩·시설 변경을 처리한다. 우선순위 프리셋·개체별 설정·동률 목록 순서를 연결한다.
3. **건설:** 플레이어의 시설/위치 지정에서 자원 처리·개체 작업·시설 사용 시작까지 연결한다. 필요한 자원과 작업이 끝나기 전에는 기능을 사용할 수 없다. 완료한 시설의 무료·즉시 이동과 새 건설을 구분한다.
4. **수집과 물류:** 실제 작업시간과 시설 회차를 연결한 뒤 수집 완료품의 운반·실제 입고를 구현한다. 시설 회차 상태는 개체 Job과 분리하며, 집기·일부 수량의 입고만으로 전량 입고 완료로 처리하지 않는다. 대체 저장소 여러 곳에 나눠 보내더라도 전량이 실제 입고되면 해당 회차를 완료한다.
5. **예외와 설정:** 용량·허용 목록·동시 예약·대상 선택·시설 이동·경로 차단에 따른 유지/해제/재예약·보유 대기를 연결한다. 정상 운반을 새 작업 때문에 끊지 않으며, 입고가 막혔다고 자원을 버리지 않는다.
6. **화면·저장·검증:** 위 각 기능 추가와 함께 저장 계약·공통 조회·검증을 확장한다. PC 화면에서 초기 건설·작업/저장 설정·이동/회전·상태 확인·이어하기·재시작을 실행하고 통합 결과를 남긴다.

단계는 구현 순서이며 저장·하네스를 마지막에 처음 추가하라는 뜻이 아니다. 생명체 여러 개와 시설 여러 곳을 사용하는 검사 준비 상태는 실제 시작 개체 수나 콘텐츠를 늘리지 않는다.
운반 대상은 현재 위치에서 가까운 공급처를 먼저, 그 공급처에서 가까운 유효 목적지를 선택한다. 장애물을 피한 최단 경로와 최초 생성 순서를 사용하고 예약분을 제외한다.
허용 자원 설정은 현재 유기물 한 종류에서도 변경·기존 재고 재배치·기존 입고 예약 즉시 반영을 검증한다. 출고 예약 유지와 집기 전/후 예외는 물류 원문을 따른다.
배치 편집 중에는 이동·건설·수집·운반 진행을 멈추고 작업·예약을 보존한다. 확정한 배치 변경을 경로·작업에 반영한 뒤 재개하며, 취소·확정으로 종료된 판을 재개하지 않는다.

## 구현 때 결정할 상세

- D-059 범위: 시설 크기·건설 영역·비용·건설 시간·초기 지급 위치/수량, 저장 용량·운반량·이동 속도·동시 작업 인원·우선순위 기본값. 실제 시작 흐름을 검증할 최소값으로 두고 근거를 기록한다.
- 건설 자원 소비/전달 시점·미완성 시설의 공간 표현·작업 단계, 경로 알고리즘·갱신 순서·컴포넌트와 API 구성은 구현에서 결정한다. 미완성 상태가 배치/자원 규칙을 우회하거나 시설을 중복 완성시키지 않게 한다.
- 시설이 생명체 위치를 덮거나 이동 중 경로가 바뀌는 기존 허용 배치와 경로 시작 상태를 함께 검토한다. 단순히 새 배치 금지나 순간 이동 규칙을 추가해 피하지 않는다.
- 저장의 상태 소유자를 구분하고 건설 자원 처리·수집 진행/회차·아직 입고되지 않은 완료품·Job 대상/단계·운반물·예약·우선순위/허용 설정을 보존한다. 경로 캐시 등 파생 정보는 재계산할 수 있지만 정상 운반·진행도를 초기화하지 않는다.
- 저장 버전 확장과 기존 진단 슬롯의 호환/거부 방침을 기술 결정에 남긴다. 손상/미지원 저장을 자동 덮어쓰지 않고, 후보 전체 검증 후 세션 교체·쓰기 실패 시 정상 파일 보존을 유지한다.

중요한 책임·자료구조·저장 계약 선택은 `docs/decisions/`에 기록한다. 위임 범위를 넘는 게임 규칙 변경이 필요하면 그 항목을 분리해 사용자와 논의한다.

테스트 저장 경로는 플레이 슬롯과 격리한다. PC 결과를 Android 실기기·최종 양방향 UI 검증 완료로 표현하지 않는다.

## 아트와 완료 판정

기능 확인에 필요한 임의 에셋은 영어 `Temp_` 이름과 교체 위치를 기록한다. Sprite를 사용하면 PPU 32와 승인된 임포트 기준을 따른다.
실행 종료 시 새로 제작·교체할 Sprite가 필요하면 `UnityProject/Assets/Sprites/Require/PLAN-008/README.md`에 명세를 작성하고 이 PLAN에서 연결한다. 지금은 요청 규격·파일·폴더를 미리 만들지 않는다.
`development` PLAN이므로 정식 아트 미수령·사용자 시각 검수 대기는 기능 완료를 막지 않는다. 필수 기능·검증 미완료를 아트 대기로 대신하지 않으며, 독립 아트 수령·적용은 기존 절차로 이어간다.

종료 확인: `Temp_Laboratory`의 임의(Temp) 도형·문자는 Unity 기본 텍스처로 표시하며 Sprite 에셋을 추가하지 않았다. 신규·교체 Sprite 요청이 없어 Require 폴더를 만들지 않았다. 정식 아트·사용자 시각 검수 완료를 뜻하지 않는다.
