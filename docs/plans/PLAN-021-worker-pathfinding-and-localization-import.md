# PLAN-021 작업자 경로 탐색 최적화와 번역 CSV 반복 가져오기 안정화

## 목표와 범위

작업자 수가 늘어도 건설·운반·배정 명령에 반응하도록 반복 탐색을 줄인다. 별도의 Editor 수정으로 같은 번역 CSV를 다시 가져왔을 때 기존 에셋의 내용이 안정적으로 유지되게 한다. 사용자 요청에 따라 두 문제를 한 PLAN에서 추적하되 변경과 검증 결과는 독립적으로 기록한다.

기준은 [PLAN-020 측정 결과](evidence/PLAN-020/analysis/README.md), [구현 로드맵](../game-design/05-development/02-implementation/roadmap.md), [운영 병목](../game-design/02-systems/04-optimization/bottlenecks.md), [저장·운반](../game-design/02-systems/02-logistics/storage-and-transport.md), [보급형 운용](../game-design/02-systems/05-creatures/support-models.md)이다. 실행 시 [아키텍처](../agents/architecture.md), [추상화 기준](../agents/abstraction.md), [Localization](../agents/localization.md), [하네스](../agents/harness.md), [검증](../agents/verification.md), [Unity 도구](../agents/unity-tools.md)를 따른다.

검증 범위는 Edit Mode와 실제 Editor Play다. 빌드·실기기, 아트·UI 재설계, 작업자 수 제한과 게임 밸런스 변경은 제외한다. 신규 Sprite 요청은 없다.

## 수정 전 탐색 주기

[LaboratoryManager.Advance](../../UnityProject/Assets/Scripts/Gameplay/Session/LaboratoryManager.cs)는 전달된 게임 시간을 최대 0.05초 조각으로 나누고 조각마다 작업자를 갱신한다. 0.016초가 들어오면 즉시 한 번, 0.2초가 들어오면 한 프레임 안에서도 여러 번 처리한다. 별도의 경로 검색 타이머는 없다.

[WorkerManager.Tick·Move](../../UnityProject/Assets/Scripts/Gameplay/Creature/WorkerManager.cs)는 유휴 작업자와 이동 중인 비운반 작업자의 일감을 재평가할 수 있다. 거리 조회와 이동은 각각 경로를 구하며, 이동에서는 다음 칸으로 갈 시간이 쌓였는지 검사하기 전에 경로를 구한다. `MoveSecondsPerCell`은 한 칸 이동 시간이다. [물류 예약 검사](../../UnityProject/Assets/Scripts/Gameplay/Logistics/LogisticsManager.cs)도 도달 가능성을 조회하므로 작업 선택만 늦췄을 때 남는 호출까지 구분해 측정한다.

## 작업 목록

- [x] **일감이 없는 작업자의 근거리 배회.** 보조형 운용의 대기 규칙에 이번 배회 조건을 반영한다. 작업이 허용된 빈손 작업자가 `NoWork`로 잠시 대기하면, 처음 대기한 칸과 그 상하좌우 한 칸 범위 안에서 가끔 인접한 통행 가능 칸으로 한 걸음 이동한다. 같은 대기 중 재검색에 실패하거나 한 걸음 옮겨도 기준 칸을 유지한다. 짐이나 운반 예약이 있으면 기존 운반 절차를 따르고, 입고처가 없는 운반자와 작업이 모두 비활성화된 유휴 작업자는 제자리에서 대기한다.
- [x] **배회와 탐색의 분리.** 배회는 인접 칸의 통행 여부만 확인하고 기존 이동 속도를 따른다. 갈 칸이 없으면 다음 배회 기회까지 쉰다. 배회 한 걸음의 완료·차단은 작업 완료 사유를 발생시키지 않으며 일반 탐색·실패 재시도 기한을 갱신하지 않는다. 새 일감·명시적 배정·재시도 만료가 배회와 겹치면 현재 확정된 칸에서 작업 판정을 먼저 수행한다. 새 작업이 생기면 남은 배회를 취소한다.

- [x] **기준 측정.** PLAN-020의 동일 저장 상태에서 작업 선택·이동·예약/유효성 검사별 탐색 호출 수, 방문 칸 수, 메인 스레드 p95와 프레임당 할당량을 기록한다. 진단 카운터는 저장 데이터와 분리하고, 원인별 할당은 Unity Profiler 표본으로 확인한다.
- [x] **후보와 경로 계산.** 작업 유형·재료·선점 여부로 가능한 후보를 먼저 거른다. 한 작업 선택에서 같은 출발 칸의 후보 간 거리 계산을 공유하고, 실제 이동에는 선택한 경로의 남은 칸을 재사용하는 방안을 단계별로 측정한다. 기존 거리·생성 순서의 동률 처리와 이동 속도를 보존한다.
- [x] **일반 자동 탐색 간격.** 첫 일감은 즉시 탐색한다. 작업을 선택한 뒤 비운반 작업자가 목적지로 가는 동안 다른 후보를 자발적으로 다시 비교하는 빈도에는 작업자별 최소 간격을 둔다. 그동안 유효한 경로로 이동을 계속한다. 목표 도착 시 첫 작업 직전의 우선순위 확인, 작업 완료 후 다음 일감 선택, 아래의 상태 변경은 간격을 기다리지 않는다. 작업 중인 생명체가 주기가 지났다는 이유로 작업을 중단하지 않도록 한다.
- [x] **실패한 자동 탐색 간격.** 일감·경로·입고할 저장소를 찾지 못하면 실패 재시도 간격을 적용한다. 특히 짐을 든 작업자의 물류 예약 검사에서도 같은 조건의 목적지 재검색을 제한한다. 예약 유효성 확인과 무효 예약 해제는 즉시 수행하고 운반 중인 재료의 소유권을 보존한다.
- [x] **간격 결정.** 두 간격은 게임 시간으로 계산한다. 작업자별 검색 시점을 분산하고 긴 프레임 뒤 지난 주기의 검색은 한 번으로 합친다. 동일한 고부하 저장 상태에서 실패 간격만 적용한 경우와 일반 간격도 적용한 경우를 비교한다. 호출 수·프레임 p95·명령 반영 시간·생산 및 입고량을 보고 각 간격 값을 결정한다.
- [x] **칸 통행 조회 비용.** [GridMap.GetBlockingFacility](../../UnityProject/Assets/Scripts/Core/Spatial/GridMap.cs)는 통행 여부를 확인할 때 배치 목록을 순회한다. 시설 수를 고정하고 작업자 수를 바꿔 같은 출발지·목적지에서 탐색당 통행 조회 횟수와 소요 시간을 측정한다. 비용이 크면 시설 점유 칸을 직접 조회하도록 한다. 배치 확정·이동·회전·제거 및 복원 때 점유 정보를 갱신하고, 미리보기·취소와 작업자의 한 칸 이동은 다른 작업자의 경로를 무효화하지 않아야 한다.
- [x] **즉시 반응과 수명.** 배정·우선순위 변경, 건설 지정, 재료 도착·예약 해제·저장 허용 변경은 영향받는 작업자의 재평가를 다음 유효 갱신에서 깨운다. 시설 이동·회전, 목표 소실, 막힌 다음 칸은 경로를 즉시 무효화한다. 운반 중인 재료·예약과 이동 누적 시간은 도메인 상태로 유지하고, 경로·재시도 시계는 새 판과 복원 시 다시 구성한다.
- [x] **CSV 반복 가져오기.** 깨끗한 설정 에셋에서 [실패 검사](evidence/PLAN-020/edit-localization-repeat.json)를 재현한다. [EnsureSetup](../../UnityProject/Assets/Scripts/Editor/Localization/LocalizationCsvTools.cs)에서 Fast Mode 빌더 인덱스가 실제로 바뀔 때만 설정을 쓰고 불필요한 dirty 표시를 제거한 뒤 같은 검사를 실행한다. 계속 실패하면 테이블 적용·변경 알림·저장·롤백 경계의 등록 내용과 해시를 대조해 최초 변경을 찾는다. 해시 비교를 제외해 통과시키지 않는다.

### 주기 만료와 행동 완료가 겹칠 때의 처리

일반 자동 탐색에도 작업자별 최소 간격을 필수로 적용한다. 일반 재평가와 실패 재시도는 직전 탐색 결과에 따라 하나만 예약한다. 행동 완료 시 다음 일감을 고르는 요청은 남은 간격을 기다리지 않는다.

1. 일반 주기 만료, 실패 재시도, 행동 완료, 명령·환경 변화는 작업자별로 사유만 모은다. 작업 선택과 물류 목적지 재탐색은 기존 세션 갱신 안에서 같은 판정 지점을 거친다. 여기서 한 번은 후보를 비교해 결정을 내리는 횟수를 뜻하며, 그 안의 경로 조회 횟수는 별도로 계측한다.
2. 입고·건설·채집의 완료 효과와 예약 정리를 먼저 확정한다. 최신 배정·우선순위와 자원 소유 상태를 읽어, 짐이 남으면 운반 목적지를 판단하고 행동이 끝났으면 다음 일감을 판단한다. 명령·상태 변경과 완료가 겹쳐도 최신 조건으로 한 번만 결정한다. 완료 전 행동에 속한 만료 요청은 함께 소비한다.
3. 작업자당 시뮬레이션 하위 단계마다 최대 한 번 판정한다. 이미 판정한 뒤 같은 단계에서 행동이 완료되면 완료 사유를 다음 단계의 첫 판정에 넘긴다. 선택한 작업에는 이전 행동이 이미 사용한 시간만큼의 이동·생산을 다시 적용하지 않는다.
4. 실제 판정 시각에서 결과에 맞는 다음 일반 또는 실패 기한을 다시 잡는다. 이전 작업의 타이머가 뒤늦게 새 작업을 재선택하거나 긴 프레임에서 누적된 만료 횟수만큼 검색하지 않도록 한다. 새 판·복원 시 이전 세션의 대기 사유도 폐기한다.

## 완료 기준과 검증 방법

| 검증 | 합격 근거 |
| --- | --- |
| 유휴 배회 | Edit/Play에서 빈손·작업 허용·일감 없음 조건의 한 걸음과 반복 시 거리 제한을 확인한다. 사방이 막힌 경우, 짐을 들고 입고 대기 중인 경우, 작업 비활성 상태에서는 이동 0회여야 한다. 배회만으로 발생한 전체 경로 탐색·추가 작업 선택은 0회이고 재시도 기한은 같아야 한다. 배회와 새 명령이 겹쳐도 작업 판정은 한 번이며 실제 현재 칸에서 선택한다. 20분 고부하 관찰에 배회를 켜고 명령 반영 시간과 탐색 횟수를 대조한다. |
| 주기·완료 경계 | 일반 주기 만료 직전·동시·직후에 행동을 완료하고, 이미 판정한 단계에서의 완료도 재현한다. 다음 일감을 처음 선택할 수 있는 단계에 판정 1회, 기존 기한에 의한 추가 판정 0회여야 한다. 실패 재시도와 저장 공간 확보가 겹치는 경우, 부분 입고와 우선순위 변경이 겹치는 경우에도 짐·예약·입고량과 경과 시간이 한 번만 반영되는지 확인한다. |
| 재검색 간격·즉시 반응 | 일감이 없거나 목표에 도달할 수 없는 작업자는 조건 변화가 없으면 최소 간격 내 자동 재검색 0회, 만료 후 첫 유효 갱신에 1회여야 한다. 간격 도중 새 건설 지정이나 막힘 해소가 발생하면 영향받는 작업자는 다음 유효 갱신에 한 번 재평가한다. 같은 갱신에 여러 변경이 겹치거나 여러 주기가 지난 경우에도 중복 검색이 없어야 한다. |
| 일반 자동 탐색 | 동일한 목표·경로로 여러 칸 이동하는 동안 일반 간격 안에서 주기적 후보 재비교는 0회이고 이동 누적 시간은 계속 증가·소비된다. 간격 만료 시 재비교가 필요한 작업자는 한 번만 평가한다. 도착 직전 우선순위 변경과 작업 완료 직후 다음 작업 선정을 검증한다. |
| 입고 대기·통행 변경 | 저장소가 가득 찬 상태에서 짐을 든 운반자의 간격 내 동일 목적지 재검색은 0회다. 공간 확보 또는 허용 자원 변경 후 다음 유효 갱신에 한 번 재평가하고 실제 입고까지 재료 수량·예약을 대조한다. 시설 이동·회전 후 통행 판정은 배치 원본과 일치하고, 다른 작업자의 이동만으로 경로를 재계산한 횟수는 0회여야 한다. |
| 체감 응답 시간 | 수정 전에 기준 표본을 수집하고 Editor에서 허용할 명령 반영 시간과 프레임당 탐색 횟수 상한을 수치로 기록한다. 고부하에서 건설 지정·우선순위 변경 입력 시점부터 대상 작업자의 상태 변경까지 실제 경과 시간(ms)의 p95·최댓값과 긴 프레임 직후 한 프레임에 집중된 탐색 횟수를 측정한다. 20분 관찰에도 같은 상한을 적용한다. |
| 작업 선택·운반 회귀 | 기존 우선순위와 거리 동률 선택, 복수 작업자의 선점, 이동 중 우선순위 변경, 막힘 해소, 재료 운반 중 저장·복원, 새 판을 Edit/Play에서 확인한다. 작업자 대기 간격이 있어도 새 일감·명시적 명령을 놓치지 않고 비용·입고량·생산 진행이 기존 규칙과 일치해야 한다. |
