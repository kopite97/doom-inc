# PLAN-027 연구소 바닥 Tilemap·시설과 개체 SpriteRenderer 전환

## 목표

연구소의 바닥은 Tilemap, 시설·생명체와 지도상의 자원 표현은 SpriteRenderer로 표시하고, HUD·메뉴·팝업·상태 정보는 기존 uGUI로 유지한다. 기존 배치·선택·운영·저장 동작과 제공 아트의 규격을 보존하면서 이후 아트를 연결할 표현 기반을 정리한다.

주목적은 표현 구조의 전환이므로 `type: development`다. **현재는 `proposed`이며 구현·에셋 변경·설치·게임 테스트를 시작하지 않는다.** 선행 PLAN-026은 2026-11-10 `completed`이며 현재 active는 0개다. 이 후보는 별도 활성화 승인을 기다린다.

## 범위

- 포함: 바닥 Tilemap, 시설·생명체·운반 자원 표시, 정식 아트가 없는 기존 종류의 대체 표현 이관, 선택·건설/이동 미리보기·상호작용 칸 표시.
- 포함: 연구소 전용 직교 카메라와 지도 표시 영역, 화면↔월드↔논리 칸 좌표 변환, 기존 지도 제스처와 UI 입력 우선권, 월드 위치에 연결되는 uGUI 상태 표식.
- 포함: 기존 아트·획득시설 상태별 재생 계약 보존, 씬/공용 구성/생성 도구 연결, 표시 객체 수명, 영향받는 Editor 검증과 같은 조건의 전환 전후 비교.
- 제외: 게임 규칙·시설 점유·경로 탐색·Thing ID·자원 소유·밸런스 JSON·저장 형식 변경, 신규 콘텐츠·정식 원화 제작, 전체 UI 재작성, 범용 렌더링 프레임워크.
- 제외: Unity/외부 에셋 업그레이드, 렌더 파이프라인 교체, 새 조명·그림자·후처리, TilemapCollider/Physics 기반 게임 판정, RuleTile·Atlas·Aseprite 임포트 방식의 추가 도입. Pixel Perfect Camera는 아래 적합성 판단만 포함하며 필수 도입으로 정하지 않는다.
- 제외: PLAN-025의 기존 큰 글씨 안내 잘림·전역 GC 최적화 후보. 이번 전환이 만든 표시·입력·성능 회귀는 이 PLAN에서 처리한다.
- 제외: Android APK/AAB·Addressables 콘텐츠·PC Player·Player 스크립트 컴파일·IL2CPP 빌드 및 설치·실기기 검증. 이 전환본에 대한 별도 빌드 요청·승인이 없으며 PLAN-025의 승인을 재사용하지 않는다.
- 요청 근거: 2026-11-07 사용자가 “바닥은 Tilemap, 시설·개체는 SpriteRenderer, UI는 uGUI로 유지하는 전환 계획을 PLAN-027로 작성”하고 실행하지 않은 `proposed` 유지를 명시했다.

## 전환 설계

### 1. 표현 책임과 상태 소유

| 대상 | 사용할 표현 | 유지할 계약 |
| --- | --- | --- |
| 연구소 바닥 | Grid + Tilemap + TilemapRenderer | 논리 Map 영역에 바닥 4종 배치. 바닥은 가장 아래에 표시하며 프레임마다 재생성하지 않음 |
| 시설·생명체 | Thing별 SpriteRenderer 표시 객체 | 시설 하나에 외형 하나. 점유 칸마다 시설 그림을 반복하지 않음. 같은 종류도 개체별 위치·표시 상태는 독립 |
| 지도에서 보이는 자원 | 머리 위 받침점에 연결한 별도 SpriteRenderer | 실제 운반 자원의 종류에 따라 한 슬롯의 Sprite를 교체. 소유와 무관한 재고 더미·새 지상 자원 개체를 만들지 않음 |
| 선택·점유·배치 미리보기·접근 칸 | 지도 좌표에 맞춘 월드 표시 | 유효/무효와 확정 전/후를 구분. 논리 판정은 기존 명령·Map을 사용 |
| HUD·메뉴·설정·팝업·목록 아이콘 | 현재 Screen Space Overlay uGUI/TMP | 번역·글씨 크기·Safe Area·기존 연출과 입력 차단 유지 |
| 상태 아이콘·게이지·문구·연결선 | 월드 앵커를 투영하는 uGUI | 지도 배율과 별도로 읽기 가능한 화면 크기, 상태 ON/OFF·표식 선택 유지 |

Map/Thing/Job은 상태의 원본으로 유지한다. Tilemap 점유나 Sprite bounds·Collider로 배치·경로·선택 규칙을 다시 만들지 않는다. 저장에는 렌더러·카메라·Unity 객체 참조를 추가하지 않는다.

좌표 변환·카메라 제어·월드 표시·상태 UI 연결은 각각 바뀌는 이유가 달라 책임을 나눈다. 확인된 교체 요구에 필요한 구체 클래스와 참조 전달로 시작하고, 이중 렌더러를 영구 지원하는 인터페이스·전역 Manager·변경 가능한 static 캐시는 선행 도입하지 않는다. 코드 배치는 기존 `Assets/Scripts/Presentation/Gameplay/Laboratory/` 책임과 대조해 정하며 새 하위 분류가 필요하면 실제 생성 시 기록한다.

### 2. 픽셀·논리 칸·월드 좌표

- 공통 Sprite 임포트는 아트 지침의 **PPU 32 / Point / Compression None**을 유지한다. 원본 리사이즈·피벗 임의 변경으로 전환 비용을 줄이지 않는다.
- 바닥 64×64픽셀을 논리 1칸으로 연결하는 기본안은 **Grid cell size 2×2 Unity 단위**다. 128×128 시설은 4×4 단위로 2×2칸, 64×64 개체는 2×2 단위, 32×32 자원은 1×1 단위가 된다. 원본 전체 캔버스 기준이며 불투명 영역·터치 영역·실제 점유는 구분한다.
- 논리 좌하단 원점과 월드 원점, 칸 중심의 반 칸 오프셋, Tilemap tileAnchor·Sprite pivot·시설 회전 중심을 명시한다. 스케일은 한 변환 경계에서 관리하고 카메라·그림·입력마다 별도 보정 상수를 두지 않는다.
- `논리 칸/중심 ↔ 월드 위치 ↔ 화면 픽셀 ↔ uGUI 로컬 좌표`의 변환과 지도 경계 판정을 공유한다. 시설의 기준 칸·회전·점유 크기는 Map 결과를 읽고, 3×2 저장소의 회전도 포함한다.
- 기존 좌표 해시와 70/10/10/10 가중치를 유지한다. 비율을 맞추려고 같은 칸의 무늬를 재추첨하지 않는다. 씬 재진입·확대/축소·회전·이어하기 후에도 같은 바닥 배치를 재현한다.

### 3. 카메라·표시 영역·픽셀 선명도

- 기본안은 연구소 씬이 소유하는 **전용 직교 월드 카메라 + 현재 uGUI Overlay**다. 카메라의 culling/sorting layer, 출력 영역, clear/background 설정을 실제 렌더 파이프라인과 대조한다. 기존 카메라·AudioListener 중복과 Title/Loading/결과 화면으로의 지도 노출을 방지한다.
- 최종 UI 레이아웃의 MapViewport 화면 사각형을 카메라 viewport에 연결한다. 가로/세로·Safe Area·패널/큰 글씨 변경 후 카메라 비율·전체 보기·입력 변환·상태 표식을 같은 갱신 순서로 맞춘다. 크기가 0이거나 화면 밖인 전환 중 영역은 안전하게 비활성화한다.
- 기존 RectMask2D는 월드 Sprite를 잘라 주지 않는다. 불투명 MapViewport Image가 카메라를 덮지 않도록 역할을 조정하고, 월드 지도는 카메라 출력 영역, 상태 uGUI는 UI 마스크로 각각 경계를 지킨다. 카메라 바깥의 이전 프레임 잔상도 확인한다.
- 전체 보기·중심 제한·선택 대상 자동 이동·연속 핀치/휠/버튼 확대를 유지한다. 줌 수치만 복사하지 않고 화면에 보이는 칸 범위와 핀치 중심의 논리 위치가 전환 전후 대응하도록 맞춘다.
- Pixel Perfect Camera는 기존 URP/Renderer·가변 viewport·PPU와 연속 줌의 양립 여부를 판단해 채택/유보 이유를 기록한다. 이번 기본안은 연속 줌 보존이며 정수 배율 고정·검은 여백·화면 잘림을 조용히 추가하지 않는다. 카메라 Pixel Perfect가 Overlay UI까지 보장한다고 가정하지 않는다.
- RenderTexture→RawImage 경로는 기본안에 포함하지 않는다. 카메라 viewport 방식에 실제 제약이 확인되면 메모리·리사이즈·입력 좌표·선명도 비용을 대조해 대안을 기록하고 영향이 있는 범위를 다시 정한다.

### 4. 입력·표시 순서·시설 동작

- 입력은 기존 Input System·제스처 인식·게임 명령을 재사용하고 좌표 어댑터를 변경한다. 지도 영역 밖·HUD·팝업·스크롤 목록 위의 입력이 지도 선택/배치로 통과하지 않아야 한다.
- 상태 표식 선택 우선권, 같은 칸에 겹친 시설/개체 후보의 순서·순환, 화면 밖 대상 선택 시 이동을 유지한다. 화면의 그리기 순서를 게임 선택 순서로 대체하지 않는다.
- 기존 Feel·DOTween의 방출 화면 피드백·선택 대상 자동 이동이 참조하는 좌표와 대상을 새 카메라/지도 구조에 맞춘다. 효과음·피드백의 사건당 1회 실행과 중단/정리 계약을 유지하고 새 연출 종류는 추가하지 않는다.
- 드래그/핀치 뒤 탭 오인 방지, 두 손가락 중 하나를 뗀 뒤 연속 조작, 화면 방향/viewport 변경·포커스 상실·일시정지 중 제스처 취소를 보존한다. 기존 줌 범위와 경계 동작은 활성화 시 기준 화면과 함께 기록한다.
- 바닥·시설/개체·운반 자원·배치 표시의 sorting 규칙을 정하고 겹친 개체에 안정적인 순서를 부여한다. 같은 대상의 여러 Sprite를 함께 정렬해야 할 때만 SortingGroup을 사용한다. 아래쪽 기준점과 회전한 시설의 기준점을 검증하고 원본 픽셀 크기로 정렬 기준을 추측하지 않는다.
- 네 방향 시설 회전, 유효/무효 미리보기, 이동 확정/취소, 점유와 입구를 유지한다. 미리보기는 실제 시설·재고를 이동시키지 않으며 취소 후 기존 위치·표시·시간 흐름을 복구한다.
- 획득시설과 프로토타입은 PLAN-026에서 적용·확인한 재생 계약을 새 표시 경로로 옮긴다. 현재 시설 r003은 Idle/Working/Complete 각 12프레임이며 실제 수집/산출 사건에 연결한다. 프로토타입은 방향당 Idle 4·Move 6·Work 6, 상하좌우 총 64프레임·12태그와 머리 위 자원 합성 계약을 보존한다. 이동 구간·작업 대상에 따른 방향 선택, 대기 시 마지막 방향, 방향만 변경 시 반복 진행률 유지를 포함한다. 최종 프레임·시간·방향별 받침 좌표는 요청 README를 기준으로 다시 확인하며 일시정지·복원·중복 효과 방지·개체별 독립 재생을 유지한다. 새 동작 종류나 게임 진행 타이밍은 추가하지 않는다.
- 누락 참조와 미제공 종류도 선택·상태 확인이 가능한 기존 대체 표현을 월드 경로에서 제공한다. 정상 경로에 과거 칸별 Image/TMP 지도를 숨겨 유지하지 않는다. 설명/상태 문구는 필요할 때 uGUI로 남기고 로컬라이즈된 내용을 사용한다.

### 5. 에셋 연결·갱신·수명

- 기존 PNG·Sprite GUID·하위 Sprite 식별자·Aseprite 원본을 보존한다. 월드 그림과 목록 아이콘 참조를 구분하되 같은 원본의 런타임 복제본이나 Require 영구 참조를 만들지 않는다.
- 머리 위 운반 표시의 기본 구성은 개체 루트 아래 `Body`와 `CarryAnchor`를 형제로 두고, `CarryAnchor` 아래 `CarrySprite` 하나를 연결하는 안이다. 명칭은 제안이며 아직 생성하지 않았다. 몸체 애니메이션의 스케일·반전을 자원에 전파하지 않고 필요한 받침점 위치 움직임만 연결한다. 개체별 앵커와 자원별 표시 크기/위치 보정으로 하단을 맞추며 원본 피벗을 임의 변경하지 않는다.
- 기존 `ResourceDefinition`의 `Icon`과 결합된 `ResourceData.Assets.Icon`을 첫 자원 그림 공급원으로 사용한다. UI용/운반용 그림이 실제로 달라져야 할 때만 에셋 참조를 분리하며, 자원 ID별 코드 분기나 캐릭터별 자원 목록을 중복 작성하지 않는다. 표시 슬롯은 해당 개체가 소유하고 자원 종류 변경 시 참조를 바꾼다.
- 표시 판정은 현재 운반 연결(`WorkerJob.ResourceId`·해당 `TransportReservation`의 집기 상태)과 자원 Thing의 실제 보관처·잔량을 함께 확인한다. 예약만 있거나 무관한 시작 지급 재고를 보유한 경우 표시하지 않는다. 집은 자원이 남아 있는 대기·경로 변경·부분 전달에서는 유지하며 전달/소비 완료·개체 제거 때 해제한다. 이어하기에서는 복원된 상태로 다시 구성하고 Sprite/앵커를 저장 필드로 추가하지 않는다.
- 한 종류 운반 규칙을 유지해 자원 표시 슬롯은 하나로 시작한다. 머리 위 자원과 상태 UI의 배치·겹친 개체 sorting·지도 경계 마스크를 함께 대조한다. 누락 Sprite는 잘못된 다른 자원 그림을 남기지 않고 기존 대체 표시 정책을 적용한다.
- Tile·프리팹·표현 설정이 필요하면 에셋 종류별 정규 위치에 만들고 실제 경로·역할을 기록한다. 원본과 머티리얼을 복제해 객체마다 소유하게 하지 않는다. 씬·공용 AppConfiguration·SO·생성 도구가 같은 구성을 제공하도록 맞춘다.
- 씬/에셋 생성 도구가 재실행되어도 제공본·애니메이션·카메라 구성을 유지해야 한다. 구형 uGUI 바닥/칸 표시 참조를 정리하되 다른 UI 사용처를 먼저 조사하고 GUID와 기존 요청 이력을 보존한다.
- 바닥은 맵/아트 구성이 바뀔 때 갱신하고, Thing 표시 객체는 ID로 생성·갱신·해제한다. 매 프레임 전체 오브젝트 재생성이나 칸별 전체 배치 검색을 새 경로로 그대로 옮기지 않는다. 먼저 실제 변경 부분의 할당·갱신 비용을 확인하며 전역 시뮬레이션 최적화로 확장하지 않는다.
- 카메라·월드 루트·상태 UI·이벤트/연출은 연구소 화면/세션의 명시적인 소유 아래 정리한다. 시설 제거·개체 방출·멸망·새 판·Title 왕복·저장 복원 때 이전 ID의 표시·구독·연출이 남지 않아야 한다.

실행 증거는 활성화 후 `docs/plans/evidence/PLAN-027/`에 실제 결과가 생길 때 생성한다. 테스트 결과·로그·비교 화면·참조 변경·측정 조건과 미검증 항목을 연결하고, 작성 시점에 가상 증거 폴더를 만들지 않는다. 빌드·실기기는 필수 완료 조건에서 제외하며 그 한계를 최종 기록에 남긴다.
