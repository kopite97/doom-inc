# 게임 개발 사전준비 점검표

생명체를 배양하고 연구소를 운영하는 콜로니 시뮬레이션의 사전 제작 범위를 한눈에 확인하는 목록이다. 2026-11-23에 [게임 개발 사전준비 대화](https://chatgpt.com/c/6b03882a-710c-83ec-b8b3-cea4ebcd41bb)의 5개 영역·18개 분야를 현재 프로젝트 자료와 대조했다.

**현재 위치**는 기존 자료를 찾고 준비할 결과물을 파악한 단계다. 표의 기존 자료에는 확정 규칙, 기획 초안, 과거 개발 절차가 함께 있으므로 각 원문의 상태를 따른다. 준비 항목은 제안이며, 사용자가 정한 제품 방향과 검증 결과는 해당 원본에 기록한다.

## 분야별 준비 현황

[시설에서 여러 개체 선택·개체 옆 아이콘으로 개별 지시](../game-design/experience/interface.md#재활용-지시)를 시설별 대기열에 연결했다. 같은 예약을 받을 시설이 여러 곳이면 [시설별 대기 수량을 보고 목적지를 선택](../game-design/experience/interface.md#예약을-받을-시설-선택)한다. [재활용을 예약한 개체](../game-design/systems/creatures.md#배양-결과와-유니크-개체)는 자기 차례가 오면 [현재 작업을 마친 뒤](../game-design/systems/work.md#작업-중단과-자기-보충) 선택한 시설로 스스로 이동한다. 재활용 시설은 예약 순서를 지켜 앞선 개체가 배달을 마치고 도착할 때까지 기다린다. [즉시 재활용과 개별 예약 취소](../game-design/systems/creatures.md#배양-결과와-유니크-개체)를 연결표에 반영했다. 즉시 지시하면 짐을 그 자리에 내려놓고 출발한다. 처리 시작 전에 A만 취소하면 B가 차례를 이어받는다. 시설이 비어 있고 A가 아직 배달 중이면 즉시 지시한 B가 먼저 들어가고 A의 예약은 다음 차례로 유지된다. |

[추출 재료](../game-design/systems/production.md#첫-프로토타입의-추가-생산시설)는 플레이어가 선택하며 미선택 상태에서는 가동하지 않는다. 목재는 건설과 추출에 쓰고, 버섯은 같은 양의 목재보다 훨씬 많은 생체 원료를 낸다. [식물과 버섯](../game-design/systems/resources.md#초기-자원-구성)은 자연적으로 다시 자란다. 공통 4단계 이후 생명체 보유 코스트 상한은 첫 중계기 완공 때 한 번만 늘어난다. | 보통은 중앙 원료로 추출기를 해금한다. 먼저 소진하면 먼 채취지의 소량 비재생 원료를 가져와 연구를 이어갈 수 있다. 테스트에서 해금 전에 먼 채취가 얼마나 자주 필요한지 확인한다. 플레이 테스트에서 가까운 채취지의 재성장을 기다리는 선택과 먼 곳에서 운반하는 선택을 관찰하고, 성장 속도·재료별 추출량·소비량·소요 시간을 조정한다. |

| [8. UX](../agents/pre-production/experience/ux.md) | 2026-11-25 첫 프로토타입의 핵심 진행 UX 기획 정리 완료. [운영 방침](../game-design/experience/interface.md#작업-우선순위-설정)에서 개체별 작업 중요도를 정한다. 중요도가 같은 작업 종류는 왼쪽부터 살피고, 개체와 상호작용해 [작업 종류와 대상을 골라 한 건을 강제로 지시](../game-design/systems/work.md#강제-작업-지시)할 수 있다. 지시를 받으면 하던 일을 즉시 중단하며, 옮기던 물건이나 환자는 그 자리에 내려놓는다. 수행 중에는 **강제 작업 취소**가 가능하며 완료하거나 취소하면 기존 작업표를 따른다. [대화 중 일시정지와 첫 배양 지시](../game-design/experience/interface.md#첫-프로토타입의-시작-대화와-첫-지시), [모든 시설에 공통으로 쓰는 상호작용 아이콘](../game-design/experience/interface.md#시설-상호작용-아이콘), [배양시설의 주된 이유 아이콘과 마우스를 올렸을 때의 수량 표시](../game-design/experience/interface.md#배양시설의-대기-이유-아이콘)를 확정했다. 화면 밖 시설이 보유 상한 대기에 들어가면 게임을 계속하면서 한 번 알리고, 알림에서 해당 시설을 확인할 수 있다. [재활용 예약 전 대상 확인](../game-design/experience/interface.md#재활용-지시)은 한 마리와 여러 마리 모두 선택한 대상을 한 번에 확인하고 수정할 수 있게 한다. [첫 습격 알림](../game-design/experience/interface.md#탄생-알림과-자동-일시정지)이 뜨면 현재 시점을 유지하고, 알림에서 습격 위치로 이동해도 플레이어가 직접 재개할 때까지 게임은 멈춰 있다. [첫 방어 후 회복시설이 없어 구조를 기다리는 경우](../game-design/experience/interface.md#첫-방어-후-구조-대기-알림)에는 게임을 계속 진행하면서 개체 위치와 이유를 한 번 알린다. 현재 [이벤트 알림 등급](../game-design/systems/events.md#이벤트-알림-등급)에서 중앙 경고와 자동 일시정지를 쓰는 경우는 적대 생명체의 연구소 진입뿐이다. 모든 이벤트 알림은 [메시지 로그](../game-design/experience/interface.md#메시지-로그)에서 다시 읽을 수 있다. 알림창과 로그 모두 대상이 있으면 위치로 이동할 수 있고, 대상이 없으면 이동 버튼이 비활성화된다. | 처음 플레이하는 사람이 휴대용 도구를 보고 조수를 선택하는지, 원료 채취와 투입을 보며 기다리는지 관찰한다. 시설 배양에서는 운반을 맡은 뒤의 아이콘 변화를 보고 기다리는지, 원료 부족·보유 상한일 때 이유와 수량을 확인해 다음 행동을 고르는지 본다. 플레이 테스트에서 다른 곳을 살펴본 뒤 강조된 대상을 다시 찾아 안내를 이어갈 수 있는지 관찰한다. 구조자와 환자를 직접 골라 이송을 시작하고 필요할 때 지시를 취소할 수 있는지도 확인한다. 화면 배치·강조 표현·입력 편의와 접근성은 UI 구현과 플레이 테스트에서 다듬는다. |

## 결과물을 어디서 찾을지

## 언제 어느 깊이까지 준비할지

1. **프로토타입 착수 전** — 비전, 대상, 플랫폼 가정, 핵심 조작·반복 흐름, 사용할 수 있는 시간·예산과 검증 질문을 모은다. 예컨대 “처음 보는 사람이 생명체의 대기 이유를 알아내고 운영 방침을 바꿀 수 있는가?”를 검토할 수 있다.
2. **프로토타입에서** — 임시 자산으로 핵심 재미·조작감·시스템 상호작용·기술 위험을 확인한다. 플레이어가 실제로 한 행동과 막힌 지점을 관찰해 다음 설계에 반영한다.
3. **본격 제작 전** — 검증된 대표 구간을 목표 품질로 완성하는 버티컬 슬라이스에서 화면·아트·소리·콘텐츠 제작 과정을 함께 확인한다. 제작 속도를 근거로 기술 구조·콘텐츠 분량·일정·품질 기준을 구체화한다.
4. **제작 중** — 밸런스 수치, 배치, 애니메이션 타이밍, 효과·UI 세부 표현을 플레이 테스트로 조정한다. 출시 계획과 검증 항목도 대상 플랫폼과 실제 결과에 맞춰 갱신한다.

이 구분은 결정에 필요한 증거를 모을 시점을 제안한다. 이 프로젝트에서 기획 마무리·비용과 재미 검토·기존 구현 검토·공통 경계 결정·단계별 개발의 순서는 [기획 지침](../agents/game-design.md)을 따른다.

## 다음 대화에서 시작할 일

먼저 비전 문서에 쓸 재료를 모은다. 기존 문서에서 장르·배양·자율 행동·연구소 운영 경험을 발췌하고, 사용자에게 **가장 즐겁게 플레이할 사람**, **그 사람이 이 게임을 다시 켤 이유**, **프로젝트에 쓸 수 있는 시간과 제작 여건**을 확인한다. 이 답을 바탕으로 분야별 우선순위를 정한다.

준비 항목을 다룰 때마다 결과물 링크와 남은 질문을 해당 행에 갱신한다. 보류·해당 없음은 이유와 다시 살펴볼 시점을 적는다. 실제 제품 규칙의 확정·제안·미정·개발 위임은 담당 기획 문서에서 관리한다.
