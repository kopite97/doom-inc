# 게임 개발 사전준비 점검표

생명체를 배양하고 연구소를 운영하는 콜로니 시뮬레이션의 사전 제작 범위를 한눈에 확인하는 목록이다. 2026-11-23에 [게임 개발 사전준비 대화](https://chatgpt.com/c/6b03882a-710c-83ec-b8b3-cea4ebcd41bb)의 5개 영역·18개 분야를 현재 프로젝트 자료와 대조했다.

**현재 위치**는 기존 자료를 찾고 준비할 결과물을 파악한 단계다. 표의 기존 자료에는 확정 규칙, 기획 초안, 과거 개발 절차가 함께 있으므로 각 원문의 상태를 따른다. 준비 항목은 제안이며, 사용자가 정한 제품 방향과 검증 결과는 해당 원본에 기록한다.

## 결과물을 어디서 찾을지

원 대화에 나온 10종의 산출물에 해당하는 자료를 아래처럼 묶는다. 여러 원본을 한 산출물로 읽을 수 있으며, 상세 내용은 해당 원본에서 갱신한다.

| 산출물 | 활용할 원본 또는 다음 초안 |
| --- | --- |
| ① 게임 비전 문서 | [게임 방향](../game-design/direction/overview.md)을 바탕으로 1~3번의 대상·재미·차별점·제약을 한 장에 정리 |
| ② 게임 기획서(GDD) | [기획 MAP](../game-design/README.md)과 대표 플레이 흐름 |
| ③ 시스템 상세 기획서 | MAP이 연결하는 개별 시스템 문서와 [미정 사항 색인](../game-design/management/open-questions.md) |
| ④ 레벨·성장 설계서 | 맵 비교도와 성장·연구·자원 문서 |
| ⑤ UX/UI 설계서 | 화면과 상호작용 문서, 사용자 흐름도, 대표 화면 배치도 |
| ⑥ 아트·사운드 가이드 | 대표 장면 스타일 시트와 상황별 소리 표, 기존 제작 지침 |
| ⑦ 기술 설계서(TDD) | 합의한 범위에 맞는 기술 결정과 데이터·저장·성능 기준 |
| ⑧ 콘텐츠 명세·제작 계획 | 콘텐츠 유형별 예시·수량·제작 공수와 준비 순서 |
| ⑨ 개발 로드맵·검증 계획 | 개발 로드맵, 단계별 확인 질문·관찰 방법, 실행 시 해당 PLAN |
| ⑩ 출시·운영 계획서 | 제품·시장 검토를 토대로 한 배포·판매·지원 계획 |

## 언제 어느 깊이까지 준비할지

1. **프로토타입 착수 전** — 비전, 대상, 플랫폼 가정, 핵심 조작·반복 흐름, 사용할 수 있는 시간·예산과 검증 질문을 모은다. 예컨대 “처음 보는 사람이 생명체의 대기 이유를 알아내고 운영 방침을 바꿀 수 있는가?”를 검토할 수 있다.
2. **프로토타입에서** — 임시 자산으로 핵심 재미·조작감·시스템 상호작용·기술 위험을 확인한다. 플레이어가 실제로 한 행동과 막힌 지점을 관찰해 다음 설계에 반영한다.
3. **본격 제작 전** — 검증된 대표 구간을 목표 품질로 완성하는 버티컬 슬라이스에서 화면·아트·소리·콘텐츠 제작 과정을 함께 확인한다. 제작 속도를 근거로 기술 구조·콘텐츠 분량·일정·품질 기준을 구체화한다.
4. **제작 중** — 밸런스 수치, 배치, 애니메이션 타이밍, 효과·UI 세부 표현을 플레이 테스트로 조정한다. 출시 계획과 검증 항목도 대상 플랫폼과 실제 결과에 맞춰 갱신한다.

이 구분은 결정에 필요한 증거를 모을 시점을 제안한다. 이 프로젝트에서 기획 마무리·비용과 재미 검토·기존 구현 검토·공통 경계 결정·단계별 개발의 순서는 [기획 지침](../agents/game-design.md)을 따른다.

## 다음 대화에서 시작할 일

먼저 비전 문서에 쓸 재료를 모은다. 기존 문서에서 장르·배양·자율 행동·연구소 운영 경험을 발췌하고, 사용자에게 **가장 즐겁게 플레이할 사람**, **그 사람이 이 게임을 다시 켤 이유**, **프로젝트에 쓸 수 있는 시간과 제작 여건**을 확인한다. 이 답을 바탕으로 분야별 우선순위를 정한다.

준비 항목을 다룰 때마다 결과물 링크와 남은 질문을 해당 행에 갱신한다. 보류·해당 없음은 이유와 다시 살펴볼 시점을 적는다. 실제 제품 규칙의 확정·제안·미정·개발 위임은 담당 기획 문서에서 관리한다.
