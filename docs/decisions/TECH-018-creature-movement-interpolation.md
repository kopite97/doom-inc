# TECH-018 생명체 이동 관찰과 화면 보간

- 날짜: 2026-11-12
- 상태: 채택·구현·Editor 기능 검증 완료. 실행 PLAN은 빌드·고부하 제외 조건으로 completed다. 추가 CPU 비교는 미완료이며 기존 전체 화면 비용의 증가와 측정 한계는 유지한다.
- 결정 주체·위임 근거: 승인된 PLAN-028의 논리/표현 분리·이동 표시 개선 범위 안에서 개발 위임으로 선택한다. 새 게임 규칙·밸런스·저장 계약은 정하지 않는다.
- 실행 계획: [PLAN-028](../plans/PLAN-028-creature-movement-interpolation.md)
- 기준 기획: [이동·운반·예약](../game-design/02-systems/02-logistics/storage-and-transport.md), [공통 Map·즉시 재배치·정지](../game-design/02-systems/03-space/placement.md), [Thing·표현 분리·저장](../game-design/05-development/01-architecture/thing-model.md), [입력·종료](../game-design/03-player-experience/03-interface/controls.md).
- 관계: [TECH-017](TECH-017-laboratory-world-rendering.md)의 Tilemap·SpriteRenderer·월드 카메라와 uGUI 투영을 유지하고 생명체의 표시 위치·게시·수명 계약을 보완한다. 렌더러 전환을 대체하거나 uGUI 몸체 경로를 복구하지 않는다.

## 문제와 제약

논리 칸이 확정될 때만 몸체를 옮기면 생명체가 한 칸씩 순간 이동해 보인다. 작업 이동은 초 단위 MoveProgress와 캐시 경로가 있지만 유휴 배회는 이웃 칸으로 즉시 Place하므로 같은 진행률을 사용할 수 없다. 화면의 이전/현재 칸 차이만으로 보간하면 배회·재배치·복원·한 프레임의 복수 이동을 구별하지 못한다.

논리 점유·경로 탐색·작업/자원 처리 시점은 기존 게임 로직이 소유한다. 몸체·운반물·테두리·입력이 같은 표시 상태를 읽어야 하며, 경로 변경과 정지·이어하기·세션 교체에서도 낡은 구간과 화면 좌표를 재사용하지 않아야 한다. 적용 대상은 TECH-017의 단일 SpriteRenderer 경로다.

## 결정

### 읽기 전용 이동 관찰

[WorkerComponent](../../UnityProject/Assets/Scripts/Gameplay/Creature/WorkerComponent.cs)와 [WorkerManager](../../UnityProject/Assets/Scripts/Gameplay/Creature/WorkerManager.cs)에 현재 유효 구간을 읽는 WorkerMoveSegment와 마지막 확정 이동을 읽는 WorkerMoveObservation을 둔다. 표시가 Move·Place·Advance를 호출하거나 Job·예약·게임 경로 캐시를 수정하지 않는다.

- 구간 조회는 같은 세션/Thing/Map 소속, 논리 원점, 이동 Job 단계·대기 이유, 대상의 현재 상호작용 칸, RouteGoal·RouteVersion·인덱스와 다음 칸의 인접성/통행 가능성을 검사한다. 초 단위 진행률과 한 칸 시간은 유한한 유효 범위여야 한다. 낡은 경로·잘못된 시간값을 Clamp로 숨기지 않는다.
- 정상 표시 좌표는 논리 칸 A와 다음 칸 B에 대해 `A + (B - A) * (MoveProgress / MoveSecondsPerCell)`로 계산한다. 정상 칸 경계의 진행률 0과 의미가 같은 Job 재생성은 새 이동 시작으로 취급하지 않는다.
- 성공한 실제 이동에서만 순번·이전/새 칸·시뮬레이션 시각·배회 여부·지도 버전을 관찰한다. 마지막 한 건만 보유하며 저장하지 않는다. 배회의 논리 Place 시점·선택 주기·이동 규칙은 유지한다.

### 화면 소유 위치와 제한된 보정

LaboratoryMapView의 ThingArt가 개체별 일반 C# 객체 CreatureMotion을 소유한다. CreatureMotion은 시뮬레이션 시각과 읽기 전용 관찰로 소수 지도 좌표·이동 여부·표시 방향을 평가하고, 렌더러별 좌표 보정은 그 결과에 한 번 적용한다. 전역 관리자·싱글톤·범용 렌더러 계층은 만들지 않는다.

- 배회는 실제 확정 시각부터 기존 한 칸 시간 동안 이전 칸에서 새 칸으로 표시한다. 이 경로의 최대 한 칸 표시 지연과 논리 이동 시점은 구분한다.
- 배회→작업·경로 재지정·진행률 재설정은 마지막으로 게시한 위치에서 연결한다. 최근 유효 구간의 끝점과 현재 논리 칸을 거치는 직교 구간만 사용해 모서리를 대각선으로 자르지 않는다. 첫 보정 시작 시 `correctionEnd = 현재 시뮬레이션 시각 + 한 칸 시간`을 고정하고 최신 목표가 바뀌어도 종료 시각을 계속 미루지 않는다. 표시 보정 속도의 일시적 차이는 논리 속도와 처리 시점을 변경하지 않는다.
- 실제 관찰 없는 불연속 재배치·새 세션·복원, 기존 표시 구간의 차단은 안전한 현재 위치로 재정렬하는 예외다. 긴 Advance에서 여러 칸을 지난 경우 최신 유효 구간을 바로 표시하며 과거 구간을 큐로 재생하지 않는다.
- 위치·배회·보정·애니메이션은 연구소 시뮬레이션 시각으로 평가한다. 정지 중에는 시간 진행을 추가하지 않고 줌/팬/방향 변경에 따른 투영만 갱신한다. 매 프레임 목표에 다시 Lerp하는 추종이나 벽시계 Tween을 같은 위치에 겹쳐 적용하지 않는다. 이 선택은 [현재 상태값 표시 기준](../agents/presentation-effects.md)에 따른다.
- 이동 중에는 표시 구간의 방향과 Move를 사용한다. 모서리의 방향 변경만으로 반복 프레임 시간을 초기화하지 않는다. 표시 도착 전 Work를 보류하되 실제 논리 작업은 지연시키지 않는다. 몸체·기존 머리 앵커의 운반물·선택 테두리·대체 표현은 같은 위치를 공유한다.

### 복원 초기 조회와 게시 순서

경로가 없는 복원 직후에는 기존 논리 칸·Job·MoveProgress로 초기화한다. 이미 유효한 게임 경로가 있으면 재사용한다. 진행 중인 복원 개체의 첫 표시에서만 표시용 경로 재구성을 최대 한 번 허용하며 성공과 실패를 모두 기억한다. 조회는 게임 경로·예약·진행률을 준비하거나 변경하지 않는다. 이후 조건이 달라졌다는 이유로 매 프레임 재조회하지 않고 게임 로직이 경로를 준비하기를 기다린다. 구간이 아직 없으면 논리 위치를 안전한 초기값으로 사용한다.

[LaboratoryView](../../UnityProject/Assets/Scripts/Presentation/Gameplay/Laboratory/LaboratoryView.cs)가 LateUpdate에서 UI 갱신 뒤 Map의 PublishFrame을 명시적으로 호출한다. [LaboratoryMapView](../../UnityProject/Assets/Scripts/Presentation/Gameplay/Laboratory/LaboratoryMapView.cs)는 카메라/지도 투영 확정 → 개체 위치 평가 → 몸체·운반물·테두리 → 겹침·상태 표식 → 클릭 범위 게시 순서를 소유한다. 별도 MonoBehaviour의 LateUpdate 호출 순서에 의존하지 않는다.

- 입력은 마지막으로 게시해 사용자가 본 몸체/운반물의 화면 영역으로 생명체 후보를 찾는다. 시설의 논리 칸 후보와 합치고 시설 우선·생성 순서·기존 후보 순환을 보존한다. 배치/건설은 논리 칸을 사용한다.
- 게시 후 viewport·원점/배율·변환 행렬·Canvas 배율·화면/안전 영역·세션 세대가 달라지거나 UI가 입력을 차단하면 오래된 범위를 사용하지 않는다. 선택 전달 전 ID의 현재 등록·배치 상태를 다시 확인한다. 이동 전 논리 칸에 별도 생명체 클릭 영역을 남기지 않는다.
- 표시 접지 y와 CreationOrder로 순서를 정한다. 몸체 프레임의 흔들림은 정렬 기준에 넣지 않는다. 정지 시설의 상태 표식은 기존 위치가 유효하면 유지하고 실제 충돌/viewport 변화가 있을 때 다시 배치한다.

### 캐시 수명과 비용 경계

구성원·위치·목표/경로·운반 자원·화면 투영은 각각의 실제 변경을 확인한다. LayoutVersion 또는 AvailabilityVersion 하나로 전체 표시를 무효화하지 않는다. 생성/제거·방출·세션 교체와 실제 위치/운반 상태를 별도로 반영한다.

- 해제는 명시적이다. LaboratoryView.ReleaseSession이 Map의 ReleaseDisplay를 호출해 개체별 상태·표시·이벤트 구독·게시 범위를 정리하고 월드 표시를 숨긴다. 새 세션 바인딩 때 표시를 다시 활성화한다. 멸망·방출/제거·씬 파괴에서도 해당 수명의 상태가 다음 개체/세션으로 이어지지 않게 한다.
- 정상 위치 평가와 표시 캐시 갱신은 개체당 O(1), 전체 O(N), 보유 상태 O(N)으로 제한한다. 프레임별 구간 평가는 한 번만 수행해 모든 사용처가 공유한다. 재사용 목록·Dictionary·집계/정렬 버퍼를 사용하며 정상 위치 계산 안에 LINQ·문자열·새 Tween/객체·개체별 전체 검색을 추가하지 않는다.
- 위치 평가/집계의 `Laboratory.Movement.Evaluate`는 준비된 placedArt를 인덱스로 순회한다. Registry의 yield 열거 등 구성원 수집 비용과 생성/제거 비용은 이 구간 밖에서 구별해 측정한다. 그 비용을 전체 화면 측정에서 제외하거나 전체 표시가 무할당인 것으로 주장하지 않는다.
- 안정된 구성원 수와 워밍업 이후 새 정상 위치 평가/캐시 경로의 managed 할당 0 B, 정상 이동·배회의 표시 추가 PathQueries/VisitedCells 0, 세션 해제 후 개체별 캐시/구독/표시 잔존 0을 실제 검증했다. 보조 12/24/48개체·세션 10회와 전체 화면 비용은 별도로 측정했으며 전체 GC/렌더 비용 무회귀를 뜻하지 않는다.

## 대안과 선택 이유

렌더 프레임 사이의 논리 칸 차이만 보간하는 방법은 실제 배회 확정·긴 Advance·복원·재배치를 구별하지 못하므로 사용하지 않는다. 최신 확정 이동 한 건과 현재 유효 경로를 관찰해 필요한 근거를 확보한다.

매 칸 easing·매 프레임 목표 추종·과거 경로 재생 큐는 속도·도착 시점 차이나 누적 지연을 만들 수 있다. 정상 구간은 진행률을 직접 표시하고 불연속 연결만 고정 종료 시각으로 보정한다. 표시용 경로 탐색의 상시 실행 대신 현재 캐시를 재사용하고 복원 첫 표시 조회만 제한적으로 허용한다.

보간 좌표를 게임 상태나 저장 형식에 넣으면 표시 빈도가 점유·작업·저장 결과에 영향을 줄 수 있으므로 분리한다. 기존 SpriteRenderer에 필요한 구체 객체를 연결하며 별도 uGUI 렌더러 지원, NavMesh·물리 이동·Pixel Perfect Camera·전역 풀·Jobs/Burst·새 패키지는 도입하지 않는다.

## 영향과 검증

정식 Sprite·GUID·피벗·PPU·임포트 설정, 이동 시간·논리 칸·Job·예약·자원 처리·저장 스키마를 유지하는 것이 적용 제약이다. 표시 객체와 관찰 필드는 저장 원본이 아니며 같은 의미의 저장 결과와 게임 진행이 표시 평가 유무/빈도에 따라 달라지지 않아야 한다.

실제 적용 파일·컴파일·Edit/Play 결과, 보정의 한 칸 시간 내 합류, 모서리/차단·화면 입력·정지/복원·수명 검증과 전후 성능·동영상은 [PLAN-028](../plans/PLAN-028-creature-movement-interpolation.md)의 실행 결과를 따른다. 변경 전후 동일한 격리 fixture와 고정 delta 조건으로 전체 화면 비용과 새 위치 평가 비용을 구분한다. 이 문서는 구현 선택을 기록하며 테스트·성능·최종 완료 판정은 실행 PLAN의 실제 증거를 따른다. Android/PC Player 빌드와 실기기는 PLAN의 제외 범위를 유지한다.
