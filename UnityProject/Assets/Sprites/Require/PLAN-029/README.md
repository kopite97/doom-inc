에셋별 독립 Aseprite 스프라이트 문서 하나 안에서 16프레임과 영문 동작 태그를 관리한다. Base·Machine·Details·Highlights·Guide는 같은 문서의 레이어다. 세 에셋의 원본은 각각 1개이며 동작마다 원본을 나누지 않는다. 프레임을 4열×4행의 PNG 시트 한 장으로 출력하고 Unity에서 Multiple로 분할한다. 프레임별 개별 PNG는 기본 산출물이 아니다. 아래 프레임 시간·반복·실제 재생 조건은 PNG에 저장되지 않으므로 제출 명세에 반드시 기록한다.

새 문서는 Aseprite RGB 모드·투명 배경으로 시작하고 사용한 색상 프로파일을 제출 명세에 기록하는 안이다. 기존 작업 원본이 있다면 색상 모드/프로파일을 임의 변환하지 말고 실제 설정과 차이를 기록한다. 편집 가능한 원본은 Art에 남기고 PNG만 Unity 요청별 수령 경로로 전달한다. Guide·참고 이미지·스케치 레이어는 출력에서 제외한다. 트리밍·자동 회전·리사이즈·팔레트 자동 축소·프레임 병합으로 원본과 다른 그림을 만들지 않는다.

Art 확정 광원은 **지하 연구실의 수직 상부 천장광**이다. 이미지 위쪽이나 왼쪽에서 비추는 측면광을 뜻하지 않는다. 각 시설을 회전해도 위를 향하는 면과 접촉 음영의 관계를 유지한다. 회전 재사용을 위해 단순한 상면 형태를 사용한다.

## 공통 제작 명세

### 보이는 인상

- 승인된 획득시설처럼 **낮은 금속 받침 위에 실험 장비가 놓인 레트로 비밀 연구소**다. 귀엽고 조금 기괴하되 현실적인 의료 장비 사진이나 공포물의 피·장기 표현으로 바꾸지 않는다.
- 거의 위에서 내려다보는 탑다운 시점이다. 장비의 상면이 주로 보이고 아래쪽 테두리에 얕은 두께만 보인다. 높은 원통을 옆에서 본 모습, 등각 투시의 건물, 높은 벽·지붕으로 내부를 가리는 형태는 피한다.
- 공통 받침·케이스는 청회색 금속, 깊은 틈은 어두운 청회색, 모서리는 밝은 회색으로 만든다. 재질마다 기본/그림자/밝은 면의 큰 색 덩어리를 먼저 잡는다. 기본 1px 어두운 윤곽과 작은 접합부를 사용하고, 촘촘한 디더링·전면 녹/스크래치·검은 외곽선 덩어리로 화면을 지저분하게 만들지 않는다.
- 세 장비는 같은 공장에서 만든 듯한 볼트·테두리 두께를 공유한다. 구분의 주된 단서는 **가공: 비대칭 기계 / 배양: 큰 원형 유리조 / 저장: 낮고 긴 분할 보관함**이다. 색을 빼도 구분돼야 한다.
- 색 강조는 가공시설의 황동/호박색 소형 부품, 배양시설의 청록색 유리/액체, 저장소의 푸른 회색 문과 손잡이로 제안한다. 기존 유기물의 황록색과 보조형의 민트색이 장비 배경에 묻히지 않게 한다. 최종 색은 기존 획득시설과 나란히 두고 사용자가 확인한다.
- 그림 안에 시설명·알파벳·수량·퍼센트·진행 게이지·선택 테두리를 넣지 않는다. 작은 표시등은 고정된 장비 장식이며 실제 가동/오류 상태를 대신하지 않는다. 상태 의미는 기존 UI로 표시한다.

- PLAN-026의 64px/칸 제작 비율을 사용한다. PPU는 공통 지침대로 32다. 픽셀 수를 바꾸려고 게임 점유 칸 수를 바꾸지 않는다.
- 표의 캔버스는 **Aseprite의 프레임 한 장 크기**다. 출력 PNG 전체는 가공/배양 512×512px, 저장소 768×512px다. 프레임 16개를 위→아래, 각 행은 왼쪽→오른쪽으로 배치하며 셀 간격·시트 외곽 패딩은 0이다. 그림 안쪽의 투명 여백은 매 프레임 유지한다.
- 캔버스 좌상단이 `(0,0)`, +x는 오른쪽, +y는 아래다. 기본 방향의 정면은 이미지 아래쪽이며 지도 논리의 -Y다. 게임의 원점은 점유 영역 좌하단이므로 PNG 좌표와 혼동하지 않는다.
- 받침의 불투명 범위는 가공/배양 `x=4..123, y=4..123`, 저장 `x=4..187, y=4..123` 안에 둔다. 실제 기계는 이 안에 들어가며 최소 4px 투명 여백을 유지한다. 바닥 타일·작업자·외부 배관·작업 발판을 PNG에 그려 점유 밖으로 넘기지 않는다.
- 공용 접근 포트는 위 표의 x를 중심으로 폭 약 24px, 하단 `y=112..121`에 둔 손잡이/해치/제어부로 표시한다. 투입·회수·작업은 같은 접근 칸을 쓴다. 장비 위 호퍼나 관찰창을 별도 접근구로 오해시키지 않는다.
- 출력 PNG 전체를 시설 한 장으로 표시하지 않는다. 지도와 미리보기는 해당 동작의 셀을 사용하고, 목록 아이콘은 첫 Idle 셀을 재사용한다. 시트 크기 기준 Max Size는 가공/배양 512 이상, 저장소 1024 이상으로 잡아 자동 축소를 막는다.
- 중심 피벗 `(0.5,0.5)`·Full Rect, PNG RGBA·알파 0/255를 시작안으로 한다. 블러·반투명 외곽·자동 트리밍·리사이즈·출력 회전은 사용하지 않는다. 유리는 청록/밝은 픽셀로 투명한 인상을 표현하되 뒤의 바닥이 비치는 반투명 합성을 요구하지 않는다.
- 이번에는 기본 방향 애니메이션 세트를 기존 획득시설처럼 런타임에서 90도 단위로 회전해 재사용한다. 90/270도에서 저장소 점유와 표시도 2×3으로 바뀐다. 방향별 별도 원화나 자동 좌우 반전은 요구하지 않는다.
- 회전을 전제로 문자·세계 방향에 고정된 긴 투영 그림자·옆면만 보이는 높은 장비를 넣지 않는다. 천장 조명 아래 상면의 짧은 반사와 내부 접촉 음영을 사용한다. 네 방향 회전의 외형 수용 여부는 최종 사용자 검수 항목이다. 방향별 새 원화가 필요하다는 피드백이 생기면 제작 전에 범위를 다시 정리하며 조용히 4배로 늘리지 않는다.
- 원본 레이어는 `Base`(받침), `Machine`(본체), `Details`(관/볼트), `Highlights`(반사), 숨김 `Guide`를 권장한다. Guide의 격자·원점·접근 좌표·주석은 PNG에서 제외한다.
- 제출은 시설별 Aseprite 원본 1개·16프레임 PNG 시트 1개와 명세다. 명세에는 실제 셀/시트 크기·동작별 프레임/시간·피벗·정면/포트 좌표·출력 해시·리비전을 기록한다. 원본은 Art 작업공간에 보존하고 Unity에는 PNG를 전달한다. 공통 임포트 값은 [아트 지침](../../../../../docs/agents/art-assets.md)을 따른다.

Unity 하위 Sprite 이름은 `Processing_Idle_01`처럼 `<AssetId>_<Tag>_<동작 내 2자리 번호>`로 한다. 첫 프레임은 `_01`이다. Aseprite 프레임 n의 시트 셀은 `col=(n-1)%4`, `row=floor((n-1)/4)`이며, Unity 좌하단 원점 Rect는 `x=col*w, y=H-(row+1)*h, width=w, height=h`다. 가공/배양 w=h=128, H=512; 저장소 w=192,h=128,H=512다. 같은 모양의 프레임도 병합하지 않아 순서와 시간이 유지돼야 한다. 기본 방향 한 세트를 네 논리 방향에 회전 재사용하며 방향 프레임을 별도로 만들지 않는다.

### 가공시설: 어디가 어떻게 움직이는가

- **Idle 4장:** 탱크·호퍼·관·받침·해치는 고정한다. 작은 황동 제어부의 표시등만 어두움→약한 밝기→기본 밝기→약한 밝기로 순환한다. 재료를 빨아들이거나 기계가 생산 중인 움직임은 없다.
- **Working 8장:** 탱크 뚜껑 중앙의 작은 축/회전 표시를 프레임마다 45도씩 진행시켜 한 바퀴 돈다. 탱크 전체/뚜껑 윤곽을 돌리지 않는다. 관 옆 펌프 막대는 기본→아래1px→아래2px→아래1px→기본→위1px→기본→기본으로 왕복한다. 호퍼 입구와 서비스 포트는 고정한다. 미세한 장비 구동이며 시설 전체를 좌우로 떨지 않는다.
- **Complete 4장:** 회전축과 펌프를 기본 자세로 놓고 출력 챔버의 작은 확인등이 기본→밝음→밝음→기본으로 반짝인다. 해치 내부 셔터는 닫힘→안쪽1px→안쪽1px→닫힘으로 짧게 반응한다. 배양액 실물 병·재고 수량을 그리거나 방출하지 않는다. 마지막 장의 본체/해치는 Idle 첫 장과 같아야 한다.

### 배양시설: 어디가 어떻게 움직이는가

- **Idle 4장:** 유체와 기포 위치·클램프는 고정하고 제어부의 작은 대기등만 약하게 변화한다. 큰 기포가 계속 솟거나 배양 완료를 암시하는 뚜껑 개방은 없다.
- **Working 8장:** 유리 안의 작은 기포 2~3개가 서로 다른 시작 높이에서 1px씩 안쪽 위로 이동한다. 관찰창 경계에 도달한 기포는 줄어 없어지고 아래쪽의 다른 위치에서 새 기포가 생기게 해 마지막→첫 장의 큰 점프를 피한다. 액체 표면의 작은 밝은 띠는 최대 1px 범위에서만 변화한다. 펌프 램프가 짧게 켜졌다 돌아오며 금속 링·유리 외곽·받침·접근 포트는 움직이지 않는다.
- **Complete 4장:** 관찰창 고정 클램프는 잠김→안쪽1px 해제→해제 유지→잠김으로 반응하고, 유리 가장자리의 확인 반사가 기본→밝음→약함→기본으로 지나간다. 둥근 탱크 뚜껑 전체를 멀리 날리거나 태어나는 생명체를 그림 안에 넣지 않는다. 실제 생명체는 게임이 별도 Thing/Sprite로 표시한다. 마지막 장은 닫힌 공용 장비 자세다.

### 저장소: 어디가 어떻게 움직이는가

- **Idle 4장:** 보관함·세 구획·손잡이·입출고 해치를 고정한다. 중앙 포트 옆 작은 대기등만 아주 약하게 변화한다. 재고가 없거나 허용 자원이 달라도 모순이 없는 대기 동작이다.
- **Receive 6장:** 중앙 해치 셔터가 닫힘→안쪽1px→안쪽2px→안쪽2px→안쪽1px→닫힘으로 움직인다. 포트 안쪽의 청록 표시 2~3픽셀이 바깥쪽에서 안쪽으로 짧게 이어져 입고 반응을 준다. 자원 그림을 가짜로 빨아들이거나 보관함 재고를 바꾸지 않는다.
- **Send 6장:** 같은 해치가 닫힘→바깥쪽1px→바깥쪽2px→바깥쪽2px→바깥쪽1px→닫힘으로 반응하고 작은 표시 순서가 안쪽→바깥쪽으로 바뀐다. 모든 픽셀은 공통 그림 영역 안에 둔다. 실제 운반물은 보조형 머리 위 Sprite가 담당한다.
- 두 일회 동작의 첫/마지막 장은 Idle 첫 장과 같은 닫힌 자세다. 세 구획을 번갈아 열거나 재고를 영구적으로 늘리지 않는다.

### 인게임 재생 조건과 수명 — 연결할 계약

- 가공/배양 **Working**은 실제 생산 진행이 늘어나는 동안만 사용한다. `ProductionWorking`과 `ProductionAutomatic`을 구분해 저속 자동 생산은 기본 Working 속도의 20%로 재생하는 현재 설정 기준안이다. 실제 유효 생산 속도가 달라지면 그 비율을 읽는다. 작업자 수/배정만으로 Working을 시작하지 않는다. 둘 사이 전환에서 반복 위상을 초기화하지 않는다.
- 재료 대기·배양 대상 미선택·완료품 입고 대기·접근 불가·미완성 건설은 기계 가동을 멈추고 Idle을 표시한다. 실제 회차 진행도는 보존한다. 접근 회복 등으로 같은 회차를 재개할 때 Working 위상도 현재 진행도 기준으로 이어간다. Idle의 대기등은 생산 가능/완료를 뜻하지 않는다.
- **Complete**는 실제 산출이 성공한 사건 1건당 1회다. 가공 완료품이 남아 있다는 이유로 반복하지 않는다. 배양 생명체의 실제 생성/배치 시점과 표시를 일치시키며 그림의 재생 완료를 기다리느라 생산/출현을 늦추지 않는다. Complete 뒤에는 그때의 실제 상태에 맞춰 Idle/Working으로 간다.
- 저장소 **Receive/Send**는 건설 완료 후 실제 자원 이전량이 0보다 큰 성공한 입고/출고를 읽는다. 예약·허용 설정 변경·수량 합치기·같은 저장소 내부 정리·새 판 초기 지급·저장 불러오기는 이 반응을 만들지 않는다. 프레임 끝 총량 차이만으로 판단하지 않아 같은 프레임에 입출고가 모두 일어난 경우도 구분한다.
- 짧은 시간에 여러 반응이 발생하면 개체별 현재 동작 1개와 최신 대기 반응 1개까지만 보유한다. 완료 동작은 매 프레임 재시작하지 않으며 오래된 이벤트를 무한 재생하지 않는다. 최신 대기 반응도 한 동작 길이보다 오래됐으면 폐기한다. 초기 바인딩/복원 때 지난 사건을 재생하지 않는다.
- 연구소 시간 정지·배치 편집·홈 복귀에서는 현재 동작/위상/반응 타이머를 함께 멈춘다. 줌/팬/회전은 투영만 바꾸고 위상을 유지한다. 세션 교체·새 판·방출과 무관한 시설 제거·씬 파괴 시 표시 캐시/관찰 구독을 정리한다. 표시 상태는 저장 필드에 넣지 않는다.
- 실제 산출 후 `ProductionCompleted`, 성공한 자원 이전 후 `ResourceTransferred` 관찰을 연결했다. 가공/배양 완료와 저장소 입출고는 이 성공 사건으로만 시작한다. 위 표의 태그가 이미 구현된 게임 API라는 뜻은 아니다. 렌더 프레임의 추측이나 애니메이션에서 생산/자원 명령을 호출하는 구현은 하지 않는다.
- 모든 프레임은 같은 캔버스·중심 피벗·받침·논리 점유·포트 기준을 공유한다. Base 레이어와 외부 음영은 고정하며 의도한 작은 부품 외에는 픽셀 덩어리의 부피·위치가 흔들리지 않게 한다. Working/Idle 마지막→첫 장과 Complete/Receive/Send의 시작·종료를 실제 Aseprite 재생으로 확인하고, Unity 연결은 전체 리소스 적용 후 별도로 검증한다.
